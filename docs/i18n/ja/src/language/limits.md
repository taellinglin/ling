# 既知の制限

Ling は若い言語で、変化も速いです。このページには、いちばん戸惑いやすい動作を集めました。何時間も
悩まずに、数分で気づけるようにするためです。ここに書いたことはすべて、現在の `ling`（2030.1.53）の
両方のエンジン、デフォルトの JIT（`ling run`）とインタプリタ（`ling run --interp`）で確かめて
あります。

> **ヒント：** プログラムの様子がおかしいときは、一度 `ling run --interp` で実行してください。
> インタプリタは、JIT が黙って `()` に変えてしまう未知の関数や実行時エラーを報告します。

## JIT とインタプリタの比較

| 状況 | JIT（デフォルト） | インタプリタ |
|---|---|---|
| 未知の関数名 | 黙って `()` を返す | `unknown function` エラー |
| 実行時エラー（ファイルがない、添字が不正など） | `()` か空の値を返して続行 | エラーとトレースバックを出して停止 |
| `1 / 0` | `()` | `inf` |
| 名前だけの `pi` | `()`（`pi()` と書く） | その値 |
| 条件の中の `""` や `[]` | 真 | 偽 |
| リストの末尾より先の添字 | 空の値 | `index N out of bounds` エラー |
| テキストの 1 文字 `s[i]` | 空の値 | その文字（両方で使えるのは `substr(s, i, 1)`） |
| `繰 c の中 "テキスト"` | 空の値 | 1 文字ずつ |
| テキストの大小比較 `"a" < "b"` | `false` | エラー |
| `実行 { }` の中の `束縛` | 後でも見える | 捨てられる |
| 変数に入れたクロージャ `f(3)` | `()` | `unknown function 'f'` エラー |
| 関数やクロージャを組み込み関数に渡す（`試す`、`list_map` など） | `()` になる | 動く |
| `待つ 式` | `()` | その値 |
| 範囲の値 `0..5` を表示 | `[0, 5]` | `[0, 1, 2, 3, 4]` |
| フィールド数の合わないコンストラクタ | `()` | エラー |
| 足りない引数を使う | `()` | `undefined` エラー |
| エントリポイントの中に直接書いた `戻る` | 黙ってプログラムを終える | `unexpected top-level return` エラー |

こうした隅を避けたプログラムは、どちらのエンジンでも同じように動きます。

## 代入はない

`x = x + 1` は構文エラーです。代わりに再束縛します：`束縛 x = x + 1`。
[束縛と再束縛](syntax.md#束縛と再束縛)を参照してください。

## ループとスコープ

| 構文 | 中の `束縛` は外側の変数を更新するか |
|---|---|
| `間` の本体 | する |
| `もし` の本体 | する |
| `繰` の本体 | **しない**：毎回スコープの新しいコピーになります |
| `実行 { }` ブロック | JIT ではする、インタプリタではしない。どちらにも頼らないこと |

合計を累積したりリストを組み立てたりするには、カウンタ付きの `間` ループを使ってください。

`break` や `continue` はありません。`停止` と `継続` は何もしない予約語です。JIT ではループは
そのまま続き、インタプリタでは `undefined` エラーになります。ループを関数に入れて `戻る` を使うか、
フラグ付きの `間` を使ってください。

## 範囲の境界は単純に

`0..n` と `0..(n + 1)` は動きます。`0..n + 1` は構文エラーで、`0..長さ(xs)` は黙って誤動作します
（JIT では空のループ、インタプリタではエラー）。ただの名前か数値以外は、かっこで囲んでください：
`0..(長さ(xs))`。

## && と || は常に両辺を評価する

どちらのエンジンも短絡評価をしません。`x != 0 && 10 / x > 1` では、`x` が `0` でも割り算が
実行されます。右辺を実行してはいけないときは、`もし` を入れ子にしてください。

## 数値とテキスト

- 数値リテラルは 10 進数で、小数部は 1 つまでです。`1e3`、`0xff`、`1_000`、`.5`、`3.` は
  ありません。さらに困ったことに、`1e3` や `0xff` は構文エラーになりません。`1` や `0` の後に
  未知の名前が続いたものとして読まれます。
- テキストは二重引用符のみで、埋め込み（補間）はありません。テキストは `+` と `str()` で
  組み立ててください。
- `print` と `println`（日本語ではどちらも `印刷`）はどちらも改行し、引数を**区切りなしで**
  つなげます。`印刷("合計", 1 + 2)` は `合計3` と表示します。
- `!x` は `x == 偽` の意味なので、`!0` も `!""` も `false` です。`!` は真偽値にだけ使ってください。

## 構造を持つ値の比較

リスト、レコード、列挙値、結果どうしの `==` は、中身が同じでも常に `false` です。要素や
フィールドを自分で比較してください。[型と値](types.md#値の比較)を参照してください。

## 型システムにできること、できないこと

Ling は動的型付けです。`x: number` や `-> T` のような型注釈は解析されて無視されます。マップ
（辞書）、集合、タプル、JSON パーサはありません。レコードや並列のリストを使うか、`db_*`
組み込み関数で SQLite にデータを保存してください。

## 何もしないキーワード

次の言葉は予約されていますが、何の効果もありません。

`停止`（`stop`）、`継続`（`again`）、`変える`（`change`）、`投稿`（`post`）、`渡す`（`give`）、
`適合`（`fit`）、`できる`（`can`）、`確か`（`sure`）、`多分`（`maybe`）、`純粋`（`pure`）、
`起動`（`spawn`）、`なし`（`none`）

所有権を表す `所有`、`貸す`、`共有`、`移動`、`複製` は解析されて無視され、借用や移動の検査は
行われません。`非同期 関数` は同期的に動きます。`型`（`type`）の宣言は捨てられ、後ろに続くものを
飲み込みます。[キーワード](keywords.md)を参照してください。

## クロージャと関数値

その場で呼び出すクロージャ式 `(|x| x + 1)(5)` はどこでも動きます。それ以外は次のとおりです。

- 変数に入れたクロージャは、インタプリタでは名前で呼べず、JIT でも当てになりません。
- JIT は関数やクロージャを組み込み関数に渡せません。`list_map`、`list_filter` などは `()` を返し、
  `試す()` は常に `悪い("try: first argument must be a function")` を返します。インタプリタでは
  動きます。
- `http_serve` を呼ぶプログラムは自動的にインタプリタで動くので、リクエストハンドラの中では
  クロージャも `試す` も使えます。

名前付きのトップレベルの `関数` と普通のループを使ってください。

## モジュール

- `使う "ファイル"` は 1 つの共有された名前空間に読み込みます。2 つのファイルが同じ名前の関数を
  定義していると、最後に読み込んだほうが黙って使われます。先に読み込んだファイルの中から呼び出した
  場合も同じです。これはエントリポイントにも当てはまるので、ライブラリでは決して `start` のような
  エントリ名を束縛しないでください。
- `モジュール` の中では、同じモジュールの関数を修飾した名前（`図形::面積`）で呼び出してください。
  名前だけでは失敗します。
- `モジュール` の中で束縛した値は使えません。定数は関数として公開してください。

ライブラリの関数にはライブラリ名の接頭辞を付けましょう。たとえば `geom_area` です。
[モジュールとプロジェクト](modules.md)を参照してください。

## ツール

- `lingfu new` は `src/start.ling` を作りますが、`lingfu build` はマニフェストに指定がなければ
  `main.ling` を探します。`Ling.toml` の `[spirit]` セクションに `entry = "src/start.ling"` を
  加えてください。
- `lingfu check`、`lingfu fmt`、`lingfu translate` は存在しない `ling` のサブコマンドを呼びます。
  `ling` の使い方を表示するだけで何もしませんが、`check` と `fmt` は成功を報告します。プログラムの
  確認には `ling run --interp` を、翻訳には `lingfu normalize <言語>` を使ってください（今いる
  フォルダのすべての `.ling` ファイルを書き換えるので、コピーに対して使ってください）。
- `lingfu normalize` はいくつかのキーワードを間違えます。中国語、韓国語、タイ語では `form` を
  字句解析器が受け付けない言葉に書き換え（[キーワード](keywords.md#綴り)の綴りを使ってください）、
  `choose` は英語のまま残し、日本語とタイ語では `ok`/`bad` を `一致` のパターンとして使えない
  組み込み関数名で書きます。所有権の言葉の一部（`copy`、`lend`、`share`）も日本語とタイ語では
  間違って出力されます。結果を実行して、こうした言葉は手で直してください。
- `lingfu build` は生成した Rust のコードを Cargo でコンパイルするので、Rust のツールチェーンが
  必要です。

## テスト

`lingfu test` は JIT でテストを実行します。JIT は実行時エラーで止まらないので、失敗したテストでも
`All tests passed!` と表示することがあります。テストには `PASS` か `FAIL` をはっきり表示させて
それを確かめるか、`ling run --interp` で実行してください。`tests/` の中に置いた補助ファイルは
テストとして扱われ、`no entry point` で失敗するので、補助ファイルは別の場所に置いてください。

## 構文上の落とし穴

- `-` や `[` で始まる行は、前の行の続きになります。
- `構造 P { x: number, y: number }` は構文エラーです。注釈付きのフィールドの並びはカンマで
  終えてください：`構造 P { x: number, y: number, }`。
- 引数なしのクロージャには空白が必要で、`| | 式` と書きます。`||` は「または」だからです。
- `関数 main() { ... }` はエントリポイントではありません。`束縛 main = 実行 { ... }` を使います。
- `assert`、`panic`、`exit`、`append_file`、`delta_time` は組み込み関数ではありません。
  フレームの時間を測るには、続けて取った `time_now()` の値を引き算してください。
