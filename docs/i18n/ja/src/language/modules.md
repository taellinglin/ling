# モジュールとプロジェクト

プログラムが 1 つのファイルに収まらなくなったら、関数をライブラリファイルに移し、`使う`（`use`）で
読み込みます。このページでは、`使う`、`モジュール`（`mod`）ブロック、名前が衝突したときに起きること、
そして `lingfu` でプロジェクトを構成する方法を説明します。

Ling のモジュールの仕組みは小さなものです。`使う` はファイルを 1 つの共有された名前空間に読み込み、
非公開にできるものはありません。以下で紹介するいくつかの命名の習慣を守れば、快適に使えます。

| 形 | 働き |
|---|---|
| `使う "lib/ファイル.ling"` | ファイルを読み込みます。その関数、型、トップレベルの束縛が名前だけで使えるようになります |
| `使う "lib/ファイル.ling" として m` | ファイルを読み込みます。その関数は `m::名前()` で呼び出します |
| `モジュール 名前 { 関数 f() { ... } }` | 1 つのファイルの中で関数をまとめます。`名前::f()` で呼び出します |

## 使う：別のファイルを読み込む

`使う "パス"` は別の `.ling` ファイルを読み込みます。パスはテキストで、`ling` を実行したフォルダでは
なく、**その `使う` を含むファイルからの相対パス**として解決されます。`.ling` という拡張子は省略
できます。

読み込んだファイルの中身はすべて使えるようになります。関数、`構造` と `選択` の型、トップレベルの
`束縛` の値です。読み込まれたファイル自身も他のファイルを `使う` ことができ、そのパスはそのファイル
自身の場所からの相対パスになります。

**`lib/textkit.ling`**

```ling-module
// textkit：小さなテキスト補助関数
関数 tk_左詰め(テキスト, 幅) {
  束縛 余白 = 幅 - 長さ(テキスト)
  もし 余白 > 0 { str_repeat(" ", 余白) + テキスト } 他 { テキスト }
}
関数 tk_罫線(幅) { str_repeat("-", 幅) }
```

**`lib/report.ling`** は、自分と同じフォルダから `textkit.ling` を読み込みます。

```ling-module
使う "textkit.ling"
構造 品目 { 名前, 数量, }
関数 rp_行(項目) { 項目.名前 + tk_左詰め(str(項目.数量), 6) }
```

**`main.ling`**

```ling-module
使う "lib/report.ling"
束縛 開始 = 実行 {
  印刷(rp_行(品目("茶", 3)))
  印刷(rp_行(品目("ジャム", 12)))
  印刷(tk_罫線(9))
}
```

```sh
$ ling run main.ling
茶     3
ジャム    12
---------
```

`main.ling` は `textkit.ling` を直接読み込んでいませんが、`tk_罫線` は見えています。読み込まれた
ファイルはすべて 1 つの名前空間を共有しているからです。

### 使う ... として

`として`（`as`）を付けると、読み込んだファイルの関数は別名を通して呼び出します。その場合、名前だけ
では**使えなくなります**。

```ling-module
使う "lib/textkit.ling" として tk
束縛 開始 = 実行 {
  印刷(tk::tk_罫線(5))
}
```

```sh
$ ling run alias.ling
-----
```

## 名前の衝突

読み込まれた名前はすべて 1 つの名前空間を共有し、2 つの定義が衝突してもエラーも警告も出ません。

- 読み込んだ 2 つのファイルが同じ名前の関数を定義していると、**最後に**読み込んだほうが使われます。
  先に読み込んだファイルの中から呼び出した場合も同じです。
- メインファイルの定義は、読み込んだどの定義よりも優先されます。

`lib/first.ling` に `関数 だれ() { "1つ目" }` が、`lib/second.ling` に `関数 だれ() { "2つ目" }`
が入っているとします。

```ling-module
使う "lib/first.ling"
使う "lib/second.ling"
束縛 開始 = 実行 {
  印刷(だれ())
}
```

```sh
$ ling run clash.ling
2つ目
```

メインファイルに `関数 だれ() { "メインファイル" }` を加えると、代わりに `メインファイル` と
表示されます。

同じ規則はエントリポイントにも当てはまります。ライブラリが `start` を束縛していて、それがメイン
ファイルの `start` より後に読み込まれると、ライブラリの `start` が実行されます。そこで、

- **ライブラリごとに短い接頭辞を決め**（`tk_`、`rp_`）、すべての関数に付けます。
- **ライブラリにはエントリポイントの束縛を決して置きません。** それを持つのはメインプログラムだけです。
- **データは引数で渡します。** ライブラリの関数はトップレベルの束縛は見えますが、呼び出し元の
  ローカルな束縛は決して見えません。

## モジュール：ファイル内の名前空間

`モジュール 名前 { ... }` は、関数を 1 つの名前の下にまとめ、`::` で呼び出せるようにします。いくつかの
グループが同じ関数名を必要とするときに便利です。

```ling
モジュール ベクトル {
  関数 足す(a, b) { [a[0] + b[0], a[1] + b[1]] }
  関数 内積(a, b) { a[0] * b[0] + a[1] * b[1] }
  関数 長さ2乗(a) { ベクトル::内積(a, a) }
}
モジュール 金額 {
  関数 足す(a, b) { 四捨五入((a + b) * 100) / 100 }
}
束縛 開始 = 実行 {
  印刷(ベクトル::足す([1, 2], [3, 4]))
  印刷(ベクトル::長さ2乗([3, 4]))
  印刷(金額::足す(0.1, 0.2))
}
```
```output
[4, 6]
25
0.3
```

`モジュール` の規則：

- **同じモジュールの関数は、修飾した名前で呼び出します**（`ベクトル::内積`）。`長さ2乗` がその例です。
  `内積(a, a)` とだけ書くと、インタプリタでは失敗し、JIT では `()` になります。
- `モジュール` の中の関数は、ファイルのトップレベルの関数を接頭辞なしで呼び出せます。
- **`モジュール` の中で値を束縛しないでください。** `ベクトル::原点` は JIT では `()`、インタプリタ
  ではテキストの `ベクトル::原点` になり、モジュール自身の関数からも見えません。定数は関数として
  公開します：`関数 原点() { [0, 0] }` とし、`ベクトル::原点()` で呼び出します。

## lingfu によるプロジェクト

`lingfu new <名前>` でプロジェクトのフォルダを作ります。

```sh
$ lingfu new shop
~ Ling Manifest — Spirit Token Descends ~
Creating project: shop

✓ Spirit Realm created!
  cd shop
  lingfu build
  lingfu run
```

```text
shop/
  Ling.toml          マニフェスト
  README.md
  ling.ignore
  lexicons/en.ling   言語データ（触らないでください）
  src/start.ling     エントリポイント
  tests/test.ling    最初のテスト
```

ライブラリは `src/` の下、たとえば `src/lib/textkit.ling` に置き、`src/start.ling` から
`使う "lib/textkit.ling"` で読み込みます。

| コマンド | 働き |
|---|---|
| `lingfu run` | `src/start.ling` を実行します |
| `lingfu test` | `tests/` の中のすべての `.ling` ファイルを実行します |
| `lingfu build` | 配布用のプログラムを作ります（下の `entry` の行が必要です） |

### プロジェクトのエントリポイント

- **プログラム**は `src/start.ling` で、エントリポイントの束縛を持ちます。
- `tests/` の中の**テスト**もプログラムです。任意の名前を `実行` ブロックに束縛し（最初のテストは
  `bind test = do { ... }` を使っています）、テストするコードを自分からの相対パスで読み込みます。
  たとえば `使う "../src/lib/textkit.ling"` です。`tests/` の中のファイルにはすべてエントリ
  ポイントが必要で、エントリポイントのない補助ファイルは `no entry point` で失敗します。
- **ライブラリ**にはエントリポイントの束縛がまったくありません。

### マニフェスト

`Ling.toml` は自動で作られます。`lingfu run` と `lingfu test` はそのままで動きますが、マニフェストが
エントリファイルを指定していないと、`lingfu build` は `main.ling` を探します。`[spirit]` の
セクションに `entry` の行を加えてください。

```toml
[spirit]
name = "shop"
kind = "bin"
version = "2030.0.0"
entry = "src/start.ling"
```

すべてのコマンドは [lingfu](../tools/lingfu.md) を、現在のツールの癖は
[既知の制限](limits.md#ツール)を参照してください。
