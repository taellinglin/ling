# エラーと結果

Ling には例外がありません。失敗しうる関数は**結果**を返します。うまくいけば `良い(値)`、だめなら
`悪い(理由)` です。呼び出し側は `一致` で結果を開きます。このページでは、結果、`試す` 組み込み関数、
実行時エラーとトレースバック、そしてほとんどの組み込み関数が従う「ソフトな失敗」の約束事を
説明します。

| 道具 | 使いどころ |
|---|---|
| `良い(値)` / `悪い(理由)` | 自分の関数から成功や失敗を返す |
| `一致 r { 良い(v) => ..., 悪い(e) => ... }` | 両方の場合を処理する |
| `試す(f, 引数...)` | 実行時エラーを `悪い` の結果に変える（インタプリタのみ） |
| `ling run --interp` | 実行時エラーをトレースバック付きで見る |

## 結果（良い と 悪い）

`良い(値)` は成功の値を包み、`悪い(理由)` は失敗を包みます。理由はふつうテキストですが、どんな値でも
かまいません。結果は `Ok(...)` または `Err(...)` と表示されます。（結果を作るときは `err` も
`悪い` の別名として使えますが、パターンには `悪い` を使う必要があります。）

```ling
関数 安全な割り算(a, b) {
  もし b == 0 { 悪い("0 で割りました") } 他 { 良い(a / b) }
}
束縛 開始 = 実行 {
  印刷(安全な割り算(6, 3))
  印刷(安全な割り算(1, 0))
}
```
```output
Ok(2)
Err(0 で割りました)
```

## 一致で結果を処理する

`良い(v)` と `悪い(e)` はパターンでもあります。かっこの中の名前は、その腕の中で包まれた値に
束縛されます。

```ling
関数 安全な割り算(a, b) {
  もし b == 0 { 悪い("0 で割りました") } 他 { 良い(a / b) }
}
関数 表示(r) {
  一致 r {
    良い(v) => "値 " + str(v),
    悪い(理由) => "失敗：" + 理由
  }
}
束縛 開始 = 実行 {
  印刷(表示(安全な割り算(8, 2)))
  印刷(表示(安全な割り算(8, 0)))
}
```
```output
値 4
失敗：0 で割りました
```

結果の中を見る方法は `一致` しかないので、小さな補助関数を作っておくと便利です。

```ling
関数 値または(r, 既定値) {
  一致 r {
    良い(v) => v,
    _ => 既定値
  }
}
関数 安全な平方根(x) {
  もし x < 0 { 悪い("負の数") } 他 { 良い(平方根(x)) }
}
束縛 開始 = 実行 {
  印刷(値または(安全な平方根(16), 0))
  印刷(値または(安全な平方根(-16), 0))
}
```
```output
4
0
```

> 結果に対してメソッドを呼ぶと、包まれた値が返ります（`良い(5).anything` は `5`）。たいていは
> 望んだ動作ではありません。`一致` を使ってください。

## 入力の検証

規則を 1 つずつ確かめ、失敗ごとに別々の理由を返します。

```ling
関数 年齢を解析(テキスト) {
  束縛 t = trim(テキスト)
  もし 長さ(t) == 0 {
    悪い("入力が空です")
  } 他 もし to_number(t) == 0 && t != "0" {
    悪い("数値ではありません：" + t)
  } 他 もし to_number(t) > 130 {
    悪い("大きすぎます：" + t)
  } 他 {
    良い(to_number(t))
  }
}
関数 表示(r) {
  一致 r {
    良い(v) => "年齢 " + str(v),
    悪い(理由) => "却下（" + 理由 + "）"
  }
}
束縛 開始 = 実行 {
  繰 s の中 ["42", " 7 ", "", "四十", "200"] {
    印刷(表示(年齢を解析(s)))
  }
}
```
```output
年齢 42
年齢 7
却下（入力が空です）
却下（数値ではありません：四十）
却下（大きすぎます：200）
```

ある手順が別の手順に依存するときは、`一致` を入れ子にし、それぞれの `悪い` に文脈を付け加えます。
そうすると、最後のメッセージでどこがおかしかったのかがわかります。

```ling
関数 数値を解析(テキスト) {
  束縛 n = to_number(テキスト)
  もし n == 0 && テキスト != "0" { 悪い("数値ではありません：" + テキスト) } 他 { 良い(n) }
}
関数 面積(幅テキスト, 高さテキスト) {
  一致 数値を解析(幅テキスト) {
    悪い(e) => 悪い("幅：" + e),
    良い(w) => 一致 数値を解析(高さテキスト) {
      悪い(e) => 悪い("高さ：" + e),
      良い(h) => 良い(w * h)
    }
  }
}
束縛 開始 = 実行 {
  印刷(面積("4", "2.5"))
  印刷(面積("4", "x"))
}
```
```output
Ok(10)
Err(高さ：数値ではありません：x)
```

## 実行時エラーとトレースバック

問題によっては、**実行時エラー**でプログラムが止まります。未知の関数の呼び出し、存在しない
ファイルの読み込み、リストの末尾より先の添字、フィールド数の合わないコンストラクタなどです。
インタプリタは、エラー、ファイル名、そして最も深い呼び出しを最後に並べたトレースバックを表示します。

```ling-module
関数 読込(パス) { read_file(パス) }
関数 進める() { 読込("no_such_file.txt") }
束縛 開始 = 実行 {
  印刷(進める())
}
```

```sh
$ ling run --interp broken.ling
[detected language: Japanese (日本語)]
error[runtime]: read_file 'no_such_file.txt': The system cannot find the file specified. (os error 2)
 --> broken.ling
  traceback (deepest call last):
    0: start
    1: 進める
    2: 読込
```

プログラムは 0 以外の終了コードで止まります。（コロンの後の OS のメッセージはシステムによって
異なります。）

> **JIT は止まりません。** デフォルトのエンジンでは、こうした問題のほとんどが黙って `()` になり、
> プログラムは続行します。上のプログラムは `ling run` では `()` と表示します。プログラムの様子が
> おかしいときは、一度 `ling run --interp` で実行して本当のエラーを確かめてください。

Ling には `assert`、`panic`、`exit` の組み込み関数はありません。失敗を知らせるには、`悪い` の結果を
返し、わかりやすいメッセージを表示してください。

## 試す：実行時エラーを捕まえる

`試す(f, 引数...)`（`try`）は、与えた引数で `f` を呼び出します。呼び出しが成功すれば
`良い(結果)` を、実行時エラーが起きれば `悪い(メッセージ)` を返します。渡すのは関数そのもの
（かっこを付けない名前）で、その後に引数を続けます。クロージャも使えます：`試す(| | 6 * 7)`。

**`試す` はインタプリタでしか動きません。** JIT は関数を組み込み関数に渡せないので、JIT では
`試す` は常に `悪い("try: first argument must be a function")` を返します。

```ling
関数 足す1(x) { x + 1 }
関数 壊れた(x) { 存在しない関数(x) }
束縛 開始 = 実行 {
  印刷(試す(足す1, 4))
  印刷(試す(壊れた, 4))
}
```
```output
Err(try: first argument must be a function)
Err(try: first argument must be a function)
```

同じプログラムをインタプリタで実行すると、こうなります。

```sh
$ ling run --interp try_demo.ling
[detected language: Japanese (日本語)]
Ok(5)
Err(unknown function '存在しない関数')
```

`http_serve` を呼ぶプログラムは常にインタプリタで動くので、Web のリクエストハンドラの中では
`試す` が使えます。それ以外の場所では、`試す` は開発の補助と考え、自分の関数が `良い` と `悪い` を
返すように書いてください。

## 組み込み関数のソフトな失敗

ほとんどの組み込み関数は結果を返しません。失敗すると、害のない中立的な値を返して処理を続けます。

| 組み込み関数 | 失敗したとき |
|---|---|
| `to_number("x")` | `0` |
| `要素取得(xs, 99)` | `""`（空のテキスト） |
| `str_find("abc", "z")` | `-1` |
| `file_exists(パス)` | `false` |
| `read_file("missing.txt")` | JIT では `()`、インタプリタでは実行時エラー |

```ling
束縛 開始 = 実行 {
  印刷(to_number("バナナ"))
  印刷("[" + 要素取得([1, 2, 3], 99) + "]")
  印刷(str_find("こんにちは", "z"))
  印刷(file_exists("no-such-file.txt"))
}
```
```output
0
[]
-1
false
```

失敗が本物の値のように見えることがあります。`to_number("0")` も `to_number("ゼロ")` も `0` です。
だから先に確かめましょう。`read_file` の前に `file_exists` を呼び、添字は `長さ(xs)` と比べ、
`to_number` を信じる前にテキストを検証します。小さな包み関数で、ソフトな失敗を本物の結果に
変えられます。

```ling
関数 テキストを読む(パス) {
  もし file_exists(パス) { 良い(read_file(パス)) } 他 { 悪い("ファイルがありません：" + パス) }
}
束縛 開始 = 実行 {
  印刷(テキストを読む("missing.cfg"))
}
```
```output
Err(ファイルがありません：missing.cfg)
```
