# ネットワーク

Ling には HTTP のほかに 4 つのネットワーク系統があります。作りたいものに合わせて選んでください。

| 目的 | 使うもの | セキュリティ |
|---|---|---|
| ゲームのロビーや LAN ツール | `net_*` | 平文、認証なし。信頼できる LAN 専用です。 |
| サーバーでコマンドを実行する、または SSH クライアントを受け付ける | `ssh_*` | SSH-2、ホスト鍵を固定、パスワードログイン。 |
| 非公開のリクエスト/レスポンス型サービス | `lingtp_*` | ポスト量子ハンドシェイク、ホスト鍵を固定。 |
| 身元を持つノードのピアツーピアネットワーク | `p2p_*` | ポスト量子、認証済み、パディングされたフレーム。 |

HTTP と HTTPS については [Web サーバーと HTTP](../reference/web.md) を参照してください。`net_*` は
すべてのインストールに含まれます。`ssh_*`、`lingtp_*`、`p2p_*` には `privacy` プロファイルが必要です
（既定の `full` インストールに含まれます）。

これらの組み込み関数はすべて、ブロックするかポーリングするかのどちらかで、コールバックを取るものは
ありません。仕事があるか確認し、確認の合間に `sleep(ms)` を呼ぶループを書きます。バインドや接続の
失敗はエラーではなくステータスの数値に現れるので、必ずステータスを確認してください。

## LAN ロビー: `net_*`

`net_*` はゲームの状態をやり取りするための、小さく信頼できるトランスポートです。プロセスは、
最大 64 クライアントを受け付ける **ホスト** か、1 つのホストに接続する **クライアント** の
どちらかになります。各メッセージは UTF-8 テキストの 1 行です。ソケットはバックグラウンド
スレッドで動くので、ゲームループがブロックすることはありません。`net_send` は 1 行をキューに入れ、
`net_recv` は 1 行を取り出します。

| 組み込み関数 | 中文 | 日本語 | 한국어 | ไทย | 用途 |
|---|---|---|---|---|---|
| `net_host(port)` | — | — | — | `เน็ตโฮสต์` | TCP ポート（既定 7777）で待ち受けてホストになる |
| `net_join(ip, port)` | — | — | — | `เน็ตจอย` | ホストに接続してクライアントになる |
| `net_send(text)` | — | — | — | `เน็ตส่ง` | 1 行送る。ホストなら全クライアントへ、クライアントならホストへ |
| `net_send_to(id, text)` | — | — | — | — | ホスト専用: 1 つのクライアントに 1 行送る |
| `net_recv()` | — | — | — | `เน็ตรับ` | キュー内で最も古いメッセージ、または `""` |
| `net_recv_from()` | — | — | — | — | 同じく、`"id\|text"` の形で返す |
| `net_clients()` | — | — | — | — | ホスト: `"1,2"` のようなクライアント ID |
| `net_client_count()` | — | — | — | — | 接続中のピア数 |
| `net_events()` | — | — | — | — | `connect:<id>` / `disconnect:<id>` の行を取り出す |
| `net_status()` | — | — | — | `เน็ตสถานะ` | `0` 待機中または失敗、`1` 待ち、`2` 接続済み |
| `net_close()` | — | — | `연결종료` | — | ホストまたはクライアントを閉じる |
| `net_announce(port, info)` | — | — | — | `เน็ตประกาศ` | ホスト: LAN にロビーの説明をブロードキャストする |
| `net_announce_stop()` | — | — | — | `เน็ตหยุดประกาศ` | ブロードキャストを止める |
| `net_discover(port)` | — | — | — | `เน็ตค้นหา` | クライアント: 直近 5 秒間に聞こえたホスト |
| `net_test(port)` | — | — | — | `เน็ตทดสอบ` | ポートをバインドできるかと LAN アドレスを報告する |
| `net_local_ip()` | — | — | — | — | このマシンの LAN アドレス。オフラインなら `""` |
| `net_upnp_map(port, description)` | — | — | — | — | TCP ポートの転送をルーターに依頼する（バックグラウンド） |
| `net_upnp_poll()` | — | — | — | — | `net_upnp_map` の結果 |
| `net_upnp_unmap()` | — | — | — | — | 転送を解除する |

### ホストと参加

`net_host(port)` と `net_join(ip, port)` は何も返さないので、`net_status()` を見てください。
ホストでは、`1` はクライアント待ち、`2` は 1 つ以上が接続済みという意味です。クライアントでは、
`1` は接続中、`2` は接続済みです。ポートをバインドできない場合や接続に失敗した場合、ステータスは
`0` に戻ります。役割はプロセスごとに 1 つで、`net_host` や `net_join` をもう一度呼ぶと以前の
役割が置き換わります。

```ling-gui
# host.ling
束縛 開始 = 実行 {
    net_host(17777)
    束縛 回数 = 0
    間 回数 < 100 {
        束縛 受信 = net_recv()
        もし 受信 != "" {
            印刷("ホストが受信: " + 受信)
            net_send("エコー:" + 受信)
            束縛 回数 = 1000
        }
        スリープ(50)
        束縛 回数 = 回数 + 1
    }
    スリープ(300)
    net_close()
}
```

```ling-gui
# client.ling
束縛 開始 = 実行 {
    net_join("127.0.0.1", 17777)
    束縛 回数 = 0
    間 net_status() != 2 && 回数 < 100 {
        スリープ(50)
        束縛 回数 = 回数 + 1
    }
    net_send("こんにちは")
    束縛 返事 = ""
    間 返事 == "" && 回数 < 200 {
        束縛 返事 = net_recv()
        スリープ(50)
        束縛 回数 = 回数 + 1
    }
    印刷("クライアントが受信: " + 返事)
    net_close()
}
```

ホストを 1 つのターミナルで、クライアントを別のターミナルで実行してください。クライアントは
`クライアントが受信: エコー:こんにちは` と表示します。

### メッセージとイベント

- メッセージに改行を含めてはいけません。埋め込まれた改行は 2 つのメッセージとして届きます。
- 受信キューはそれぞれ 4096 行を保持し、いっぱいになると古いものから捨てられます。
- `net_recv()` と `net_recv_from()` は同じキューを読むので、プログラムごとにどちらか一方の
  スタイルを使ってください。`net_recv_from()` は `"2|hello"` を返します。メッセージ自体に `|` が
  含まれることがあるので、**最初の** `|` で分割してください。
- `net_events()` は直近 256 件のイベントを改行でつないで保持します。

### LAN 上のホストを探す

`net_announce(port, info)` は `info` を UDP（既定のポートは 7778）でおよそ 1 秒ごとに
ブロードキャストします。もう一度呼ぶとテキストが更新されます。`net_discover(port)` は、直近 5 秒間に
聞こえたホストを `"ip|info"` の行で返します。最初の呼び出しでリスナーが起動するので、アナウンスが
届くまでは `""` を返します。

```ling-gui
束縛 開始 = 実行 {
    束縛 ホスト一覧 = ""
    束縛 回数 = 0
    間 ホスト一覧 == "" && 回数 < 40 {
        束縛 ホスト一覧 = net_discover(7778)
        スリープ(250)
        束縛 回数 = 回数 + 1
    }
    印刷(ホスト一覧)
}
```

### ルーターのポート転送

`net_upnp_map(port, description)` は、TCP ポートをこのマシンに転送するようルーター（UPnP IGD）に
依頼します。`net_upnp_poll()` は処理中は `""` を返し、その後 `"ok|<public ip>"`、`"cgnat|<ip>"`
（ルーター自体がキャリアグレード NAT の内側にあり、転送が届かない）、または `"fail|<reason>"` を
返します。`net_upnp_unmap()` は転送を解除します。

### セキュリティ

ホストはすべてのインターフェースで待ち受け、通信は平文で、ポートに届く人は誰でも参加できます。
`net_*` は信頼できる LAN 内かトンネルの中で使ってください。インターネット越しには `lingtp_*`、
`ssh_*`、HTTPS を使ってください。`net_test` と `net_local_ip` は、公開アドレスに向けて UDP
ソケットを開くことで LAN アドレスを調べます。何も送信はしません。

## SSH: `ssh_*`

SSH の組み込み関数は、本物の SSH-2 クライアントと小さな SSH サーバーです。クライアントはどの
OpenSSH サーバーとも動きます。サーバーを使うと、Ling プログラムが OpenSSH クライアントからの
シェル行や `exec` リクエストを受け取れます。どれにもローカライズされた別名はありません。

| 組み込み関数 | 用途 |
|---|---|
| `ssh_connect(host, port, user, password)` | 接続してログイン: `1` 成功、`0` 認証情報の誤り、`-1` 接続エラー、`-2` ホスト鍵の変更 |
| `ssh_exec(command)` | コマンドを 1 つ実行し、標準出力を返す |
| `ssh_exit_code()` | 最後の `ssh_exec` の終了ステータス（なければ `-1`） |
| `ssh_client_status()` | `0` 切断、`2` 接続済み |
| `ssh_close()` | クライアントを切断する |
| `ssh_config(port, user, password, host_key_path)` | サーバー設定を準備する |
| `ssh_serve()` | バックグラウンドでサーバーを起動する。待ち受けていれば `true` |
| `ssh_serve_recv()` | いずれかのクライアントからの最も古い入力を `"id\|text"` で、または `""` |
| `ssh_serve_send(id, text)` | クライアントに 1 行送る |
| `ssh_serve_exit(id, code)` | 終了ステータスを付けて `exec` リクエストを終え、チャネルを閉じる |
| `ssh_serve_clients()` | 接続中のクライアント ID（カンマ区切り） |
| `ssh_serve_client_count()` | 接続中のクライアント数 |
| `ssh_serve_events()` | `connect:`、`disconnect:`、`authfail:` の行を取り出す |
| `ssh_serve_status()` | `0` 待機中、`1` 待ち受け中、`2` クライアント接続中 |
| `ssh_stop()` | 待ち受けをやめ、全クライアントを切断する |

### クライアント

```ling-gui
束縛 開始 = 実行 {
    束縛 結果 = ssh_connect("192.168.1.20", 22, "deploy", env_get("DEPLOY_PASSWORD", ""))
    もし 結果 == 1 {
        印刷(ssh_exec("uname -a"))
        印刷(ssh_exit_code())
        ssh_close()
    } 他 {
        印刷("SSH に失敗しました: " + 結果)
    }
}
```

クライアントは、すべてのホスト鍵を OpenSSH 形式の `known_hosts` ファイルと照合します。あるホストへの
最初の接続ではその鍵を信頼し（OpenSSH と同じです）、鍵が変わっていれば拒否します（`-2`）。
認証はパスワードのみです。パスワードをソースコードに書かず、`env_get` で読み込んでください。

### サーバー

`ssh_config` は、ポート（既定は 22）、受け付ける唯一のユーザー名、空であってはならないパスワード、
Ed25519 のホスト鍵ファイル（`""` なら `.ling-ssh/host_ed25519`。初回起動時に作られます）を取ります。
サーバーはパスワードログインのみを提供し、パスワードを定数時間で比較します。コマンドを代わりに
実行することはありません。クライアントが入力したものをキューに入れ、何を返すかはあなたのコードが
決めます。これはシェルではなく、プロトコルの端点です。

```ling-gui
束縛 開始 = 実行 {
    ssh_config(2222, "admin", env_get("SSH_PASSWORD", ""), "")
    もし ssh_serve() {
        間 真 {
            束縛 受信 = ssh_serve_recv()
            もし 受信 != "" {
                束縛 部分 = split(受信, "|")
                ssh_serve_send(to_number(部分[0]), "入力内容: " + 部分[1])
                ssh_serve_exit(to_number(部分[0]), 0)
            }
            スリープ(50)
        }
    }
}
```

> 既知の制限: Ling のクライアントを Ling のサーバーに対してループバックで試したところ、`ssh_exec` は
> サーバーの返答ではなく、終了コード `-1` とともに `""` を返しました。相手には OpenSSH を使うのが
> よく、依存する前に自分の組み合わせを試してください。

## ポスト量子トランスポート: `lingtp://`

`lingtp://` は、ポスト量子暗号を使い、認証局を持たない形で HTTPS の役割を果たす、小さな
リクエスト/レスポンス型プロトコルです。各接続はハンドシェイクで始まります。サーバーは **ML-DSA-87**
署名で身元を証明し、双方は **X25519 + ML-KEM-768** ハイブリッド KEM で鍵を合意します。その後の
各フレームは XChaCha20-Poly1305 で封印され、さらに DICE-42 カスケードで包まれます。鍵は接続ごとに
新しく、前方秘匿性が得られます。

信頼の仕組みは SSH と同じです。クライアントがあるホストに初めて出会うと、そのホストの公開鍵を
`.lingtp/known_hosts`（現在のフォルダからの相対パス）に保存します。後でそのホストが別の鍵を
示すと、接続は拒否されます。ネットワークが敵対的かもしれない場合は、初回に鍵を別の経路で
確認してください。

リクエストは 1 つの文字列（クエリ文字列を含むパス）で、レスポンスも 1 つの文字列（本文）です。
POST は `path + "\n" + body` を送るので、ハンドラは改行があるかどうかで両者を見分けます。

| 組み込み関数 | 用途 |
|---|---|
| `lingtp_get(host, port, path)` | パスを取得する（ポートの既定は 7780）。本文を返し、失敗時は `""` |
| `lingtp_post(host, port, path, body)` | 本文を送り、レスポンスの本文を返す |
| `lingtp_get_status()` | 最後のリクエストの結果: `1` 成功、`0` 接続エラー、`-1` サーバー署名が不正、`-2` ホスト鍵の変更 |
| `lingtp_config(port, host_key_path)` | サーバー設定を準備する |
| `lingtp_route(prefix, handler)` | `prefix` で始まるパスに応答する（最長一致が優先） |
| `lingtp_serve()` | `lingtp_stop` まで提供する。呼び出したスレッドをブロックする |
| `lingtp_stop()` | サーバーを止める |
| `lingtp_status()` | `0` 停止、`1` 待ち受け中、`2` クライアント接続中 |
| `lingtp_client_count()` | 接続中のクライアント数 |
| `lingtp_events()` | `connect:<id>` / `disconnect:<id>` の行を取り出す |

どれにもローカライズされた別名はありません。

### 提供する

ルートは `lingtp_serve()` の直前に登録してください。起動時にルート表が消去されるからです。
何も設定されていない場合や、鍵やソケットを作れなかった場合は `false` を返します。ハンドラは
パスを受け取り、本文を返します。

```ling-gui
関数 挨拶(パス) {
    戻る "pq-hello from " + パス
}

束縛 開始 = 実行 {
    lingtp_config(17780, "hostkey.hex")
    lingtp_route("/", 挨拶)
    印刷("提供中")
    lingtp_serve()
}
```

### 取得する

```ling-gui
束縛 開始 = 実行 {
    束縛 本文 = lingtp_get("127.0.0.1", 17780, "/hi?x=1")
    もし lingtp_get_status() == 1 {
        印刷(本文)
    } 他 {
        印刷("lingtp に失敗しました: " + lingtp_get_status())
    }
}
```

上のサーバーに対して実行すると `pq-hello from /hi?x=1` と表示されます。

### セキュリティ上の注意

- ホスト鍵は 16 進のシードとして平文ファイルに保存されます（既定は `.lingtp/host_mldsa87`、または
  `lingtp_config` に渡したパス）。SSH の秘密鍵と同じように守り、バックアップしてください。失うと
  サーバーの身元が変わり、すべてのクライアントが接続を拒否します。
- ハンドラのエラーは `handler error: ...` としてクライアントに返され、内部情報が漏れることがあります。
  入力を検証し、ハンドラ内でエラーを起こさないようにしてください。
- サーバーはすべてのインターフェースで待ち受け、リクエストに 1 つずつ応答します。
- `lingtp_post` は最初の改行を本文の始まりとみなすので、パス内の改行はパーセントエンコードしてください。
- Rust の `ling-net` クレートには、ワイヤ形式の異なる独自の `lingtp` モジュールがあります。Ling の
  `lingtp_get` は `ling-net` のサーバーとは通信できません。両端で同じ実装を使ってください。

## ピアツーピア: `p2p_*`

`p2p_*` は Ling Wallet プロジェクトのトランスポートである LWP-1 を動かします。ピアはハイブリッド
X25519 + ML-KEM-1024 ハンドシェイクの中で ML-DSA-87 の身元を使って互いを認証し、フレームは固定
サイズにパディングされて封印されます。ノードはピアのデータベースを持ち、署名付きシードリストや
SOCKS5 プロキシ（`127.0.0.1:9050` の Tor など）を使え、トランザクションを Dandelion++ で中継します。
ペイロードは、プログラムが意味を決める `kind` 番号の付いた 16 進文字列です。

| 組み込み関数 | 用途 |
|---|---|
| `p2p_start(config, events)` | ノードを起動する。`Ok(handle)` または `Err(message)`。`events` には `""` を渡す |
| `p2p_poll(net, max, timeout_ms)` | 最大 `max` 件（既定 64）のイベントを取り出す。最長 `timeout_ms` 待つ |
| `p2p_send(net, peer, kind, payload_hex)` | 1 つのピアに送る。キューに入れば `true` |
| `p2p_broadcast(net, kind, payload_hex, except_peer)` | 1 つを除く全ピアに送る（除外しないなら `-1`） |
| `p2p_relay(net, id_hex, payload_hex, kind, from_peer)` | 検証済みトランザクションの Dandelion++ 中継 |
| `p2p_mark_fluffed(net, id_hex)` | トランザクションがすでに拡散済みであることを記録する |
| `p2p_peers(net)` | ピアごとの `[id, addr, inbound, fingerprint, is_seed, connected_secs]` |
| `p2p_misbehaving(net, peer, score, reason)` | ピアの BAN スコアを加算する |
| `p2p_local_addr(net)` | 待ち受けアドレス `"ip:port"`、または `""` |
| `p2p_fingerprint(identity_seed_hex)` | シードに対してピアに見えるフィンガープリント（`9ebc-56af-97f2-61af` など） |
| `p2p_netgroup(net, peer)` | ピアのネットワークグループ（`v4:1.2` など） |
| `p2p_seeds_sign(network, issued_at, entries, authority_seed_hex)` | シード機関としてシードリストに署名する |
| `p2p_seeds_verify(list_hex, authority_pk_hex)` | `Ok([network, issued_at, entries])` または `Err(...)` |
| `p2p_shutdown(net)` | ノードを止める。初回は `true` |

どれにもローカライズされた別名はありません。`str_to_hex(text)` と `hex_to_str(hex)` は、
ペイロードをテキストと 16 進数の間で変換します。

### 設定

`config` は `[key, value]` のペアのリストです。未知のキー、重複、型の誤りは `Err(message)` で
拒否されます。

| キー | 意味 |
|---|---|
| `magic_hex` | **必須。** 16 進 8 文字。マジックが異なるピア同士は接続しません。 |
| `network` | **必須。** ネットワーク ID、0〜255。 |
| `data_dir` | **必須。** ピアのデータベースと身元を置くフォルダ。なければ作られます。 |
| `listen` | ピアを受け付ける `"ip:port"`、または送信専用なら `""`。ポート `0` は空いているポートを選びます。 |
| `peers` | 常に接続を試みる `"host:port"` のリスト。 |
| `identity_seed_hex` | 長期的な身元のための 16 進 64 文字。省略するとランダムな身元になります。 |
| `ephemeral_outbound` | 送信接続ごとに新しい身元を使う（既定は `true`）。 |
| `max_outbound`、`max_inbound` | 接続数の上限（既定は 8 と 32）。 |
| `proxy` | すべての送信通信に使う SOCKS5 プロキシ `"ip:port"`。 |
| `seeds_hex`、`authority_pk_hex` | 署名付きシードリストと、それを検証すべき鍵。 |
| `fast_timers` | テスト用の短いタイマー。 |

### イベント

`p2p_poll` はイベントのリストを返し、各イベントもリストです。

| 最初の要素 | 構成 |
|---|---|
| `"connected"` | `["connected", peer_id, addr, inbound, fingerprint, is_seed]` |
| `"disconnected"` | `["disconnected", peer_id]` |
| `"message"` | `["message", peer_id, kind, payload_hex]` |
| `"stem"` | `["stem", peer_id, payload_hex]`: 検証すべき Dandelion++ トランザクション |

ポーリングを続けてください。イベントは上限のあるキューで待ち、キューがいっぱいになるとすべての
ピアが遅くなります。メッセージの kind は 16〜255（それより小さい値は予約済み）で、ペイロードは
最大で約 4 MiB です。

### 例

1 台のマシン上の 2 つのノードです。A が待ち受け、B が A に接続して `こんにちは` を送ります。

```ling-gui

束縛 開始 = 実行 {

    束縛 乙 = 取出(p2p_start([["magic_hex", "4c494e47"], ["network", 1], ["listen", ""], ["data_dir", "node_b"], ["peers", [p2p_local_addr(甲)]]], ""))
    束縛 ピア = []
    束縛 回数 = 0

        束縛 ピア = p2p_peers(乙)
        スリープ(100)
```

### セキュリティ上の注意

- 制限付きのアイソレートでは、すべての `p2p_*` 組み込み関数に `"p2p"` ケイパビリティが必要です。
  メインスレッドはすべてのケイパビリティを持っています。
- ネットワークハンドルは推測できない 128 ビットの 16 進文字列で、それを起動したアイソレートの中でのみ
  有効です。未知のハンドルはエラーになります。`p2p_shutdown` の後の呼び出しは `false` か `[]` を返します。
- `data_dir` にはノードの身元が入っています。秘密鍵と同じように守ってください。
