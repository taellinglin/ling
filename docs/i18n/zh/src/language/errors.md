# 错误与结果

Ling 没有异常。可能失败的函数返回一个**结果**：成功时是 `好(值)`，失败时是 `坏(原因)`。调用者
用 `配` 打开结果。本页介绍结果、`试` 内置函数、运行时错误和回溯，以及大多数内置函数遵循的
"软失败"约定。

| 工具 | 用途 |
|---|---|
| `好(值)` / `坏(原因)` | 让你自己的函数返回成功或失败 |
| `配 r { 好(v) => ..., 坏(e) => ... }` | 处理两种情况 |
| `试(f, 参数...)` | 把运行时错误转成 `坏` 结果（仅限解释器） |
| `ling run --interp` | 查看带回溯的运行时错误 |

## 结果：好与坏

`好(值)` 包装成功的值，`坏(原因)` 包装失败。原因通常是文本，但可以是任何值。结果打印为
`Ok(...)` 或 `Err(...)`。（构造结果时，`err` 是 `坏` 的另一个名字，但模式必须用 `坏`。）

```ling
函 安全除(a, b) {
  若 b == 0 { 坏("除以零") } 否 { 好(a / b) }
}
令 始 = 执 {
  打印(安全除(6, 3))
  打印(安全除(1, 0))
}
```
```output
Ok(2)
Err(除以零)
```

## 用配处理结果

`好(v)` 和 `坏(e)` 也是模式。括号里的名字会在该分支中绑定到被包装的值：

```ling
函 安全除(a, b) {
  若 b == 0 { 坏("除以零") } 否 { 好(a / b) }
}
函 显示(r) {
  配 r {
    好(v) => "值 " + str(v),
    坏(原因) => "失败：" + 原因
  }
}
令 始 = 执 {
  打印(显示(安全除(8, 2)))
  打印(显示(安全除(8, 0)))
}
```
```output
值 4
失败：除以零
```

`配` 是查看结果内部的唯一方法，所以写几个小辅助函数很划算：

```ling
函 取值或(r, 默认) {
  配 r {
    好(v) => v,
    _ => 默认
  }
}
函 安全开方(x) {
  若 x < 0 { 坏("负数") } 否 { 好(平方根(x)) }
}
令 始 = 执 {
  打印(取值或(安全开方(16), 0))
  打印(取值或(安全开方(-16), 0))
}
```
```output
4
0
```

> 对结果调用方法会返回被包装的值（`好(5).anything` 是 `5`）。这通常不是你想要的。请用 `配`。

## 验证输入

逐条检查规则，并为每种失败给出各自的原因：

```ling
函 解析年龄(文本) {
  令 t = trim(文本)
  若 长度(t) == 0 {
    坏("输入为空")
  } 否 若 to_number(t) == 0 && t != "0" {
    坏("不是数字：" + t)
  } 否 若 to_number(t) > 130 {
    坏("太大：" + t)
  } 否 {
    好(to_number(t))
  }
}
函 显示(r) {
  配 r {
    好(v) => "年龄 " + str(v),
    坏(原因) => "拒绝（" + 原因 + "）"
  }
}
令 始 = 执 {
  历 s 于 ["42", " 7 ", "", "四十", "200"] {
    打印(显示(解析年龄(s)))
  }
}
```
```output
年龄 42
年龄 7
拒绝（输入为空）
拒绝（不是数字：四十）
拒绝（太大：200）
```

当一步依赖另一步时，就嵌套 `配`，并给每个 `坏` 加上上下文，这样最终的消息能说明是哪里出了错：

```ling
函 解析数字(文本) {
  令 n = to_number(文本)
  若 n == 0 && 文本 != "0" { 坏("不是数字：" + 文本) } 否 { 好(n) }
}
函 面积(宽文本, 高文本) {
  配 解析数字(宽文本) {
    坏(e) => 坏("宽度：" + e),
    好(w) => 配 解析数字(高文本) {
      坏(e) => 坏("高度：" + e),
      好(h) => 好(w * h)
    }
  }
}
令 始 = 执 {
  打印(面积("4", "2.5"))
  打印(面积("4", "x"))
}
```
```output
Ok(10)
Err(高度：不是数字：x)
```

## 运行时错误与回溯

有些问题会以**运行时错误**让程序停止：调用未知函数、读取不存在的文件、索引超出列表末尾、
构造函数的字段数量不对，等等。解释器会打印错误、文件名，以及最深的调用排在最后的回溯：

```ling-module
函 加载(路径) { read_file(路径) }
函 开始() { 加载("no_such_file.txt") }
令 始 = 执 {
  打印(开始())
}
```

```sh
$ ling run --interp broken.ling
[detected language: Chinese (中文)]
error[runtime]: read_file 'no_such_file.txt': The system cannot find the file specified. (os error 2)
 --> broken.ling
  traceback (deepest call last):
    0: start
    1: 开始
    2: 加载
```

程序以非零退出码停止。（冒号后面的操作系统消息因系统而异。）

> **JIT 不会停止。** 在默认引擎上，这类问题大多会悄悄得到 `()`，程序继续运行：上面的程序在
> `ling run` 下打印 `()`。程序行为异常时，请用 `ling run --interp` 运行一次，看看真正的错误。

Ling 没有 `assert`、`panic` 或 `exit` 内置函数。要表示失败，请返回 `坏` 结果并打印清楚的消息。

## 试：捕获运行时错误

`试(f, 参数...)`（`try`）用给定的参数调用 `f`。调用成功时返回 `好(结果)`，引发运行时错误时
返回 `坏(消息)`。传入的是函数本身（只写名字，不加括号），后面跟上它的参数。闭包也可以：
`试(| | 6 * 7)`。

**`试` 只在解释器上可用。** JIT 不能把函数传给内置函数，所以在 JIT 上 `试` 总是返回
`坏("try: first argument must be a function")`：

```ling
函 加一(x) { x + 1 }
函 坏掉(x) { 不存在的函数(x) }
令 始 = 执 {
  打印(试(加一, 4))
  打印(试(坏掉, 4))
}
```
```output
Err(try: first argument must be a function)
Err(try: first argument must be a function)
```

同一个程序在解释器上：

```sh
$ ling run --interp try_demo.ling
[detected language: Chinese (中文)]
Ok(5)
Err(unknown function '不存在的函数')
```

调用 `http_serve` 的程序总是在解释器上运行，所以 `试` 在网页请求处理函数里可以用。在其他地方，
请把 `试` 当作开发辅助工具，并让你自己的函数返回 `好` 和 `坏`。

## 内置函数的软失败

大多数内置函数不返回结果。失败时，它们返回一个无害的中性值，然后继续运行：

| 内置函数 | 失败时 |
|---|---|
| `to_number("x")` | `0` |
| `取元素(xs, 99)` | `""`（空文本） |
| `str_find("abc", "z")` | `-1` |
| `file_exists(路径)` | `false` |
| `read_file("missing.txt")` | JIT 上是 `()`，解释器上是运行时错误 |

```ling
令 始 = 执 {
  打印(to_number("香蕉"))
  打印("[" + 取元素([1, 2, 3], 99) + "]")
  打印(str_find("你好", "z"))
  打印(file_exists("no-such-file.txt"))
}
```
```output
0
[]
-1
false
```

失败值可能看起来像真实的值：`to_number("0")` 和 `to_number("零")` 都是 `0`。所以要先问：
在 `read_file` 之前调用 `file_exists`，把索引和 `长度(xs)` 比较，在相信 `to_number` 之前先
验证文本。一个小包装函数就能把软失败变成真正的结果：

```ling
函 读取文本(路径) {
  若 file_exists(路径) { 好(read_file(路径)) } 否 { 坏("没有这个文件：" + 路径) }
}
令 始 = 执 {
  打印(读取文本("missing.cfg"))
}
```
```output
Err(没有这个文件：missing.cfg)
```
