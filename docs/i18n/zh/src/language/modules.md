# 模块与项目

当程序在一个文件里放不下时，就把函数移到库文件中，再用 `载`（`use`）加载它们。本页介绍 `载`、
`核`（`mod`）代码块、名字冲突时会发生什么，以及如何用 `lingfu` 组织项目。

Ling 的模块系统很小：`载` 把文件加载到同一个共享的命名空间里，没有任何东西是私有的。下面介绍的
几个命名习惯能让它用起来很顺手。

| 形式 | 作用 |
|---|---|
| `载 "lib/文件.ling"` | 加载文件；其中的函数、类型和顶层绑定都可以直接用名字访问 |
| `载 "lib/文件.ling" 为 m` | 加载文件；用 `m::名字()` 调用其中的函数 |
| `核 名字 { 函 f() { ... } }` | 在一个文件内给函数分组；用 `名字::f()` 调用 |

## 载：加载另一个文件

`载 "路径"` 加载另一个 `.ling` 文件。路径是文本，并且**相对于包含这条 `载` 的文件**来解析，
而不是相对于你运行 `ling` 时所在的文件夹。`.ling` 扩展名可以省略。

被加载文件中的一切都会变得可用：函数、`形` 和 `选` 类型，以及顶层的 `令` 值。被加载的文件
自己也可以 `载` 其他文件，路径相对于它自己的位置。

**`lib/textkit.ling`**

```ling-module
// textkit：小型文本辅助函数
函 tk_左填充(文本, 宽度) {
  令 空位 = 宽度 - 长度(文本)
  若 空位 > 0 { str_repeat(" ", 空位) + 文本 } 否 { 文本 }
}
函 tk_横线(宽度) { str_repeat("-", 宽度) }
```

**`lib/report.ling`** 从自己所在的文件夹加载 `textkit.ling`：

```ling-module
载 "textkit.ling"
形 条目 { 名称, 数量, }
函 rp_行(项) { 项.名称 + tk_左填充(str(项.数量), 6) }
```

**`main.ling`**

```ling-module
载 "lib/report.ling"
令 始 = 执 {
  打印(rp_行(条目("茶", 3)))
  打印(rp_行(条目("果酱", 12)))
  打印(tk_横线(9))
}
```

```sh
$ ling run main.ling
茶     3
果酱    12
---------
```

`main.ling` 从未直接加载 `textkit.ling`，但 `tk_横线` 依然可见：所有被加载的文件共享同一个
命名空间。

### 载 ... 为

使用 `为`（`as`）时，被加载文件的函数要通过别名调用，这时它们就**不能**再直接用名字访问：

```ling-module
载 "lib/textkit.ling" 为 tk
令 始 = 执 {
  打印(tk::tk_横线(5))
}
```

```sh
$ ling run alias.ling
-----
```

## 名字冲突

所有被加载的名字共享一个命名空间，两个定义冲突时既没有错误也没有警告：

- 如果两个被加载的文件定义了同名函数，**最后**加载的那个生效，即使调用者在先加载的文件里也是如此。
- 主文件中的定义优先于它加载的任何内容。

假设 `lib/first.ling` 包含 `函 谁() { "第一个" }`，`lib/second.ling` 包含
`函 谁() { "第二个" }`：

```ling-module
载 "lib/first.ling"
载 "lib/second.ling"
令 始 = 执 {
  打印(谁())
}
```

```sh
$ ling run clash.ling
第二个
```

在主文件中加上 `函 谁() { "主文件" }`，它就会改为打印 `主文件`。

同样的规则也适用于入口点：如果某个库绑定了 `start`，并且在主文件的 `start` 之后加载，那么运行
的是库里的 `start`。因此：

- **给每个库一个简短的前缀**（`tk_`、`rp_`），并用在每个函数上。
- **永远不要在库里放入口绑定。** 只有主程序才有入口点。
- **通过参数传入数据。** 库函数能看到顶层绑定，但永远看不到调用者的局部绑定。

## 核：文件内的命名空间

`核 名字 { ... }` 把函数归到一个名字下，用 `::` 访问。当几组函数本来需要同样的函数名时，它很有用：

```ling
核 向量 {
  函 加(a, b) { [a[0] + b[0], a[1] + b[1]] }
  函 点积(a, b) { a[0] * b[0] + a[1] * b[1] }
  函 长度平方(a) { 向量::点积(a, a) }
}
核 金额 {
  函 加(a, b) { 四舍五入((a + b) * 100) / 100 }
}
令 始 = 执 {
  打印(向量::加([1, 2], [3, 4]))
  打印(向量::长度平方([3, 4]))
  打印(金额::加(0.1, 0.2))
}
```
```output
[4, 6]
25
0.3
```

`核` 的规则：

- **调用同一个 `核` 里的其他函数时，请写完整名字**（`向量::点积`），就像 `长度平方` 那样。
  只写 `点积(a, a)` 在解释器上会失败，在 JIT 上得到 `()`。
- `核` 里的函数可以不加前缀地调用文件的顶层函数。
- **不要在 `核` 里绑定值。** `向量::原点` 在 JIT 上得到 `()`，在解释器上得到文本
  `向量::原点`，就连模块自己的函数也看不到它。请把常量写成函数：
  `函 原点() { [0, 0] }`，用 `向量::原点()` 调用。

## 使用 lingfu 管理项目

`lingfu new <名字>` 创建一个项目文件夹：

```sh
$ lingfu new shop
~ Ling Manifest — Spirit Token Descends ~
Creating project: shop

✓ Spirit Realm created!
  cd shop
  lingfu build
  lingfu run
```

```text
shop/
  Ling.toml          清单文件
  README.md
  ling.ignore
  lexicons/en.ling   语言数据（不要改动）
  src/start.ling     入口点
  tests/test.ling    示例测试
```

把库放在 `src/` 下，例如 `src/lib/textkit.ling`，然后在 `src/start.ling` 中用
`载 "lib/textkit.ling"` 加载。

| 命令 | 作用 |
|---|---|
| `lingfu run` | 运行 `src/start.ling` |
| `lingfu test` | 运行 `tests/` 中的每个 `.ling` 文件 |
| `lingfu build` | 构建可分发的程序（需要下面的 `entry` 行） |

### 项目中的入口点

- **程序**是 `src/start.ling`，其中有 `令 始 = 执 { ... }` 这样的入口绑定。
- `tests/` 中的**测试**也是程序。它把任意名字绑定到一个 `执` 代码块（示例测试用的是
  `bind test = do { ... }`），并用相对于自身的路径加载要测试的代码，例如
  `载 "../src/lib/textkit.ling"`。`tests/` 中的每个文件都必须有入口点：没有入口点的辅助文件会
  以 `no entry point` 失败。
- **库**完全没有入口绑定。

### 清单文件

`Ling.toml` 会自动创建。`lingfu run` 和 `lingfu test` 无需修改即可使用，但除非清单写明入口
文件，`lingfu build` 会去找 `main.ling`。请在 `[spirit]` 部分加上一行 `entry`：

```toml
[spirit]
name = "shop"
kind = "bin"
version = "2030.0.0"
entry = "src/start.ling"
```

所有命令见 [lingfu](../tools/lingfu.md)，当前工具的怪癖见[已知限制](limits.md#工具)。
