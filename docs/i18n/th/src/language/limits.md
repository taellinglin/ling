# ข้อจำกัดที่ทราบ

Ling ยังเป็นภาษาใหม่และเปลี่ยนแปลงเร็ว หน้านี้รวบรวมพฤติกรรมที่ทำให้คนแปลกใจบ่อยที่สุด เพื่อให้คุณจับได้
ภายในไม่กี่นาทีแทนที่จะเสียเวลาหลายชั่วโมง ทุกข้อในหน้านี้ตรวจสอบแล้วกับ `ling` เวอร์ชันปัจจุบัน (2030.1.53)
บนทั้งสองเอนจิน คือ JIT ซึ่งเป็นค่าเริ่มต้น (`ling run`) และอินเทอร์พรีเตอร์ (`ling run --interp`)

> **เคล็ดลับ:** เมื่อโปรแกรมทำงานแปลกๆ ให้รันด้วย `ling run --interp` สักครั้ง อินเทอร์พรีเตอร์จะแจ้ง
> ฟังก์ชันที่ไม่รู้จักและข้อผิดพลาดขณะทำงาน ซึ่ง JIT เปลี่ยนเป็น `()` อย่างเงียบๆ

## เปรียบเทียบ JIT กับอินเทอร์พรีเตอร์

| สถานการณ์ | JIT (ค่าเริ่มต้น) | อินเทอร์พรีเตอร์ |
|---|---|---|
| ชื่อฟังก์ชันที่ไม่รู้จัก | คืน `()` เงียบๆ | ข้อผิดพลาด `unknown function` |
| ข้อผิดพลาดขณะทำงาน (ไม่มีไฟล์ ดัชนีผิด ฯลฯ) | คืน `()` หรือค่าว่าง แล้วทำงานต่อ | หยุดพร้อมข้อผิดพลาดและเทรซแบ็ก |
| `1 / 0` | `()` | `inf` |
| ชื่อ `pi` เปล่าๆ | `()` (ให้เขียน `pi()`) | ค่าของมัน |
| `""` หรือ `[]` ในเงื่อนไข | จริง | เท็จ |
| ดัชนีเลยท้ายรายการ | ค่าว่าง | ข้อผิดพลาด `index N out of bounds` |
| อักขระตัวเดียวของข้อความ `s[i]` | ค่าว่าง | อักขระนั้น (ใช้ `substr(s, i, 1)` ได้ทั้งสองเอนจิน) |
| `สำหรับ c ใน "ข้อความ"` | ค่าว่าง | ทีละอักขระ |
| เรียงลำดับข้อความ `"a" < "b"` | `false` | ข้อผิดพลาด |
| `ผูก` ภายใน `ทำ { }` | ยังมองเห็นภายหลัง | ถูกทิ้ง |
| โคลเชอร์ที่เก็บในตัวแปร `f(3)` | `()` | ข้อผิดพลาด `unknown function 'f'` |
| ส่งฟังก์ชันหรือโคลเชอร์ให้ฟังก์ชันในตัว (`ลอง` `list_map` ฯลฯ) | กลายเป็น `()` | ใช้ได้ |
| `รอ นิพจน์` | `()` | ค่าของมัน |
| พิมพ์ค่าช่วง `0..5` | `[0, 5]` | `[0, 1, 2, 3, 4]` |
| คอนสตรักเตอร์ที่จำนวนฟิลด์ผิด | `()` | ข้อผิดพลาด |
| ใช้อาร์กิวเมนต์ที่ไม่ได้ส่งมา | `()` | ข้อผิดพลาด `undefined` |
| `คืน` ที่เขียนตรงๆ ในจุดเริ่มต้น | จบโปรแกรมเงียบๆ | ข้อผิดพลาด `unexpected top-level return` |

โปรแกรมที่เลี่ยงมุมเหล่านี้จะทำงานเหมือนกันบนทั้งสองเอนจิน

## ไม่มีการกำหนดค่า

`x = x + 1` เป็นข้อผิดพลาดทางไวยากรณ์ ให้ผูกใหม่แทน: `ผูก x = x + 1` ดูหัวข้อการผูกและการผูกใหม่ใน
[ไวยากรณ์](syntax.md)

## ลูปและขอบเขต

| โครงสร้าง | `ผูก` ภายในเปลี่ยนตัวแปรด้านนอกหรือไม่ |
|---|---|
| ตัวของ `ขณะที่` | ใช่ |
| ตัวของ `ถ้า` | ใช่ |
| ตัวของ `สำหรับ` | **ไม่**: แต่ละรอบได้สำเนาขอบเขตใหม่ |
| บล็อก `ทำ { }` | ใช่บน JIT ไม่บนอินเทอร์พรีเตอร์ อย่าพึ่งพาแบบใดแบบหนึ่ง |

ถ้าจะสะสมผลรวมหรือสร้างรายการ ให้ใช้ลูป `ขณะที่` กับตัวนับ

ไม่มี `break` หรือ `continue` ส่วน `หยุด` และ `ทำอีก` เป็นคำสงวนที่ไม่ทำอะไร บน JIT ลูปจะทำงานต่อไปเฉยๆ
และบนอินเทอร์พรีเตอร์จะเป็นข้อผิดพลาด `undefined` ให้ใส่ลูปไว้ในฟังก์ชันแล้ว `คืน` หรือใช้ `ขณะที่`
กับตัวแปรธง

## ขอบเขตของช่วงต้องเรียบง่าย

`0..n` และ `0..(n + 1)` ใช้ได้ `0..n + 1` เป็นข้อผิดพลาดทางไวยากรณ์ และ `0..ความยาว(xs)` ทำงานผิดเงียบๆ
(ลูปว่างบน JIT และข้อผิดพลาดบนอินเทอร์พรีเตอร์) อะไรที่ไม่ใช่ชื่อหรือตัวเลขเดี่ยวๆ ให้ครอบด้วยวงเล็บ:
`0..(ความยาว(xs))`

## && และ || ประเมินทั้งสองข้างเสมอ

ทั้งสองเอนจินไม่ลัดวงจร ใน `x != 0 && 10 / x > 1` การหารยังทำงานแม้ `x` เป็น `0` ถ้าข้างขวาต้องไม่ทำงาน
ให้ใช้ `ถ้า` ซ้อนกัน

## ตัวเลขและข้อความ

- ลิเทอรัลตัวเลขเป็นตัวเลขฐานสิบ มีทศนิยมได้ไม่เกินหนึ่งส่วน ไม่มี `1e3` `0xff` `1_000` `.5` หรือ `3.`
  ที่แย่กว่านั้นคือ `1e3` และ `0xff` ไม่ใช่ข้อผิดพลาดทางไวยากรณ์ แต่ถูกอ่านเป็น `1` หรือ `0` ตามด้วยชื่อ
  ที่ไม่รู้จัก
- ข้อความใช้อัญประกาศคู่เท่านั้นและไม่มีการแทรกค่า ให้สร้างข้อความด้วย `+` และ `str()`
- `print` และ `println` (ภาษาไทยคือ `พิมพ์` ทั้งคู่) ขึ้นบรรทัดใหม่ทั้งคู่ และต่ออาร์กิวเมนต์**โดยไม่มีตัวคั่น**
  `พิมพ์("ผลรวม", 1 + 2)` พิมพ์ `ผลรวม3`
- `!x` หมายถึง `x == เท็จ` ดังนั้น `!0` และ `!""` ได้ `false` ใช้ `!` กับค่าบูลีนเท่านั้น

## การเปรียบเทียบค่าที่มีโครงสร้าง

`==` ระหว่างรายการ เรคคอร์ด ค่าอีนัม และผลลัพธ์ได้ `false` เสมอ แม้เนื้อหาจะเหมือนกัน ให้เปรียบเทียบสมาชิก
หรือฟิลด์เอง ดู[ชนิดข้อมูลและค่า](types.md)

## สิ่งที่ระบบชนิดข้อมูลทำและไม่ทำ

Ling เป็นภาษาชนิดข้อมูลแบบไดนามิก การระบุชนิดอย่าง `x: number` และ `-> T` ถูกแยกวิเคราะห์แล้วไม่สนใจ
ไม่มีแมป (ดิกชันนารี) เซต ทูเพิล และตัวแยกวิเคราะห์ JSON ให้ใช้เรคคอร์ดหรือรายการคู่ขนาน หรือเก็บข้อมูลลง
SQLite ด้วยฟังก์ชันในตัว `db_*`

## คำสงวนที่ไม่ทำอะไร

คำเหล่านี้ถูกสงวนไว้แต่ไม่มีผลใดๆ

`หยุด` (`stop`) `ทำอีก` (`again`) `เปลี่ยนแปลง` (`change`) `ส่ง` (`post`) `ให้` (`give`) `เหมาะสม` (`fit`)
`สามารถ` (`can`) `แน่นอน` (`sure`) `อาจจะ` (`maybe`) `บริสุทธิ์` (`pure`) `สร้าง` (`spawn`) `ไม่มี` (`none`)

คำเกี่ยวกับความเป็นเจ้าของ `เป็นเจ้าของ` `ให้ยืม` `แบ่งปัน` `ย้าย` และ `คัดลอก` ถูกแยกวิเคราะห์แล้วละเลย
ไม่มีการตรวจการยืมหรือการย้าย `ไม่พร้อมกัน ฟังก์ชัน` ทำงานแบบซิงโครนัส การประกาศ `ชนิด` (`type`) ถูกทิ้ง
และกลืนสิ่งที่ตามมา ดู[คำสงวน](keywords.md)

## โคลเชอร์และค่าฟังก์ชัน

นิพจน์โคลเชอร์ที่เรียกทันที `(|x| x + 1)(5)` ใช้ได้ทุกที่ นอกจากนั้น

- โคลเชอร์ที่เก็บในตัวแปรเรียกด้วยชื่อบนอินเทอร์พรีเตอร์ไม่ได้ และบน JIT ก็เชื่อถือไม่ได้
- JIT ส่งฟังก์ชันหรือโคลเชอร์ให้ฟังก์ชันในตัวไม่ได้ `list_map` `list_filter` และฟังก์ชันในตัวทำนองเดียวกัน
  คืน `()` ส่วน `ลอง()` คืน `ผิดพลาด("try: first argument must be a function")` เสมอ ทั้งหมดนี้ใช้ได้บน
  อินเทอร์พรีเตอร์
- โปรแกรมที่เรียก `http_serve` จะรันบนอินเทอร์พรีเตอร์โดยอัตโนมัติ โคลเชอร์และ `ลอง` จึงใช้ได้ในตัวจัดการคำขอ

ให้ใช้ `ฟังก์ชัน` ระดับบนสุดที่มีชื่อและลูปธรรมดา

## โมดูล

- `ใช้ "ไฟล์"` โหลดเข้าเนมสเปซเดียวที่ใช้ร่วมกัน ถ้าสองไฟล์นิยามฟังก์ชันชื่อเดียวกัน ตัวที่โหลดทีหลังสุดจะชนะ
  เงียบๆ แม้ผู้เรียกจะอยู่ในไฟล์ที่โหลดก่อน กฎนี้ใช้กับจุดเริ่มต้นด้วย ไลบรารีจึงต้องไม่ผูกชื่อจุดเริ่มต้นอย่าง
  `start` เด็ดขาด
- ภายใน `โมดูล` ให้เรียกฟังก์ชันในโมดูลเดียวกันด้วยชื่อเต็ม (`เรขาคณิต::พื้นที่`) ถ้าเรียกด้วยชื่อเปล่าๆ จะล้มเหลว
- ค่าที่ผูกไว้ใน `โมดูล` ใช้ไม่ได้ ให้เปิดเผยค่าคงที่เป็นฟังก์ชัน

ให้ใส่ชื่อไลบรารีนำหน้าฟังก์ชันในไลบรารี เช่น `geom_area` ดู[โมดูลและโปรเจกต์](modules.md)

## เครื่องมือ

- `lingfu new` สร้าง `src/start.ling` แต่ `lingfu build` จะมองหา `main.ling` ถ้าแมนิเฟสต์ไม่ได้บอกเป็นอย่างอื่น
  ให้เพิ่ม `entry = "src/start.ling"` ในส่วน `[spirit]` ของ `Ling.toml`
- `lingfu check` `lingfu fmt` และ `lingfu translate` เรียกคำสั่งย่อยของ `ling` ที่ไม่มีอยู่ จึงแค่พิมพ์วิธีใช้
  ของ `ling` แล้วไม่ทำอะไร แต่ `check` และ `fmt` ยังรายงานว่าสำเร็จ ให้ตรวจโปรแกรมด้วย `ling run --interp`
  และแปลโปรแกรมด้วย `lingfu normalize <ภาษา>` (คำสั่งนี้เขียนทับไฟล์ `.ling` ทุกไฟล์ในโฟลเดอร์ปัจจุบัน
  จึงควรใช้กับสำเนา)
- `lingfu normalize` เขียนคำสงวนบางคำผิด ในภาษาจีน เกาหลี และไทย มันเขียน `form` เป็นคำที่ตัวแยกคำไม่ยอมรับ
  (ให้ใช้ตัวสะกดจาก[คำสงวน](keywords.md) เช่น `โครงสร้าง`) ปล่อย `choose` ไว้เป็นภาษาอังกฤษ และในภาษาญี่ปุ่น
  กับไทยจะเขียน `ok`/`bad` เป็นชื่อฟังก์ชันในตัว (`โอเค`/`ผิด`) ที่ใช้เป็นแพตเทิร์นของ `จับคู่` ไม่ได้ คำเกี่ยวกับ
  ความเป็นเจ้าของบางคำ (`copy` `lend` `share`) ก็ออกมาผิดในภาษาญี่ปุ่นและไทย ให้รันผลลัพธ์แล้วแก้คำเหล่านี้เอง
- `lingfu build` คอมไพล์โค้ด Rust ที่สร้างขึ้นด้วย Cargo จึงต้องมี Rust toolchain

## การทดสอบ

`lingfu test` รันเทสต์บน JIT ซึ่งไม่หยุดเมื่อเกิดข้อผิดพลาดขณะทำงาน จึงอาจพิมพ์ `All tests passed!` ทั้งที่
เทสต์ล้มเหลว ให้เทสต์พิมพ์บรรทัด `PASS` หรือ `FAIL` ที่ชัดเจนแล้วตรวจบรรทัดนั้น หรือรันเทสต์ด้วย
`ling run --interp` ไฟล์ช่วยที่วางใน `tests/` จะถูกถือเป็นเทสต์และล้มเหลวด้วย `no entry point`
จึงควรเก็บไฟล์ช่วยไว้ที่อื่น

## กับดักในการแยกวิเคราะห์

- บรรทัดที่ขึ้นต้นด้วย `-` หรือ `[` จะต่อจากบรรทัดก่อนหน้า
- `โครงสร้าง P { x: number, y: number }` เป็นข้อผิดพลาดทางไวยากรณ์ รายการฟิลด์ที่ระบุชนิดให้ปิดท้ายด้วย
  จุลภาค: `โครงสร้าง P { x: number, y: number, }`
- โคลเชอร์ไม่มีพารามิเตอร์ต้องเว้นวรรคเป็น `| | นิพจน์` เพราะ `||` คือ "หรือ"
- `ฟังก์ชัน main() { ... }` ไม่ใช่จุดเริ่มต้น ให้ใช้ `ผูก main = ทำ { ... }`
- `assert` `panic` `exit` `append_file` และ `delta_time` ไม่ใช่ฟังก์ชันในตัว ถ้าจะวัดเวลาต่อเฟรม
  ให้ลบค่า `time_now()` สองครั้งที่ต่อกัน
