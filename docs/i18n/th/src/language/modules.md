# โมดูลและโปรเจกต์

เมื่อโปรแกรมใหญ่เกินกว่าจะอยู่ในไฟล์เดียว ให้ย้ายฟังก์ชันไปไว้ในไฟล์ไลบรารีแล้วโหลดด้วย `ใช้` (`use`)
หน้านี้อธิบาย `ใช้` บล็อก `โมดูล` (`mod`) สิ่งที่เกิดขึ้นเมื่อชื่อชนกัน และวิธีจัดโปรเจกต์ด้วย `lingfu`

ระบบโมดูลของ Ling มีขนาดเล็ก `ใช้` โหลดไฟล์เข้าไปในเนมสเปซเดียวที่ใช้ร่วมกัน และไม่มีอะไรเป็นส่วนตัวเลย
นิสัยการตั้งชื่อไม่กี่ข้อด้านล่างจะช่วยให้ใช้งานได้สบาย

| รูปแบบ | สิ่งที่ทำ |
|---|---|
| `ใช้ "lib/ไฟล์.ling"` | โหลดไฟล์ ฟังก์ชัน ชนิด และการผูกระดับบนสุดของไฟล์นั้นเรียกด้วยชื่อตรงๆ ได้ |
| `ใช้ "lib/ไฟล์.ling" เป็น m` | โหลดไฟล์ และเรียกฟังก์ชันของไฟล์นั้นด้วย `m::ชื่อ()` |
| `โมดูล ชื่อ { ฟังก์ชัน f() { ... } }` | รวมฟังก์ชันภายในไฟล์เดียว เรียกด้วย `ชื่อ::f()` |

## ใช้: โหลดไฟล์อื่น

`ใช้ "ที่อยู่"` โหลดไฟล์ `.ling` อื่น ที่อยู่เป็นข้อความ และ**อ้างอิงจากไฟล์ที่มีคำสั่ง `ใช้` นั้น** ไม่ใช่จาก
โฟลเดอร์ที่คุณรัน `ling` จะละนามสกุล `.ling` ก็ได้

ทุกอย่างในไฟล์ที่โหลดจะใช้ได้ ทั้งฟังก์ชัน ชนิด `โครงสร้าง` และ `เลือกแบบ` และค่าที่ `ผูก` ไว้ระดับบนสุด
ไฟล์ที่ถูกโหลดก็ `ใช้` ไฟล์อื่นต่อได้ โดยที่อยู่อ้างอิงจากตำแหน่งของไฟล์นั้นเอง

**`lib/textkit.ling`**

```ling-module
// textkit: ฟังก์ชันช่วยจัดข้อความเล็กๆ
ฟังก์ชัน tk_ชิดขวา(ข้อความ, ความกว้าง) {
  ผูก ช่องว่าง = ความกว้าง - ความยาว(ข้อความ)
  ถ้า ช่องว่าง > 0 { str_repeat(" ", ช่องว่าง) + ข้อความ } มิฉะนั้น { ข้อความ }
}
ฟังก์ชัน tk_เส้น(ความกว้าง) { str_repeat("-", ความกว้าง) }
```

**`lib/report.ling`** โหลด `textkit.ling` จากโฟลเดอร์เดียวกับตัวเอง

```ling-module
ใช้ "textkit.ling"
โครงสร้าง สินค้า { ชื่อ, จำนวน, }
ฟังก์ชัน rp_แถว(รายการสินค้า) { รายการสินค้า.ชื่อ + tk_ชิดขวา(str(รายการสินค้า.จำนวน), 6) }
```

**`main.ling`**

```ling-module
ใช้ "lib/report.ling"
ผูก เริ่ม = ทำ {
  พิมพ์(rp_แถว(สินค้า("ชา", 3)))
  พิมพ์(rp_แถว(สินค้า("แยม", 12)))
  พิมพ์(tk_เส้น(9))
}
```

```sh
$ ling run main.ling
ชา     3
แยม    12
---------
```

`main.ling` ไม่ได้โหลด `textkit.ling` โดยตรง แต่ก็ยังเห็น `tk_เส้น` เพราะไฟล์ที่ถูกโหลดทั้งหมดใช้เนมสเปซ
เดียวกัน

### ใช้ ... เป็น

เมื่อใส่ `เป็น` (`as`) ต้องเรียกฟังก์ชันของไฟล์ที่โหลดผ่านชื่อแทน และจะเรียกด้วยชื่อตรงๆ **ไม่ได้**อีก

```ling-module
ใช้ "lib/textkit.ling" เป็น tk
ผูก เริ่ม = ทำ {
  พิมพ์(tk::tk_เส้น(5))
}
```

```sh
$ ling run alias.ling
-----
```

## ชื่อชนกัน

ชื่อที่โหลดเข้ามาทั้งหมดใช้เนมสเปซเดียวกัน และเมื่อนิยามสองตัวชนกันจะไม่มีทั้งข้อผิดพลาดและคำเตือน

- ถ้าไฟล์ที่โหลดสองไฟล์นิยามฟังก์ชันชื่อเดียวกัน ตัวที่โหลด**ทีหลังสุด**จะถูกใช้ แม้ผู้เรียกจะอยู่ในไฟล์ที่โหลด
  ก่อนก็ตาม
- นิยามในไฟล์หลักชนะทุกอย่างที่ไฟล์นั้นโหลดเข้ามา

สมมติว่า `lib/first.ling` มี `ฟังก์ชัน ใคร() { "ไฟล์แรก" }` และ `lib/second.ling` มี
`ฟังก์ชัน ใคร() { "ไฟล์ที่สอง" }`

```ling-module
ใช้ "lib/first.ling"
ใช้ "lib/second.ling"
ผูก เริ่ม = ทำ {
  พิมพ์(ใคร())
}
```

```sh
$ ling run clash.ling
ไฟล์ที่สอง
```

ถ้าเพิ่ม `ฟังก์ชัน ใคร() { "ไฟล์หลัก" }` ลงในไฟล์หลัก จะพิมพ์ `ไฟล์หลัก` แทน

กฎเดียวกันใช้กับจุดเริ่มต้นด้วย ถ้าไลบรารีผูก `start` และถูกโหลดหลัง `start` ของไฟล์หลัก `start` ของไลบรารี
จะเป็นตัวที่ทำงาน ดังนั้น

- **ตั้งคำนำหน้าสั้นๆ ให้แต่ละไลบรารี** (`tk_` `rp_`) และใช้กับทุกฟังก์ชัน
- **อย่าใส่การผูกจุดเริ่มต้นในไลบรารีเด็ดขาด** มีแต่โปรแกรมหลักเท่านั้นที่มีจุดเริ่มต้น
- **ส่งข้อมูลผ่านพารามิเตอร์** ฟังก์ชันในไลบรารีเห็นการผูกระดับบนสุด แต่ไม่เห็นการผูกภายในของผู้เรียกเลย

## โมดูล: เนมสเปซภายในไฟล์

`โมดูล ชื่อ { ... }` รวมฟังก์ชันไว้ใต้ชื่อเดียวและเข้าถึงด้วย `::` มีประโยชน์เมื่อฟังก์ชันหลายกลุ่มต้องการ
ใช้ชื่อเดียวกัน

```ling
โมดูล เวกเตอร์ {
  ฟังก์ชัน บวก(a, b) { [a[0] + b[0], a[1] + b[1]] }
  ฟังก์ชัน ผลคูณจุด(a, b) { a[0] * b[0] + a[1] * b[1] }
  ฟังก์ชัน ความยาวกำลังสอง(a) { เวกเตอร์::ผลคูณจุด(a, a) }
}
โมดูล เงิน {
  ฟังก์ชัน บวก(a, b) { ปัดเศษ((a + b) * 100) / 100 }
}
ผูก เริ่ม = ทำ {
  พิมพ์(เวกเตอร์::บวก([1, 2], [3, 4]))
  พิมพ์(เวกเตอร์::ความยาวกำลังสอง([3, 4]))
  พิมพ์(เงิน::บวก(0.1, 0.2))
}
```
```output
[4, 6]
25
0.3
```

กฎของ `โมดูล`

- **เรียกฟังก์ชันในโมดูลเดียวกันด้วยชื่อเต็ม** (`เวกเตอร์::ผลคูณจุด`) แบบที่ `ความยาวกำลังสอง` ทำ ถ้าเขียน
  แค่ `ผลคูณจุด(a, a)` จะล้มเหลวบนอินเทอร์พรีเตอร์และได้ `()` บน JIT
- ฟังก์ชันใน `โมดูล` เรียกฟังก์ชันระดับบนสุดของไฟล์ได้โดยไม่ต้องมีคำนำหน้า
- **อย่าผูกค่าใน `โมดูล`** `เวกเตอร์::จุดกำเนิด` ได้ `()` บน JIT และได้ข้อความ `เวกเตอร์::จุดกำเนิด`
  บนอินเทอร์พรีเตอร์ แม้แต่ฟังก์ชันของโมดูลเองก็มองไม่เห็นค่านั้น ให้เปิดเผยค่าคงที่เป็นฟังก์ชันแทน:
  `ฟังก์ชัน จุดกำเนิด() { [0, 0] }` แล้วเรียกด้วย `เวกเตอร์::จุดกำเนิด()`

## โปรเจกต์ด้วย lingfu

`lingfu new <ชื่อ>` สร้างโฟลเดอร์โปรเจกต์

```sh
$ lingfu new shop
~ Ling Manifest — Spirit Token Descends ~
Creating project: shop

✓ Spirit Realm created!
  cd shop
  lingfu build
  lingfu run
```

```text
shop/
  Ling.toml          ไฟล์แมนิเฟสต์
  README.md
  ling.ignore
  lexicons/en.ling   ข้อมูลภาษา (อย่าแก้ไข)
  src/start.ling     จุดเริ่มต้น
  tests/test.ling    เทสต์ตัวอย่าง
```

วางไลบรารีไว้ใต้ `src/` เช่น `src/lib/textkit.ling` แล้วโหลดจาก `src/start.ling` ด้วย
`ใช้ "lib/textkit.ling"`

| คำสั่ง | สิ่งที่ทำ |
|---|---|
| `lingfu run` | รัน `src/start.ling` |
| `lingfu test` | รันไฟล์ `.ling` ทุกไฟล์ใน `tests/` |
| `lingfu build` | สร้างโปรแกรมสำหรับแจกจ่าย (ต้องมีบรรทัด `entry` ด้านล่าง) |

### จุดเริ่มต้นในโปรเจกต์

- **โปรแกรม**คือ `src/start.ling` ซึ่งมีการผูกจุดเริ่มต้น
- **เทสต์**ใน `tests/` ก็เป็นโปรแกรมเช่นกัน มันผูกชื่ออะไรก็ได้กับบล็อก `ทำ` (เทสต์ตัวอย่างใช้
  `bind test = do { ... }`) และโหลดโค้ดที่จะทดสอบด้วยที่อยู่ที่อ้างอิงจากตัวเอง เช่น
  `ใช้ "../src/lib/textkit.ling"` ทุกไฟล์ใน `tests/` ต้องมีจุดเริ่มต้น ไฟล์ช่วยที่ไม่มีจุดเริ่มต้นจะล้มเหลว
  ด้วย `no entry point`
- **ไลบรารี**ไม่มีการผูกจุดเริ่มต้นเลย

### แมนิเฟสต์

`Ling.toml` ถูกสร้างให้อัตโนมัติ `lingfu run` และ `lingfu test` ใช้ได้ทันทีโดยไม่ต้องแก้ แต่ `lingfu build`
จะมองหา `main.ling` ถ้าแมนิเฟสต์ไม่ได้ระบุไฟล์เริ่มต้น ให้เพิ่มบรรทัด `entry` ในส่วน `[spirit]`

```toml
[spirit]
name = "shop"
kind = "bin"
version = "2030.0.0"
entry = "src/start.ling"
```

ดูคำสั่งทั้งหมดได้ที่ [lingfu](../tools/lingfu.md) และดูพฤติกรรมแปลกๆ ของเครื่องมือในตอนนี้ได้ที่
[ข้อจำกัดที่ทราบ](limits.md)
