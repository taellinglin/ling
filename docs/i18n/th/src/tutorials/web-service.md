# เว็บเซอร์วิสขนาดเล็ก

Ling มีเว็บเซิร์ฟเวอร์ในตัว ในหน้านี้ คุณจะส่งหน้าเว็บ อ่านสิ่งที่เบราว์เซอร์ส่งมา ตอบกลับเป็น JSON
เก็บบันทึกลงฐานข้อมูล SQLite แล้วรวมทั้งหมดเป็น API บันทึกขนาดเล็ก ไม่ต้องใช้เฟรมเวิร์กและไม่ต้องติดตั้งอะไรเพิ่ม

โค้ดที่เริ่มเซิร์ฟเวอร์ตรวจสอบในเทอร์มินัลไม่ได้ บล็อกเหล่านั้นจึงไม่มีผลลัพธ์ ส่วนฟังก์ชันช่วยและตัวจัดการเป็นฟังก์ชันธรรมดา
ทดสอบได้โดยไม่ต้องมีเซิร์ฟเวอร์ ดังที่จะเห็นด้านล่าง

ฟังก์ชันในตัวด้านเว็บเซิร์ฟเวอร์และฐานข้อมูล (`http_*`, `db_*`, `query_param` ฯลฯ) บางตัวมีชื่อภาษาไทยในอินเทอร์พรีเตอร์
เช่น `เว็บเส้นทาง` สำหรับ `http_route` แต่ `lingfu normalize` ไม่ได้แปลงให้ ตัวอย่างในหน้านี้จึงใช้ชื่อภาษาอังกฤษ
ชื่อฟิลด์ของคำขอและการตอบกลับ (`query`, `body`, `status` ฯลฯ) ต้องเป็นภาษาอังกฤษด้วย เพราะเซิร์ฟเวอร์อ่านค่าตามชื่อ

## สวัสดี เว็บ

```ling-gui
ฟังก์ชัน สวัสดี(คำขอ) {
    คืน "<h1>สวัสดีจาก Ling!</h1>"
}

ผูก เริ่ม = ทำ {
    http_route("GET", "/", สวัสดี)
    http_serve("127.0.0.1", 8080)
}
```

บันทึกเป็น `hello.ling` รันแล้วเปิด <http://127.0.0.1:8080/> ในเบราว์เซอร์:

```sh
ling run hello.ling
```

- `http_route(method, path, handler)` ลงทะเบียน**ตัวจัดการ**สำหรับเมธอดหนึ่งและพาธที่ตรงกันพอดีหนึ่งพาธ
  ให้ลงทะเบียนทุกเส้นทางก่อนเริ่มเซิร์ฟเวอร์
- `http_serve(host, port)` เริ่มเซิร์ฟเวอร์และตอบคำขอไปเรื่อยๆ จนกว่าคุณจะกด Ctrl+C ใช้ `"127.0.0.1"`
  สำหรับเครื่องของคุณเท่านั้น และ `"0.0.0.0"` เพื่อรับการเชื่อมต่อจากเครือข่าย
- ตัวจัดการรับคำขอแล้วคืนสตริง สตริงจะถูกตอบกลับเป็นหน้า HTML พร้อมสถานะ `200`
- พาธที่ไม่ได้ลงทะเบียนจะได้ `404 not found`

ถ้าต้องการส่งไฟล์อย่าง CSS รูปภาพ หรือทั้งโฟลเดอร์ ให้เพิ่ม `http_static(prefix, dir)`:
`http_static("/css", "css")` จับคู่ `/css/site.css` กับไฟล์ `css/site.css` ไฟล์สแตติกจะถูกส่งไปแบบไบต์ต่อไบต์
และไม่ผ่านตัวจัดการของคุณ

## เบราว์เซอร์ส่งอะไรมา

อาร์กิวเมนต์ของตัวจัดการคือ `Request` ซึ่งมีฟิลด์ข้อความเหล่านี้:

| ฟิลด์ | เนื้อหา |
|---|---|
| `method` | `"GET"` `"POST"` ฯลฯ เป็นตัวพิมพ์ใหญ่ |
| `path` | พาธที่ไม่รวมสตริงคิวรี |
| `query` | สตริงคิวรีดิบหลัง `?` เช่น `name=Ada&page=2` |
| `body` | เนื้อหาคำขอเป็นข้อความ |
| `cookie` | เฮดเดอร์ `Cookie` แบบดิบ |
| `authorization` | เฮดเดอร์ `Authorization` แบบดิบ |
| `client_ip` | ที่อยู่ของไคลเอนต์จากเฮดเดอร์พร็อกซี หรือ `""` |

เส้นทางจับคู่พาธแบบตรงตัว จึงไม่มีพารามิเตอร์ในพาธอย่าง `/note/2` ให้ส่งค่าผ่านสตริงคิวรีแทน (`/note?id=2`)
แล้วอ่านด้วย `query_param(text, name, default)` ซึ่งถอดรหัสเปอร์เซ็นต์ให้ และใช้กับเนื้อหาฟอร์มได้ด้วย
เพราะฟอร์มใช้รูปแบบ `a=1&b=2` เหมือนกัน

```ling
ผูก เริ่ม = ทำ {
    ผูก คิวรี = "name=%E0%B8%AA%E0%B8%A1%E0%B8%8A%E0%B8%B2%E0%B8%A2&lang=th"
    พิมพ์(query_param(คิวรี, "name", "ไม่มีชื่อ"))
    พิมพ์(query_param(คิวรี, "page", "1"))
}
```

```output
สมชาย
1
```

อย่าใส่ข้อความจากผู้ใช้ลงใน HTML ตรงๆ `html_escape` จะเปลี่ยน `& < > " '` เป็นเอนทิตี:

```ling
ผูก เริ่ม = ทำ {
    พิมพ์(html_escape("<b>ทอม & เจอร์รี่</b>"))
}
```

```output
&lt;b&gt;ทอม &amp; เจอร์รี่&lt;/b&gt;
```

หน้าทักทายจึงเป็นแบบนี้:

```ling-module
ฟังก์ชัน ทักทาย(คำขอ) {
    ผูก ชื่อ = html_escape(query_param(คำขอ.query, "name", "ชาวโลก"))
    คืน "<h1>สวัสดี " + ชื่อ + "!</h1>"
}
```

## ตอบกลับเป็น JSON

ถ้าต้องการกำหนดรหัสสถานะหรือชนิดเนื้อหา ให้คืนเรคคอร์ดแทนสตริง ประกาศ `form` (ภาษาไทยเขียนว่า `โครงสร้าง`)
โดยเลือกชื่อฟิลด์จาก `status`, `content_type`, `body`, `set_cookie` และ `location` เรคคอร์ดสร้างตามตำแหน่ง
ส่วนเซิร์ฟเวอร์อ่านฟิลด์ตามชื่อ:

```ling-module
โครงสร้าง Response { status, content_type, body }

ฟังก์ชัน ตอบJSON(สถานะ, เนื้อหา) {
    คืน Response(สถานะ, "application/json", เนื้อหา)
}
```

Ling สร้าง JSON ด้วยการต่อสตริง ให้ส่งข้อความทุกชิ้นผ่าน `json_escape` ซึ่งจะ escape เครื่องหมายคำพูด
แบ็กสแลช และอักขระควบคุม:

```ling
ผูก เริ่ม = ทำ {
    ผูก หัวข้อ = "พูดว่า \"สวัสดี\""
    พิมพ์("{\"title\":\"" + json_escape(หัวข้อ) + "\"}")
}
```

```output
{"title":"พูดว่า \"สวัสดี\""}
```

ถ้าต้องการเปลี่ยนเส้นทาง ให้คืนสถานะ `302` พร้อม `location` เช่น `Response(302, "text/plain", "", "", "/new")`
กับเรคคอร์ดที่ประกาศครบทั้งห้าฟิลด์

## API บันทึกด้วย SQLite

คราวนี้เก็บบันทึกไว้ในฐานข้อมูล ฟังก์ชันในตัวสามตัวครอบคลุม SQLite:

| ฟังก์ชันในตัว | ใช้ทำอะไร |
|---|---|
| `db_open(path)` | เปิด (หรือสร้าง) ไฟล์ฐานข้อมูล หรือใช้ `":memory:"` |
| `db_exec(sql, params...)` | รันคำสั่งที่เปลี่ยนข้อมูล คืนจำนวนแถวที่เปลี่ยน |
| `db_query(sql, params...)` | รันคิวรี คืนรายการของแถว อ่านด้วย `row.column` |

พารามิเตอร์ผูกตามตำแหน่งเป็น `?1` `?2` ไปเรื่อยๆ ส่งข้อมูลจากผู้ใช้เป็นพารามิเตอร์เสมอ อย่าต่อเข้าไปในข้อความ SQL

ตัวจัดการเป็นแค่ฟังก์ชัน คุณจึงลองใช้ได้โดยไม่ต้องมีเซิร์ฟเวอร์ ด้วยการสร้างคำขอขึ้นเอง ในที่นี้ `Request`
เป็น `โครงสร้าง` เล็กๆ ที่มีเฉพาะฟิลด์ที่ตัวจัดการใช้:

```ling
โครงสร้าง Response { status, content_type, body }
โครงสร้าง Request { method, path, query, body }

ฟังก์ชัน ตอบJSON(สถานะ, เนื้อหา) {
    คืน Response(สถานะ, "application/json", เนื้อหา)
}

ฟังก์ชัน บันทึกJSON(แถว) {
    คืน "{\"id\":" + แถว.id + ",\"text\":\"" + json_escape(แถว.text) + "\"}"
}

ฟังก์ชัน รายการบันทึก(คำขอ) {
    ผูก แถวทั้งหมด = db_query("SELECT id, text FROM notes ORDER BY id")
    ผูก ผล = "["
    ผูก i = 0
    ขณะที่ i < ความยาว(แถวทั้งหมด) {
        ถ้า i > 0 {
            ผูก ผล = ผล + ","
        }
        ผูก ผล = ผล + บันทึกJSON(แถวทั้งหมด[i])
        ผูก i = i + 1
    }
    คืน ตอบJSON(200, ผล + "]")
}

ฟังก์ชัน เพิ่มบันทึก(คำขอ) {
    ผูก ข้อความ = query_param(คำขอ.body, "text", "")
    ถ้า ข้อความ == "" {
        คืน ตอบJSON(400, "{\"error\":\"ต้องมี text\"}")
    }
    db_exec("INSERT INTO notes(text) VALUES (?1)", ข้อความ)
    ผูก แถวทั้งหมด = db_query("SELECT id, text FROM notes ORDER BY id DESC LIMIT 1")
    คืน ตอบJSON(201, บันทึกJSON(แถวทั้งหมด[0]))
}

ฟังก์ชัน เตรียม() {
    db_open(":memory:")
    db_exec("CREATE TABLE notes(id INTEGER PRIMARY KEY AUTOINCREMENT, text TEXT NOT NULL)")
}

ผูก เริ่ม = ทำ {
    เตรียม()
    ผูก r1 = เพิ่มบันทึก(Request("POST", "/notes", "", "text=ซื้อนม"))
    พิมพ์(r1.status, " ", r1.body)
    ผูก r2 = เพิ่มบันทึก(Request("POST", "/notes", "", "text=พูดว่า+%22สวัสดี%22"))
    พิมพ์(r2.status, " ", r2.body)
    ผูก r3 = เพิ่มบันทึก(Request("POST", "/notes", "", ""))
    พิมพ์(r3.status, " ", r3.body)
    ผูก r4 = รายการบันทึก(Request("GET", "/notes", "", ""))
    พิมพ์(r4.status, " ", r4.body)
}
```

```output
201 {"id":1,"text":"ซื้อนม"}
201 {"id":2,"text":"พูดว่า \"สวัสดี\""}
400 {"error":"ต้องมี text"}
200 [{"id":1,"text":"ซื้อนม"},{"id":2,"text":"พูดว่า \"สวัสดี\""}]
```

รายการสร้างด้วยลูป `ขณะที่` และดัชนี เพราะตัวลูป `สำหรับ` อัปเดตการผูกที่อยู่นอกลูปไม่ได้

### เปิดให้บริการ

คงตัวจัดการและ `เตรียม` ไว้เหมือนด้านบนทุกอย่าง เอาเรคคอร์ด `Request` ที่ใช้ทดสอบออก แล้วเปลี่ยนบล็อก `เริ่ม`
เป็นการลงทะเบียนเส้นทาง:

```ling-gui
โครงสร้าง Response { status, content_type, body }

ฟังก์ชัน ตอบJSON(สถานะ, เนื้อหา) {
    คืน Response(สถานะ, "application/json", เนื้อหา)
}

ฟังก์ชัน บันทึกJSON(แถว) {
    คืน "{\"id\":" + แถว.id + ",\"text\":\"" + json_escape(แถว.text) + "\"}"
}

ฟังก์ชัน รายการบันทึก(คำขอ) {
    ผูก แถวทั้งหมด = db_query("SELECT id, text FROM notes ORDER BY id")
    ผูก ผล = "["
    ผูก i = 0
    ขณะที่ i < ความยาว(แถวทั้งหมด) {
        ถ้า i > 0 {
            ผูก ผล = ผล + ","
        }
        ผูก ผล = ผล + บันทึกJSON(แถวทั้งหมด[i])
        ผูก i = i + 1
    }
    คืน ตอบJSON(200, ผล + "]")
}

ฟังก์ชัน เพิ่มบันทึก(คำขอ) {
    ผูก ข้อความ = query_param(คำขอ.body, "text", "")
    ถ้า ข้อความ == "" {
        คืน ตอบJSON(400, "{\"error\":\"ต้องมี text\"}")
    }
    db_exec("INSERT INTO notes(text) VALUES (?1)", ข้อความ)
    ผูก แถวทั้งหมด = db_query("SELECT id, text FROM notes ORDER BY id DESC LIMIT 1")
    คืน ตอบJSON(201, บันทึกJSON(แถวทั้งหมด[0]))
}

ฟังก์ชัน เตรียม() {
    db_open("notes.db")
    db_exec("CREATE TABLE IF NOT EXISTS notes(id INTEGER PRIMARY KEY AUTOINCREMENT, text TEXT NOT NULL)")
}

ฟังก์ชัน ทักทาย(คำขอ) {
    ผูก ชื่อ = html_escape(query_param(คำขอ.query, "name", "ชาวโลก"))
    คืน "<h1>สวัสดี " + ชื่อ + "!</h1>"
}

ผูก เริ่ม = ทำ {
    เตรียม()
    http_route("GET", "/", ทักทาย)
    http_route("GET", "/notes", รายการบันทึก)
    http_route("POST", "/notes", เพิ่มบันทึก)
    http_serve("127.0.0.1", to_number(cli_arg("port", "8080")))
}
```

เวอร์ชันนี้เปิดไฟล์ `notes.db` ที่อยู่ข้างโปรแกรม บันทึกจึงยังอยู่แม้รีสตาร์ต `cli_arg("port", "8080")` อ่าน `--port`
จากบรรทัดคำสั่งเป็นข้อความ และ `to_number` แปลงเป็นตัวเลข

```sh
ling run notes.ling --port 8080
```

ลองจากเทอร์มินัลอีกหน้าต่าง:

```text
$ curl -X POST -d "text=Buy milk" http://127.0.0.1:8080/notes
{"id":1,"text":"Buy milk"}
$ curl http://127.0.0.1:8080/notes
[{"id":1,"text":"Buy milk"}]
$ curl "http://127.0.0.1:8080/?name=%3Cb%3EAda"
<h1>สวัสดี &lt;b&gt;Ada!</h1>
```

## รับผู้เข้าชมพร้อมกันได้มากขึ้น: workers

โดยปกติ อินเทอร์พรีเตอร์ตัวเดียวจะตอบคำขอทีละรายการ ตัวจัดการที่ช้าจึงทำให้คนอื่นต้องรอ ไฟล์สแตติกจาก
`http_static` ไม่ได้รับผลกระทบ เพราะถูกส่งแยกต่างหากและส่งพร้อมกันได้ ถ้าต้องการให้ตัวจัดการทำงานพร้อมกัน
ให้ส่งจำนวน worker เป็นอาร์กิวเมนต์ตัวที่สามของ `http_serve` ในตัวอย่างนี้อ่านมาจากบรรทัดคำสั่ง:

```ling-gui
ฟังก์ชัน สวัสดี(คำขอ) {
    คืน "<h1>สวัสดีจาก Ling!</h1>"
}

ฟังก์ชัน จำนวนworker() {
    คืน to_number(cli_arg("workers", "1"))
}

ผูก เริ่ม = ทำ {
    http_route("GET", "/", สวัสดี)
    http_serve("127.0.0.1", 8080, จำนวนworker())
}
```

```sh
ling run hello.ling --workers 4
```

เมื่อมี worker มากกว่าหนึ่งตัว อินเทอร์พรีเตอร์ที่เพิ่มมาแต่ละตัวจะโหลดโปรแกรมของคุณใหม่ และบล็อก `เริ่ม`
จะทำงานเพียงครั้งเดียวบนตัวหลัก ดังนั้น:

- ตัวจัดการต้องเป็น**ฟังก์ชันระดับบนสุดที่มีชื่อ** เหมือนตัวจัดการทุกตัวในหน้านี้
- เก็บค่าตั้งไว้ในฟังก์ชัน (อย่าง `จำนวนworker()` ด้านบน) ไม่ใช่ใน `ผูก` ระดับบนสุด
- worker แต่ละตัวจะเปิดฐานข้อมูลที่คุณเปิดด้วย `db_open` ใหม่ ให้ใช้ไฟล์ ไม่ใช่ `":memory:"`
  ไม่อย่างนั้น worker แต่ละตัวจะได้ฐานข้อมูลว่างของตัวเอง เมื่อ worker สองตัวเขียนพร้อมกัน SQLite
  จะให้การเขียนรอคิว

## ling-lang.org ก็ทำงานด้วยสิ่งนี้

เว็บไซต์ ling-lang.org ให้บริการโดยโปรแกรม Ling ไฟล์เดียวชื่อ `site.ling` ซึ่งสร้างจากฟังก์ชันในตัวชุดเดียวกันนี้
มันลงทะเบียนโฟลเดอร์สแตติกสำหรับ CSS รูปภาพ วิดีโอ PDF ของหนังสือ Ling และเอกสารชุดนี้ด้วย `http_static`
ตอบหน้าแรกและ JSON endpoint บางตัวด้วย `http_route` และเริ่มทำงานพร้อม worker:

```sh
ling run site.ling --host 0.0.0.0 --port 80 --workers 4
```

มันยังใช้ `http_vhost(host, dir)` ซึ่งส่งโฟลเดอร์ที่รากของชื่อโฮสต์อื่น โดยจับคู่กับเฮดเดอร์ `Host` ของคำขอ
ถ้า `dir` เป็นที่อยู่ `http://` หรือ `https://` แทนโฟลเดอร์ โฮสต์นั้นจะเปลี่ยนเส้นทางไปที่อยู่นั้น
`docs.ling-lang.org` เดิมจึงส่งผู้เข้าชมไปที่ `ling-lang.org/docs` แบบนี้:

```ling-module
ฟังก์ชัน ลงทะเบียนโฮสต์เอกสาร() {
    http_vhost("docs.ling-lang.org", "https://ling-lang.org/docs")
    คืน จริง
}
```

## ลองทำดู

1. เพิ่ม `GET /note?id=2` ที่คืนบันทึกหนึ่งรายการ หรือสถานะ `404` พร้อม `{"error":"not found"}`
   เมื่อ `db_query` คืนรายการว่าง
2. เพิ่ม `POST /delete?id=2` ด้วย `db_exec("DELETE FROM notes WHERE id = ?1", id)` ใช้ตัวเลขที่ `db_exec`
   คืนมาเพื่อตอบ `404` เมื่อไม่มีอะไรถูกลบ
3. ส่งโฟลเดอร์ `public/` ที่มี `index.html` ที่ `/app` ด้วย `http_static`
4. ทำให้หน้าทักทายนับจำนวนการเข้าชมในตาราง `visits` และแสดงยอดรวม

ดูฟังก์ชันในตัวด้านเซิร์ฟเวอร์ทั้งหมดได้ที่ [เว็บเซิร์ฟเวอร์และ HTTP](../reference/web.md) และ
[ฐานข้อมูล (SQLite)](../reference/database.md)
