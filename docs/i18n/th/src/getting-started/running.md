# การรันโปรแกรม

ใช้ `ling run` เพื่อรันไฟล์เดียว และใช้ `lingfu run` เพื่อรันทั้งโปรเจกต์ หน้านี้อธิบายทั้งสองแบบ
อธิบายสองวิธีที่ Ling ใช้รันโค้ดของคุณ และวิธีทำให้โปรแกรมกลายเป็นสิ่งที่แจกจ่ายได้

## รันไฟล์

```sh
ling run hello.ling
ling hello.ling          # แบบย่อของคำสั่งเดียวกัน
```

`ling run` จะแจงไวยากรณ์ไฟล์ หาจุดเริ่มต้น (`ผูก เริ่ม = ทำ { ... }`) แล้วรัน
ไฟล์ซอร์สใช้นามสกุล `.ling`, `.灵`, `.霊`, `.령` หรือ `.ลิง` ก็ได้

อาร์กิวเมนต์ที่อยู่หลังชื่อไฟล์จะคงอยู่ในบรรทัดคำสั่งให้โปรแกรมอ่านได้: `get_args()` คืนบรรทัดคำสั่งทั้งหมด
และ `cli_arg("port", "8080")` อ่านตัวเลือกอย่าง `--port 99` โดยใช้ `"8080"` เมื่อไม่มีตัวเลือกนี้

## JIT หรืออินเทอร์พรีเตอร์

Ling มีแบ็กเอนด์สองแบบ:

| คำสั่ง | แบ็กเอนด์ | เหมาะกับ |
|---|---|---|
| `ling run file.ling` | Cranelift JIT (ค่าเริ่มต้น) | ความเร็ว คอมไพล์โปรแกรมเป็นโค้ดเครื่องก่อน |
| `ling run --interp file.ling` | อินเทอร์พรีเตอร์แบบไล่ต้นไม้ | การวินิจฉัยปัญหา เป็นมาตรฐานอ้างอิงพฤติกรรมของ Ling |

ถ้า JIT คอมไพล์โปรแกรมไม่ได้ `ling run` จะให้อินเทอร์พรีเตอร์รันทั้งโปรแกรมแทน ถ้าโปรแกรมใหญ่มากจนคอมไพล์นานเกินไป
ลดระดับการปรับแต่งของ JIT ได้ด้วย `--O0`, `--O1`, `--O2` หรือ `--O3` (ค่าเริ่มต้นคือ `--O3`)

### เมื่อโปรแกรม "ไม่ทำอะไรเลย" ให้ลอง `--interp`

บน JIT การเรียกฟังก์ชันที่ไม่มีอยู่จะไม่คืนอะไรเลย และโปรแกรมทำงานต่อไป โปรแกรมนี้พิมพ์ชื่อผิดเป็น `draw_rectt`:

```ling
ผูก เริ่ม = ทำ {
    พิมพ์("ก่อน")
    draw_rectt(1, 2)
    พิมพ์("หลัง")
}
```
```output
ก่อน
หลัง
```

อินเทอร์พรีเตอร์จะหยุดและบอกว่าเกิดอะไรขึ้น:

```text
$ ling run --interp typo.ling
[detected language: Thai (ภาษาไทย)]
ก่อน
error[runtime]: unknown function 'draw_rectt'
 --> typo.ling
  traceback (deepest call last):
    0: start
  hint: check the spelling, or `use` the module that defines it
```

เมื่อใดที่รู้สึกว่าโค้ดบางส่วนถูกเมินเฉย ให้รันด้วย `--interp` อีกครั้งจนเป็นนิสัย
ความแตกต่างอื่น ๆ ระหว่างสองแบ็กเอนด์ดูได้ที่[ข้อจำกัดที่ทราบ](../language/limits.md)

### เซิร์ฟเวอร์รันบนอินเทอร์พรีเตอร์

โปรแกรมที่เรียก `http_serve` (หรือชื่อภาษาไทย `เว็บเสิร์ฟ`) หรือ `lingtp_serve` จะรันบนอินเทอร์พรีเตอร์เสมอ
แม้ไม่ได้ใส่ `--interp` เพราะตัวจัดการคำขอเป็นโคลเชอร์ที่ส่งให้ฟังก์ชันในตัว ซึ่ง JIT ยังไม่รองรับ
เว็บเซอร์วิสส่วนใหญ่ใช้เวลารอเครือข่าย จึงแทบไม่รู้สึกถึงความต่างด้านความเร็ว ดู[เว็บเซอร์วิสขนาดเล็ก](../tutorials/web-service.md)

### รันในเบราว์เซอร์

`ling run --wasm file.ling` (หรือ `--web`) จะบิลด์โปรแกรมเป็น WebAssembly เปิดเว็บเซิร์ฟเวอร์ในเครื่อง
แล้วเปิดเบราว์เซอร์ให้ การบิลด์ครั้งแรกต้องคอมไพล์รันไทม์ อาจใช้เวลาราวหนึ่งนาที และต้องมีโปรแกรม `lingc` อยู่ข้าง `ling`

## โปรเจกต์ด้วย lingfu

ถ้างานใหญ่กว่าไฟล์เดียว ให้ `lingfu` สร้างโปรเจกต์ให้:

```sh
lingfu new demo
cd demo
lingfu run
```

```text
Running ...\demo\src\start.ling...
🌊 Welcome to demo Spirit Realm 🌊
Spirit Level: 铁
```

`lingfu new` สร้างโครงสร้างแบบนี้:

```text
demo/
├── Ling.toml          ไฟล์แมนิเฟสต์
├── README.md
├── .gitignore
├── ling.ignore        ไฟล์ที่ไม่ต้องรวมตอนเผยแพร่
├── lexicons/en.ling
├── src/start.ling     โปรแกรมจุดเริ่มต้น
└── tests/test.ling
```

| คำสั่ง | หน้าที่ |
|---|---|
| `lingfu run` | รันโปรแกรมจุดเริ่มต้นด้วย `ling run` อาร์กิวเมนต์เพิ่มเติมจะถูกส่งต่อไป |
| `lingfu test` | รันไฟล์ `.ling` ทุกไฟล์ใน `tests/` ทีละไฟล์ |
| `lingfu build` | บิลด์ไฟล์โปรแกรมแบบเนทีฟด้วย `ling build --aot` |
| `lingfu clean` | ลบผลลัพธ์จากการบิลด์ |

`lingfu new demo --lang th` จะสร้างโปรเจกต์เป็นภาษาไทย รวมถึงชื่อโฟลเดอร์และชื่อไฟล์ด้วย
แมนิเฟสต์คือ `ลิงฟู.toml` และจุดเริ่มต้นคือ `ต้นกำเนิด/เริ่ม.ลิง` คำสั่งทั้งหมดดูได้ที่ [lingfu](../tools/lingfu.md)

## Ling.toml

แมนิเฟสต์ที่ `lingfu new` เขียนให้มีหน้าตาแบบนี้:

```toml
[spirit]
name = "demo"
kind = "bin"
version = "2030.0.0"

[author]
ling-lin = { email = "you@example.com" }

[realm]
language = "en"
level    = "铁"
source   = "src"

[root]
core = { version = "2030.0", language = "en" }

[depends]
# Add dependencies: spirit-name = { version = "x.y.z" }
```

- `[spirit]` ตั้งชื่อโปรเจกต์ เพิ่ม `entry = "src/start.ling"` ไว้ตรงนี้ได้
- `[realm]` กำหนดภาษาของโปรเจกต์และโฟลเดอร์ซอร์ส
- `[root]` และ `[depends]` ระบุไลบรารี `core` และแพ็กเกจของคุณ

`lingfu run` และ `lingfu test` หา `src/start.ling` เจอเอง แต่ `ling build` (และ `lingfu build`)
จะหา `main.ling` ถ้าแมนิเฟสต์ไม่ได้ระบุไว้ ดังนั้น**ให้เพิ่ม `entry = "src/start.ling"` ใต้ `[spirit]`** ก่อนบิลด์

## บิลด์โปรแกรม

`ling build` เปลี่ยนไฟล์หรือโฟลเดอร์โปรเจกต์ให้เป็นสิ่งที่แจกจ่ายได้:

```sh
ling build game.ling                      # แพลตฟอร์มเครื่องนี้ + web ลงใน dist/
ling build . --platform win,web --out dist
ling build . --platform all --pack --icon logo.svg
```

| ตัวเลือก | ความหมาย |
|---|---|
| `--out <dir>` | โฟลเดอร์ผลลัพธ์ (ค่าเริ่มต้น `dist`) แต่ละแพลตฟอร์มมีโฟลเดอร์ย่อยของตัวเอง |
| `--platform <list>` | คั่นด้วยจุลภาค: `web`, `win`, `lin`, `mac`, `macarm`, `pios`, `kernel`, `rpi`, `lingos`, `lingos-rpi` โดย `all` หมายถึง `win,lin,mac,web` |
| `--icon <file>` | ไอคอนแอป (`.svg`, `.png`, `.ico` ฯลฯ) |
| `--pack` | ฝังไฟล์ใน `[includes]` ของแมนิเฟสต์ไว้ในไฟล์โปรแกรม |
| `--aot` | คอมไพล์ล่วงหน้าเป็นโค้ดเครื่องแทนการฝังอินเทอร์พรีเตอร์ |

ถ้าไม่ใส่ `--platform` การบิลด์จะใช้รายการ `targets` ในแมนิเฟสต์ หรือถ้าไม่มีก็บิลด์แพลตฟอร์มเครื่องนี้กับ `web`
เป้าหมายเดสก์ท็อปจะสร้างและคอมไพล์โปรเจกต์ Rust ขนาดเล็ก จึงต้องติดตั้งชุดเครื่องมือ Rust
และการบิลด์ครั้งแรกอาจใช้เวลาหลายนาที ส่วนเป้าหมาย `web` ใช้โปรแกรม `lingc`

ตัวเลือกทั้งหมดและคีย์ในแมนิเฟสต์ดูได้ที่[คำสั่ง ling](../tools/ling.md)
