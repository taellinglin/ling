# AI และโมเดลภาษา

Ling มีปัญญาประดิษฐ์สามขนาด ทุกตัวทำงานบนเครื่องของคุณเอง ไม่มีข้อมูลใดถูกส่งไปยังบริการภายนอก

| ตระกูล | หน้าที่ | ต้องใช้ |
|---|---|---|
| `nn_*` | โครงข่ายประสาทเทียมแบบป้อนไปข้างหน้าขนาดเล็กที่คุณฝึกในลูป | โปรไฟล์ `ai` |
| `bt_*` | ต้นไม้พฤติกรรมสำหรับตัวละครในเกม | โปรไฟล์ `ai` |
| `dialog_*` (การเรียนรู้) | โมเดลภาษาจิ๋วที่เรียนรู้น้ำเสียงของตัวละคร | โปรไฟล์ `ai` |
| `stt_*` | แปลงเสียงพูดเป็นข้อความด้วย Whisper | โปรไฟล์ `ai` และโมเดล Whisper |
| `llm_*` | แชตกับโมเดล GGUF ในเครื่อง (Qwen3, GLM-4) | ฟีเจอร์เสริม `llm` และไฟล์โมเดล |
| `vision_*` | ถามคำถามเกี่ยวกับภาพ (Moondream2) | ฟีเจอร์เสริม `vision` และไฟล์โมเดล |

การติดตั้งค่าเริ่มต้น (`full`) มีโปรไฟล์ `ai` อยู่แล้ว ส่วน `llm` และ `vision` ไม่อยู่ใน `full`
ต้องติดตั้งแยกเอง เช่น `cargo install ling-lang --features llm` (ใช้ `llm-cuda` สำหรับ GPU ของ NVIDIA)
ในบิลด์ที่ไม่มีฟีเจอร์เหล่านี้ การเรียก `llm_*` และ `vision_*` จะได้ค่า `()`

มีสองสิ่งที่ไม่มีอยู่จริง แม้คุณอาจเห็นชื่อในที่อื่น คือ ไม่มีฟังก์ชันในตัวชื่อ `ai_chat` หรือ `ai_embed`
และไม่มีไคลเอนต์สำหรับ API ของโมเดลที่โฮสต์ภายนอก ถ้าจะเรียกโมเดลระยะไกล ให้ใช้ `http_post_async`
จาก [เว็บเซิร์ฟเวอร์และ HTTP](../reference/web.md) แล้วแยกวิเคราะห์คำตอบเอง

## ข้อตกลง

- **แฮนเดิลเป็นตัวเลข** `nn_new`, `bt_build`, `dialog_new`, `llm_load` และ `vision_load`
  คืนตัวเลขเล็กๆ การโหลดที่ล้มเหลวคืน `-1` แฮนเดิลที่ไม่ถูกต้องเมื่อส่งให้ฟังก์ชันอื่นจะได้ค่ากลาง
  (`[]`, `0`, `""` หรือ `false`) และไม่ทำให้โปรแกรมพัง
- **รายการตัวเลข** เช่น `[0.5, 1]` จะถูกแปลงเป็นทศนิยม 32 บิตภายใน สิ่งที่ไม่ใช่ตัวเลขจะถูกข้าม
- **งานที่ใช้เวลานานต้องวนถาม** `stt_start`, `llm_generate_start` และ `vision_analyze_start`
  คืนรหัสงานทันทีแล้วทำงานบนเธรดเบื้องหลัง ตรวจดูงานในลูปพร้อม `นอน(ms)`

## โครงข่ายประสาทเทียม: `nn_*`

โครงข่ายแบบป้อนไปข้างหน้าที่เชื่อมต่อเต็ม: ระบุจำนวนอินพุต เพิ่มชั้น แล้วเรียก `nn_train`
ครั้งละหนึ่งตัวอย่าง การฝึกใช้ stochastic gradient descent ธรรมดากับค่าความสูญเสียแบบผลต่างกำลังสอง
เบาพอที่จะรันได้ทุกเฟรม ค่าเมล็ดที่ส่งให้ `nn_new` ทำให้ผลลัพธ์ทำซ้ำได้

| ฟังก์ชันในตัว | 中文 | 日本語 | 한국어 | ไทย | หน้าที่ |
|---|---|---|---|---|---|
| `nn_new(n_inputs, seed)` | `建神经网` | `ニューラル作成` | `신경망생성` | `สร้างโครงข่าย` | โครงข่ายว่างที่รับตัวเลข `n_inputs` ตัว |
| `nn_dense(net, units, activation)` | `密集层` | `密層追加` | `밀집층` | `ชั้นหนาแน่น` | เพิ่มชั้นที่เชื่อมต่อเต็ม |
| `nn_forward(net, inputs)` | `神经前向` | `順伝播` | `순전파` | `ส่งต่อโครงข่าย` | รันโครงข่าย คืนรายการ |
| `nn_train(net, inputs, targets, rate)` | `训练网` | `ニューラル学習` | `신경망학습` | `ฝึกโครงข่าย` | ฝึกหนึ่งขั้น คืนค่าความสูญเสีย |
| `nn_save(net, path)` | `保存网` | `網保存` | `신경망저장` | `บันทึกโครงข่าย` | บันทึกในรูปแบบ `LNN1` |
| `nn_load(path)` | `载入网` | `網読込` | `신경망불러오기` | `โหลดโครงข่าย` | โหลดโครงข่ายที่บันทึกไว้ หรือ `-1` |

### การสร้างและการฝึก

- `nn_new(n_inputs, seed)`: ทั้งสองค่ามีค่าเริ่มต้นเป็น 1
- `nn_dense(net, units, activation)`: ฟังก์ชันกระตุ้นได้แก่ `"relu"` (ค่าเริ่มต้น), `"tanh"`,
  `"sigmoid"` หรือค่าอื่นใดสำหรับแบบเชิงเส้น ความกว้างของชั้นสุดท้ายคือขนาดเอาต์พุต
- `nn_forward(net, inputs)`: รายการอินพุตที่สั้นไปจะถูกเติมศูนย์ ที่ยาวไปจะถูกตัด
- `nn_train(net, inputs, targets, rate)`: `rate` มีค่าเริ่มต้น 0.01 คืนค่าความสูญเสียก่อนการปรับ
  วนฝึกกับข้อมูลทั้งชุดหลายๆ รอบ

โครงข่ายนี้เรียนรู้ XOR:

```ling
ผูก เริ่ม = ทำ {
    ผูก โครงข่าย = สร้างโครงข่าย(2, 7)
    ชั้นหนาแน่น(โครงข่าย, 8, "tanh")
    ชั้นหนาแน่น(โครงข่าย, 1, "sigmoid")
    สำหรับ รอบ ใน 0..2000 {
        ฝึกโครงข่าย(โครงข่าย, [0, 0], [0], 0.5)
        ฝึกโครงข่าย(โครงข่าย, [0, 1], [1], 0.5)
        ฝึกโครงข่าย(โครงข่าย, [1, 0], [1], 0.5)
        ฝึกโครงข่าย(โครงข่าย, [1, 1], [0], 0.5)
    }
    พิมพ์(ส่งต่อโครงข่าย(โครงข่าย, [0, 1])[0] > 0.9)
    พิมพ์(ส่งต่อโครงข่าย(โครงข่าย, [1, 1])[0] < 0.1)
}
```

```output
true
true
```

### การบันทึก

`nn_save(net, path)` เขียนไฟล์ขนาดเล็กแบบ little-endian (ค่าเริ่มต้น `"model.lnn"`) และคืน `true`
`nn_load(path)` คืนแฮนเดิลใหม่ หรือ `-1` ถ้าไม่มีไฟล์หรือไฟล์ไม่ถูกต้อง รูปแบบนี้ไม่มีผลรวมตรวจสอบหรือลายเซ็น
จึงไม่ควรโหลดไฟล์ `.lnn` จากแหล่งที่ไม่น่าไว้ใจ

## ต้นไม้พฤติกรรม: `bt_*`

ต้นไม้พฤติกรรมคือชั้นการตัดสินใจของตัวละครในเกม คุณเขียนมันด้วยภาษาข้อความขนาดเล็ก
แล้ว tick มันกับ**กระดานดำ**ที่เก็บข้อเท็จจริงเป็นตัวเลข (พลังชีวิต ระยะทาง กระสุน)
การ tick แต่ละครั้งคืนชื่อของการกระทำที่ถูกเลือก แล้วโปรแกรมของคุณตัดสินว่าจะทำอย่างไร

```text
selector {                  # ลองลูกทีละตัวจนกว่าจะมีตัวที่สำเร็จ
    sequence {              # ลูกทุกตัวต้องสำเร็จ
        ?เห็นศัตรู > 0      # เงื่อนไขของข้อเท็จจริงบนกระดานดำ
        ?กระสุน >= 1
        !โจมตี              # การกระทำ
    }
    !ลาดตระเวน              # ทางเลือกสุดท้าย
}
```

ตัวประกอบได้แก่ `selector`, `sequence`, `parallel` (สำเร็จเมื่อลูกทุกตัวสำเร็จ) และ `not <child>`
เงื่อนไขเขียนเป็น `?key OP value` โดยใช้ `>`, `<`, `>=`, `<=`, `==` และ `!=` คีย์ที่ยังไม่เคยตั้งค่าจะอ่านได้เป็น `0`
คอมเมนต์ขึ้นต้นด้วย `#` ชื่อคีย์และชื่อการกระทำเป็นภาษาไทยได้

| ฟังก์ชันในตัว | 中文 | 日本語 | 한국어 | ไทย | หน้าที่ |
|---|---|---|---|---|---|
| `bt_build(spec)` | `建行为树` | `行動木構築` | `행동트리구성` | `สร้างต้นไม้พฤติกรรม` | คอมไพล์ต้นไม้ หรือ `-1` เมื่อไวยากรณ์ผิด |
| `bt_set(tree, key, value)` | `设事实` | `事実設定` | `사실설정` | `ตั้งข้อเท็จจริง` | ตั้งข้อเท็จจริงบนกระดานดำ |
| `bt_tick(tree)` | `行为树滴答` | `行動木更新` | `행동트리틱` | `เดินต้นไม้พฤติกรรม` | รันหนึ่งครั้ง คืนชื่อการกระทำหรือ `""` |
| `bt_status(tree)` | `行为树状态` | `行動木状態` | `행동트리상태` | `สถานะต้นไม้พฤติกรรม` | ผลล่าสุด: `0` ล้มเหลว `1` สำเร็จ `2` กำลังทำงาน |

```ling
ผูก เริ่ม = ทำ {
    ผูก สมอง = สร้างต้นไม้พฤติกรรม("selector { sequence { ?เห็นศัตรู > 0 ?กระสุน >= 1 !โจมตี } sequence { ?เห็นศัตรู > 0 !หนี } !ลาดตระเวน }")
    พิมพ์(เดินต้นไม้พฤติกรรม(สมอง))
    ตั้งข้อเท็จจริง(สมอง, "เห็นศัตรู", 1)
    ตั้งข้อเท็จจริง(สมอง, "กระสุน", 5)
    พิมพ์(เดินต้นไม้พฤติกรรม(สมอง))
    ตั้งข้อเท็จจริง(สมอง, "กระสุน", 0)
    พิมพ์(เดินต้นไม้พฤติกรรม(สมอง))
}
```

```output
ลาดตระเวน
โจมตี
หนี
```

## การเรียนรู้บทสนทนา: `dialog_*`

ฟังก์ชันเหล่านี้มอบโมเดลภาษาประสาทเทียมขนาดจิ๋วให้ตัวละคร มันเรียนรู้**จังหวะและคำศัพท์**
ของบรรทัดที่คุณใช้ฝึก แล้วเขียนบรรทัดใหม่ด้วยน้ำเสียงนั้น มันเล็กมาก (ไม่กี่กิโลไบต์ ใช้ CPU คอร์เดียว)
และจะพูดวลีจากคลังข้อความขนาดเล็กซ้ำ ส่วนกล่องบทสนทนาตระกูล `dialog_show` เป็นอีกฟีเจอร์หนึ่งในโปรไฟล์ game

ป้อนข้อความทีละบรรทัดด้วย `dialog_learn` หรือป้อนทั้งไฟล์ในรูปแบบ Ling Dialog (`.lingdialog`)
ซึ่ง `= label` เริ่มบทสนทนา และ `speaker: text` คือหนึ่งการพูด:

```text
= ต้อนรับ
แบรม: ยินดีต้อนรับ นักเดินทาง พักเท้า ก่อน
ฮีโร่: มี ข่าว อะไร จาก ถนน บ้าง
แบรม: มี โจร ที่ ช่องเขา ทาง เหนือ
```

ระบบใช้เฉพาะข้อความของแต่ละการพูดในการฝึก ข้อความจะถูกแปลงเป็นตัวพิมพ์เล็กและแยกเป็นคำ
(แยกด้วยช่องว่าง จึงควรเว้นวรรคระหว่างคำภาษาไทย)

| ฟังก์ชันในตัว | 中文 | 日本語 | 한국어 | ไทย | หน้าที่ |
|---|---|---|---|---|---|
| `dialog_new(context, embed, hidden, seed)` | `建对话模型` | `対話モデル作成` | `대화모델생성` | `สร้างโมเดลสนทนา` | โมเดลที่ยังไม่ฝึก (ค่าเริ่มต้น 3, 32, 64, 1) |
| `dialog_learn(model, text)` | `对话学习` | `対話学習` | `대화학습` | `เรียนรู้สนทนา` | เพิ่มข้อความฝึกหนึ่งบรรทัด |
| `dialog_load(model, path)` | `对话载入` | `対話読込` | `대화불러오기` | `โหลดชุดสนทนา` | เพิ่มไฟล์ `.lingdialog` คืนจำนวนบทสนทนาที่เพิ่ม |
| `dialog_train(model, epochs, rate)` | `对话训练` | `対話訓練` | `대화훈련` | `ฝึกสนทนา` | ฝึก (ค่าเริ่มต้น 20, 0.1) คืนค่าความสูญเสียสุดท้าย |
| `dialog_say(model, prompt, max_tokens, temperature)` | `对话生成` | `対話生成` | `대화생성` | `พูดสนทนา` | สร้างหนึ่งบรรทัด (ค่าเริ่มต้น 24, 0.8) |
| `dialog_save(model, path)` | `对话存模` | `対話モデル保存` | `대화모델저장` | `บันทึกโมเดลสนทนา` | บันทึกโมเดลที่ฝึกแล้ว |
| `dialog_load_model(path)` | `对话载模` | `対話モデル読込` | `대화모델불러오기` | `โหลดโมเดลสนทนา` | โหลดโมเดลที่บันทึกไว้ หรือ `-1` |

`context` คือจำนวนคำก่อนหน้าที่โมเดลมองเห็น `temperature` ที่เป็น `0` หรือน้อยกว่าจะเลือกคำที่น่าจะเป็นที่สุดเสมอ
ค่าที่สูงขึ้นจะหลากหลายขึ้น ด้วยเมล็ด คลังข้อความ และอาร์กิวเมนต์ชุดเดียวกัน ผลลัพธ์จะเหมือนเดิมทุกครั้ง
ถ้าเพิ่มข้อความหลังจากฝึกแล้ว ให้ฝึกใหม่

```ling
ผูก เริ่ม = ทำ {
    ผูก ตัวละคร = สร้างโมเดลสนทนา(3, 16, 32, 1)
    เรียนรู้สนทนา(ตัวละคร, "ยินดีต้อนรับ นักเดินทาง พักเท้า ข้าง กองไฟ ก่อน")
    เรียนรู้สนทนา(ตัวละคร, "ลับ ดาบ ให้ คม และ เก็บ ถุงเงิน ให้ ดี นักเดินทาง")
    พิมพ์(ฝึกสนทนา(ตัวละคร, 40, 0.1) < 2)
    พิมพ์(ความยาว(พูดสนทนา(ตัวละคร, "ยินดีต้อนรับ นักเดินทาง", 8, 0.7)) > 0)
}
```

```output
true
true
```

## แปลงเสียงพูดเป็นข้อความ: `stt_*`

`stt_*` ถอดความไฟล์เสียงด้วย Whisper บนเครื่องของคุณ มันใช้เอนจิน Whisper ในตัวเมื่อมีฟีเจอร์ `llm`
และติดตั้งโมเดลไว้แล้ว ไม่เช่นนั้นจะรัน [faster-whisper](https://github.com/SYSTRAN/faster-whisper) ผ่าน Python
ตั้งค่าเส้นทาง Python เพียงครั้งเดียว:

```sh
python -m venv venv
venv/bin/pip install faster-whisper
huggingface-cli download Systran/faster-whisper-small
```

ตั้ง `LING_STT_PYTHON` ให้ชี้ไปที่ Python ตัวนั้น หรือสร้าง venv ในโฟลเดอร์เริ่มต้นของ Ling
(`%LOCALAPPDATA%\LingStation\stt\venv` บน Windows และ `~/.local/share/lingstation/stt/venv` บนระบบอื่น)
โมเดลถูกอ่านจากแคช Hugging Face ในเครื่อง ไม่มีการใช้เครือข่าย

| ฟังก์ชันในตัว | หน้าที่ |
|---|---|
| `stt_available()` | `true` ถ้ามีเอนจิน Whisper ที่รันได้ |
| `stt_models()` | โมเดลที่ติดตั้งไว้ เป็นรายการแบน `[name, size_mb, ...]` |
| `stt_start(audio, model, lang, words)` | เริ่มงาน คืนรหัสงาน หรือ `""` ถ้าเริ่มไม่ได้ |
| `stt_poll(job)` | ความคืบหน้าตั้งแต่ 0 ถึง 1 |
| `stt_done(job)` | `true` เมื่องานเสร็จ |
| `stt_error(job)` | `""` หรือสาเหตุที่งานล้มเหลว |
| `stt_info(job)` | ข้อความสถานะ เช่น `"loaded small on cuda"` |
| `stt_language(job)` | รหัสภาษาที่ตรวจพบ |
| `stt_segments(job)` | `[start, end, text, ...]` ของช่วงที่ได้จนถึงตอนนี้ |
| `stt_words(job)` | `[start, end, word, probability, ...]` ของคำที่ได้จนถึงตอนนี้ |
| `stt_srt(job, max_chars)` | ซับไตเติล SubRip แต่ละคิวยาวไม่เกิน `max_chars` ตัวอักษร (ค่าเริ่มต้น 42, `0` = ทั้งช่วง) |
| `stt_align(job, lyrics)` | จับเวลาแต่ละบรรทัดของข้อความที่วางไว้กับสิ่งที่ได้ยิน: `[start, end, line, ...]` |
| `stt_align_srt(job, lyrics)` | แบบเดียวกัน ในรูปซับไตเติล SubRip |
| `stt_cancel(job)` | หยุดงาน |

ไม่มีตัวใดมีชื่อแปลตามภาษา `stt_start` รับชื่อโมเดล (ค่าเริ่มต้น `"small"`) ภาษา (ค่าเริ่มต้น `"auto"`
หรือรหัสเช่น `"en"` หรือ `"th"`) และจะบันทึกเวลาของแต่ละคำหรือไม่ (ค่าเริ่มต้น `true`) เวลาทั้งหมดเป็นวินาที

```ling-gui
ผูก เริ่ม = ทำ {
    ถ้า !stt_available() {
        พิมพ์("ไม่ได้ติดตั้งเอนจิน Whisper")
    } มิฉะนั้น {
        ผูก งาน = stt_start("interview.wav", "small", "auto", จริง)
        ขณะที่ !stt_done(งาน) {
            พิมพ์(stt_poll(งาน))
            นอน(500)
        }
        ถ้า stt_error(งาน) == "" {
            พิมพ์(stt_language(งาน))
            write_file("interview.srt", stt_srt(งาน, 42))
        }
    }
}
```

## โมเดลภาษาในเครื่อง: `llm_*`

`llm_*` รันโมเดลแชตภายในโปรเซส `ling` มันโหลดไฟล์ **GGUF** ที่ถูกควอนไทซ์ พร้อม `tokenizer.json`
บน CPU หรือ GPU ของ CUDA สถาปัตยกรรมที่รองรับคือ `qwen3` และ `glm4` ต้องใช้ฟีเจอร์เสริม `llm`
(`llm-cuda` สำหรับ GPU)

การสร้างข้อความไม่เคยบล็อกโปรแกรมของคุณ `llm_generate_start` คืนรหัสงานทันที แล้วคุณวนถาม
`llm_generate_poll` เพื่อดูข้อความที่ได้จนถึงตอนนั้น เรื่องนี้สำคัญที่สุดในตัวจัดการเว็บ
ซึ่งการสร้างข้อความนานๆ จะทำให้ผู้เข้าชมทุกคนต้องรอ

ประวัติการสนทนาเป็นสตริงเดียวในรูปแบบนี้ และต้องจบด้วยการพูดของผู้ใช้:

```text
<|user|>
เลนส์คืออะไร
<|assistant|>
แก้วโค้งที่หักเหแสง
<|user|>
แล้วกระจกเงาล่ะ
```

| ฟังก์ชันในตัว | หน้าที่ |
|---|---|
| `llm_load(gguf_path, tokenizer_path, device)` | โหลดโมเดล `device` ติดลบสำหรับ CPU นอกนั้นคือหมายเลข CUDA คืนแฮนเดิลหรือ `-1` |
| `llm_generate_start(model, system_prompt, history, max_tokens, temperature, top_p)` | เริ่มสร้างคำตอบ (ค่าเริ่มต้น 512, 0.7, 0.9) คืนรหัสงาน |
| `llm_generate_poll(job)` | ข้อความที่สร้างได้จนถึงตอนนี้ |
| `llm_generate_done(job)` | `true` เมื่อเสร็จ |
| `llm_job_status(job)` | `"pending"` หรือ `"done"` |
| `llm_job_cancel(job)` | ทำเครื่องหมายว่างานเสร็จ (ดูหมายเหตุ) |
| `llm_job_tool_name(job)`, `llm_job_provide_tool_result(job, text)` | สงวนไว้สำหรับการเรียกเครื่องมือ ยังไม่ได้สร้าง |

ไม่มีตัวใดมีชื่อแปลตามภาษา

```ling-gui
ผูก เริ่ม = ทำ {
    ผูก โมเดล = llm_load("models/Qwen3-0.6B-Q8_0.gguf", "models/tokenizer.json", 0 - 1)
    ถ้า โมเดล < 0 {
        พิมพ์("โหลดโมเดลไม่ได้")
    } มิฉะนั้น {
        ผูก งาน = llm_generate_start(โมเดล, "ตอบในประโยคเดียว", "<|user|>\nทำไมท้องฟ้าจึงเป็นสีฟ้า\n", 128, 0.7, 0.9)
        ขณะที่ !llm_generate_done(งาน) {
            นอน(250)
        }
        พิมพ์(llm_generate_poll(งาน))
    }
}
```

หมายเหตุ:

- การโหลดจะอ่านโมเดลทั้งหมดเข้าหน่วยความจำและอาจใช้เวลาหลายวินาที ให้โหลดครั้งเดียวตอนเริ่มโปรแกรม
- โมเดลหนึ่งตัวสร้างข้อความได้ทีละงาน
- `llm_job_cancel` เพียงทำเครื่องหมายว่างานเสร็จ การสร้างข้อความยังทำงานต่อเบื้องหลังจนถึง `max_tokens`
  จึงควรตั้ง `max_tokens` ให้พอเหมาะ
- ไม่มีชั้นกลั่นกรองเนื้อหา กรองเอาต์พุตก่อนแสดงให้ผู้ใช้ที่ไม่น่าไว้ใจ และห้ามส่งเอาต์พุตของโมเดล
  ไปยังไฟล์ SQL หรือคำสั่งโดยตรง

## การเข้าใจภาพ: `vision_*`

`vision_*` ตอบคำถามเกี่ยวกับภาพด้วยโมเดล **Moondream2** ที่ถูกควอนไทซ์ ทำงานเหมือน `llm_*`
คือโหลดครั้งเดียวแล้ววนถามงานเบื้องหลัง ต้องใช้ฟีเจอร์เสริม `vision` (ซึ่งรวม `llm`)
มันไม่ได้ทำการรู้จำตัวอักษร (OCR)

| ฟังก์ชันในตัว | หน้าที่ |
|---|---|
| `vision_load(gguf_path, tokenizer_path, device)` | โหลดโมเดล คืนแฮนเดิลหรือ `-1` |
| `vision_analyze_start(model, image_base64, question, max_tokens, temperature, top_p)` | เริ่มงาน (ค่าเริ่มต้น `"Describe this image."`, 256, 0.7, 0.9) |
| `vision_analyze_poll(job)` | ข้อความที่ได้จนถึงตอนนี้ |
| `vision_analyze_done(job)` | `true` เมื่อเสร็จ ไม่ว่าจะสำเร็จหรือไม่ |
| `vision_analyze_error(job)` | `""` หรือสาเหตุที่ล้มเหลว |

ภาพต้องส่งเป็น**สตริง base64** ของไบต์ PNG หรือ JPEG เพราะสตริงของ Ling เก็บไบต์ดิบไม่ได้
จากหน้าเว็บ ให้ POST ผลของ `canvas.toDataURL()` แล้วตัดคำนำหน้า `data:image/png;base64,` ออก

```ling-gui
ผูก เริ่ม = ทำ {
    ผูก โมเดล = vision_load("models/moondream2-q4.gguf", "models/moondream-tokenizer.json", 0 - 1)
    ผูก งาน = vision_analyze_start(โมเดล, read_file("shot.b64"), "บนหน้าจอมีอะไร", 128, 0.2, 0.9)
    ขณะที่ !vision_analyze_done(งาน) {
        นอน(250)
    }
    ถ้า vision_analyze_error(งาน) == "" {
        พิมพ์(vision_analyze_poll(งาน))
    }
}
```
