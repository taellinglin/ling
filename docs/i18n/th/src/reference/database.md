# ฐานข้อมูล (SQLite)

Ling มี SQLite ในตัว ฟังก์ชันในตัวสามตัวก็ครอบคลุมทุกอย่าง `db_open` เปิดไฟล์ฐานข้อมูล
`db_exec` เปลี่ยนข้อมูลหรือโครงสร้างตาราง และ `db_query` อ่านแถวกลับมาเป็นเรคคอร์ด
SQLite ถูกรวมไว้ใน `ling` แล้ว จึงไม่ต้องติดตั้งอะไรเพิ่มและไม่ต้องรันเซิร์ฟเวอร์ฐานข้อมูล
ฐานข้อมูลเป็นแค่ไฟล์ธรรมดาหนึ่งไฟล์ที่วางอยู่ข้างโปรแกรมของคุณ

ฟังก์ชันในตัวเหล่านี้อยู่ในโปรไฟล์การติดตั้ง `web` (และ `full` ซึ่งเป็นค่าเริ่มต้น)
เพราะมักใช้คู่กับ[เว็บเซิร์ฟเวอร์](../reference/web.md) แต่ในเครื่องมือบรรทัดคำสั่งก็ใช้ได้ดีเหมือนกัน

## สรุป

| Builtin | 中文 | 日本語 | 한국어 | ไทย | Purpose |
|---|---|---|---|---|---|
| `db_open(path)` | — | — | — | `ฐานข้อมูลเปิด` | เปิดหรือสร้างฐานข้อมูล แล้วตั้งเป็นการเชื่อมต่อปัจจุบัน |
| `db_exec(sql, params...)` | — | — | — | `ฐานข้อมูลรัน` | รันคำสั่งหนึ่งคำสั่งที่เปลี่ยนข้อมูลหรือโครงสร้าง คืนจำนวนแถวที่ได้รับผล |
| `db_query(sql, params...)` | — | — | — | `ฐานข้อมูลถาม` | รันคิวรี คืนรายการเรคคอร์ด `Row` |

## ฐานข้อมูลแรก

```ling
ผูก เริ่ม = ทำ {
  ฐานข้อมูลเปิด(":memory:")
  ฐานข้อมูลรัน("CREATE TABLE บันทึก(รหัส INTEGER PRIMARY KEY AUTOINCREMENT, หัวข้อ TEXT NOT NULL, ดาว REAL, หมายเหตุ TEXT)")
  ฐานข้อมูลรัน("INSERT INTO บันทึก(หัวข้อ, ดาว) VALUES (?1, ?2)", "รายการแรก", 4.5)
  ฐานข้อมูลรัน("INSERT INTO บันทึก(หัวข้อ, ดาว) VALUES (?1, ?2)", "ปลอดภัยดี", 3)
  ผูก แถวทั้งหมด = ฐานข้อมูลถาม("SELECT รหัส, หัวข้อ, ดาว, หมายเหตุ FROM บันทึก ORDER BY รหัส")
  พิมพ์(ความยาว(แถวทั้งหมด))
  พิมพ์(แถวทั้งหมด[0])
  สำหรับ แถว ใน แถวทั้งหมด {
    พิมพ์(str(แถว.รหัส) + ": " + แถว.หัวข้อ)
  }
  พิมพ์("[" + แถวทั้งหมด[1].หมายเหตุ + "]")
}
```

```output
2
Row { รหัส: 1, หัวข้อ: รายการแรก, ดาว: 4.5, หมายเหตุ:  }
1: รายการแรก
2: ปลอดภัยดี
[]
```

SQLite ยอมให้ตั้งชื่อตารางและชื่อคอลัมน์เป็นภาษาไทยได้ ชื่อฟิลด์ของเรคคอร์ดจึงเป็นภาษาไทยได้ด้วย
`":memory:"` สร้างฐานข้อมูลที่มีอยู่เฉพาะตอนโปรแกรมทำงาน เหมาะกับการทดสอบและตัวอย่าง
ถ้าต้องการเก็บข้อมูลไว้ ให้ใช้ชื่อไฟล์อย่าง `"app.db"`

## `db_open(path)`

เปิดฐานข้อมูล SQLite ที่ `path` (ค่าเริ่มต้น `"app.db"`) และสร้างไฟล์ให้ถ้ายังไม่มี
แล้วตั้งเป็นการเชื่อมต่อปัจจุบันของอินเทอร์พรีเตอร์ ไม่คืนค่าใด

- ตอนเปิด Ling จะเปิดใช้คีย์นอก (`PRAGMA foreign_keys = ON`) การบันทึกล่วงหน้า
  (`journal_mode = WAL`) และเวลารอเมื่อไม่ว่าง 5 วินาที การเขียนที่ชนกับการเขียนอื่นจึงรอคิว
  แทนที่จะล้มเหลวด้วย "database is locked"
- อินเทอร์พรีเตอร์แต่ละตัวถือการเชื่อมต่อได้ **หนึ่ง** การเชื่อมต่อ เรียก `db_open` อีกครั้งจะแทนที่ของเดิม
- เมื่อใช้ WAL ระหว่างที่ฐานข้อมูลเปิดอยู่ SQLite จะเก็บไฟล์ช่วยสองไฟล์ไว้ข้างๆ
  (`app.db-wal` และ `app.db-shm`) ให้สำรองทั้งสามไฟล์พร้อมกัน หรือคัดลอกตอนที่ไม่มีโปรแกรมใดเปิดอยู่
- ถ้าเปิดไฟล์ไม่ได้ `db_open` จะแจ้งข้อผิดพลาด

## `db_exec(sql, params...)`

รันคำสั่ง SQL **หนึ่ง** คำสั่งที่ไม่คืนแถว เช่น `CREATE` `INSERT` `UPDATE` `DELETE`
`BEGIN` `COMMIT` คืนจำนวนแถวที่เปลี่ยน (คำสั่งโครงสร้างคืน `0`)

- ใส่คำสั่งเดียวต่อการเรียกหนึ่งครั้ง สองคำสั่งที่คั่นด้วย `;` ถือเป็นข้อผิดพลาด
- เมื่อล้มเหลวจะแจ้งข้อผิดพลาดที่มีข้อความ SQL อยู่ด้วย การเรียกก่อน `db_open` ก็เป็นข้อผิดพลาดเช่นกัน

## `db_query(sql, params...)`

รันคิวรีและคืนแถว **ทั้งหมด** เป็นรายการเรคคอร์ด `Row` อ่านคอลัมน์ด้วยจุด เช่น `แถว.หัวข้อ`
ชื่อฟิลด์คือชื่อคอลัมน์ใน `SELECT` ดังนั้นคอลัมน์ที่คำนวณขึ้นควรตั้งชื่อด้วย `AS`

```ling
ผูก เริ่ม = ทำ {
  ฐานข้อมูลเปิด(":memory:")
  ฐานข้อมูลรัน("CREATE TABLE ปูม(เลข INTEGER)")
  ฐานข้อมูลรัน("BEGIN")
  ผูก i = 0
  ขณะที่ i < 1000 {
    ฐานข้อมูลรัน("INSERT INTO ปูม(เลข) VALUES (?1)", i)
    ผูก i = i + 1
  }
  ฐานข้อมูลรัน("COMMIT")
  ผูก ผล = ฐานข้อมูลถาม("SELECT count(*) AS จำนวน, sum(เลข) AS ผลรวม, avg(เลข) AS ค่าเฉลี่ย FROM ปูม")[0]
  พิมพ์(ผล.จำนวน)
  พิมพ์(ผล.ผลรวม)
  พิมพ์(ผล.ค่าเฉลี่ย)
}
```

```output
1000
499500
499.5
```

การครอบการแทรกจำนวนมากด้วย `BEGIN` และ `COMMIT` ทำให้กลายเป็นธุรกรรมเดียว
ซึ่งเร็วกว่าการคอมมิตทีละแถวมาก

### ค่าที่ได้กลับมา

| ค่าใน SQLite | ค่าใน Ling |
|---|---|
| `INTEGER` | ตัวเลข |
| `REAL` | ตัวเลข |
| `TEXT` | ข้อความ |
| `NULL` | `""` (ข้อความว่าง) |
| `BLOB` | ข้อความ base64 |

คิวรีที่ไม่พบแถวที่ตรงจะคืนรายการว่าง ดังนั้นให้ตรวจ `ความยาว(แถวทั้งหมด)` ก่อนอ่าน `แถวทั้งหมด[0]`

## พารามิเตอร์

พารามิเตอร์ผูกกับ `?1` `?2` `?3` ไปเรื่อยๆ **ตามตำแหน่ง** ตามลำดับที่คุณส่งต่อท้าย SQL
ให้ส่งข้อมูลจากผู้ใช้เป็นพารามิเตอร์เสมอ ห้ามต่อเข้าไปในข้อความ SQL พารามิเตอร์เป็นแค่ค่าเสมอ
จึงเปลี่ยนตัวคำสั่งไม่ได้

```ling
ผูก เริ่ม = ทำ {
  ฐานข้อมูลเปิด(":memory:")
  ฐานข้อมูลรัน("CREATE TABLE ผู้ใช้(รหัส INTEGER PRIMARY KEY, ชื่อ TEXT UNIQUE, ผู้ดูแล INTEGER)")
  ผูก ชื่อ = "Robert'); DROP TABLE ผู้ใช้; --"
  ฐานข้อมูลรัน("INSERT INTO ผู้ใช้(ชื่อ, ผู้ดูแล) VALUES (?1, ?2)", ชื่อ, เท็จ)
  ฐานข้อมูลรัน("INSERT INTO ผู้ใช้(ชื่อ, ผู้ดูแล) VALUES (?1, ?2)", "เอดา", จริง)
  พิมพ์(ฐานข้อมูลถาม("SELECT count(*) AS จำนวนคน FROM ผู้ใช้")[0].จำนวนคน)
  พิมพ์(ฐานข้อมูลถาม("SELECT ชื่อ FROM ผู้ใช้ WHERE ผู้ดูแล = ?1", จริง)[0].ชื่อ)
  พิมพ์(ฐานข้อมูลถาม("SELECT last_insert_rowid() AS รหัส")[0].รหัส)
  พิมพ์(ฐานข้อมูลรัน("UPDATE ผู้ใช้ SET ผู้ดูแล = 0 WHERE ชื่อ = ?1", "เอดา"))
  พิมพ์(ฐานข้อมูลรัน("DELETE FROM ผู้ใช้ WHERE รหัส > ?1", 100))
}
```

```output
2
เอดา
2
1
0
```

ค่าใน Ling ผูกเป็นชนิดใด

| ค่าใน Ling | ผูกเป็น |
|---|---|
| จำนวนเต็ม (`3`) | `INTEGER` |
| ทศนิยม (`4.5`) | `REAL` |
| `จริง` / `เท็จ` | `1` / `0` |
| ค่าอื่นๆ | `TEXT` (ค่านั้นในรูปข้อความ) |

ถ้าต้องการ id ของแถวที่เพิ่งแทรก ให้คิวรี `SELECT last_insert_rowid() AS รหัส`
บนการเชื่อมต่อเดียวกัน เหมือนตัวอย่างข้างบน

## ข้อผิดพลาด

คำสั่งที่ล้มเหลว (ไวยากรณ์ผิด ไม่มีตาราง หรือผิดข้อกำหนด `UNIQUE`) จะเกิดข้อผิดพลาดขณะรัน
ซึ่งข้อความขึ้นต้นด้วย `db_exec:` หรือ `db_query:` และแสดง SQL

บนอินเทอร์พรีเตอร์ (`ling run --interp` และโปรแกรมที่เรียก `http_serve` ซึ่งรันบนอินเทอร์พรีเตอร์เสมอ)
ข้อผิดพลาดจะหยุดโปรแกรม หรือคืนกลับมาเป็น `ผิด` เมื่ออยู่ใน `ลอง` ส่วนแบ็กเอนด์ JIT ที่เป็นค่าเริ่มต้นของ
`ling run` ตอนนี้จะข้ามคำสั่งที่ล้มเหลวไปเงียบๆ โดยไม่มีข้อความ ระหว่างพัฒนาสคริปต์ฐานข้อมูลจึงควรรันด้วย `--interp`

```ling-module
ฟังก์ชัน เพิ่มผู้ใช้(ชื่อ) {
  คืน ฐานข้อมูลรัน("INSERT INTO ผู้ใช้(ชื่อ) VALUES (?1)", ชื่อ)
}

ฟังก์ชัน ลองเพิ่ม(ชื่อ) {
  จับคู่ ลอง(| | เพิ่มผู้ใช้(ชื่อ)) {
    โอเค(n) => คืน "เพิ่มแล้ว"
    ผิด(e) => คืน "เพิ่ม " + ชื่อ + " ไม่ได้: " + e
  }
}
```

## ใช้กับเว็บเซิร์ฟเวอร์

รูปแบบที่พบบ่อยคือ เปิดฐานข้อมูลใน `เริ่ม` สร้างตารางถ้ายังไม่มี ลงทะเบียนเส้นทาง แล้วเริ่มให้บริการ
ตัวจัดการเรียก `db_query` และ `db_exec` ได้โดยตรง

```ling-gui
โครงสร้าง คำตอบ { status, content_type, body, set_cookie, location }

ฟังก์ชัน รายการบันทึก(คำขอ) {
  ผูก แถวทั้งหมด = ฐานข้อมูลถาม("SELECT รหัส, หัวข้อ FROM บันทึก ORDER BY รหัส DESC LIMIT 50")
  ผูก ผลลัพธ์ = "<ul>"
  สำหรับ แถว ใน แถวทั้งหมด {
    ผูก ผลลัพธ์ = ผลลัพธ์ + "<li>" + กันเอชทีเอ็มแอล(แถว.หัวข้อ) + "</li>"
  }
  คืน ผลลัพธ์ + "</ul>"
}

ฟังก์ชัน เพิ่มบันทึก(คำขอ) {
  ผูก หัวข้อ = พารามิเตอร์(คำขอ.body, "title", "")
  ถ้า หัวข้อ == "" {
    คืน คำตอบ(400, "text/plain; charset=utf-8", "ต้องใส่หัวข้อ", "", "")
  }
  ฐานข้อมูลรัน("INSERT INTO บันทึก(หัวข้อ) VALUES (?1)", หัวข้อ)
  คืน คำตอบ(303, "text/plain", "", "", "/")
}

ผูก เริ่ม = ทำ {
  ฐานข้อมูลเปิด("notes.db")
  ฐานข้อมูลรัน("CREATE TABLE IF NOT EXISTS บันทึก(รหัส INTEGER PRIMARY KEY AUTOINCREMENT, หัวข้อ TEXT NOT NULL)")
  เว็บเส้นทาง("GET", "/", รายการบันทึก)
  เว็บเส้นทาง("POST", "/add", เพิ่มบันทึก)
  เว็บเสิร์ฟ("127.0.0.1", 8080, 4)
}
```

ชื่อฟิลด์ของเรคคอร์ดคำตอบ (`status` `content_type` `body` `set_cookie` `location`)
และชื่อฟิลด์ของคำขอ (`body` `query` และอื่นๆ) ต้องเป็นภาษาอังกฤษตามเดิม เพราะเซิร์ฟเวอร์ใช้ชื่อเหล่านี้ในการจดจำ
ส่วนชื่อของเรคคอร์ดเอง (ในที่นี้คือ `คำตอบ`) ตั้งได้ตามใจ

### เวิร์กเกอร์และการเชื่อมต่อ

เมื่อใช้ `http_serve(host, port, 1)` (ค่าเริ่มต้น) อินเทอร์พรีเตอร์ตัวเดียวจะตอบทุกคำขอทีละรายการ
ผ่านการเชื่อมต่อเดียวของมัน

เมื่อ `workers` มากกว่า 1 เวิร์กเกอร์ที่เพิ่มขึ้นแต่ละตัวเป็นอินเทอร์พรีเตอร์แยกกัน และมี **การเชื่อมต่อของตัวเอง**
ไปยังพาธที่คุณส่งให้ `db_open` การอ่านทำงานคู่ขนานกันได้ ส่วนการเขียนยังคงทำทีละรายการ
WAL กับเวลารอเมื่อไม่ว่างทำให้การเขียนต่อคิวแทนที่จะล้มเหลว จึงมีสองเรื่องที่ตามมา

- เรียก `db_open` ใน `เริ่ม` **ก่อน** `http_serve` เวิร์กเกอร์จะเปิดพาธที่เป็นปัจจุบันตอนเซิร์ฟเวอร์เริ่มทำงาน
- อย่าใช้ `":memory:"` กับเวิร์กเกอร์ เพราะเวิร์กเกอร์แต่ละตัวจะได้ฐานข้อมูลในหน่วยความจำที่แยกกันและว่างเปล่า

ทำธุรกรรมในตัวจัดการให้สั้น `BEGIN` ที่ไม่มี `COMMIT` ในตัวจัดการเดียวกันจะถือล็อกการเขียนไว้
และทำให้การเขียนอื่นทั้งหมดต้องรอ
