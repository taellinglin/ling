# เครือข่าย

นอกจาก HTTP แล้ว Ling มีฟังก์ชันเครือข่ายอีกสี่ตระกูล เลือกตามสิ่งที่คุณกำลังสร้าง:

| สิ่งที่ต้องการ | ใช้ | ความปลอดภัย |
|---|---|---|
| ล็อบบี้เกมหรือเครื่องมือใน LAN | `net_*` | ข้อความธรรมดา ไม่มีการยืนยันตัวตน ใช้ใน LAN ที่ไว้ใจได้เท่านั้น |
| สั่งงานบนเซิร์ฟเวอร์ หรือรับไคลเอนต์ SSH | `ssh_*` | SSH-2 ตรึงกุญแจโฮสต์ ล็อกอินด้วยรหัสผ่าน |
| บริการแบบคำขอ/คำตอบที่เป็นส่วนตัว | `lingtp_*` | แฮนด์เชกหลังควอนตัม ตรึงกุญแจโฮสต์ |
| เครือข่ายเพียร์ทูเพียร์ของโหนดที่มีตัวตน | `p2p_*` | หลังควอนตัม ยืนยันตัวตน เฟรมถูกเติมขนาด |

สำหรับ HTTP และ HTTPS ดู [เว็บเซิร์ฟเวอร์และ HTTP](../reference/web.md) `net_*` มีอยู่ในทุกการติดตั้ง
ส่วน `ssh_*`, `lingtp_*` และ `p2p_*` ต้องใช้โปรไฟล์ `privacy` (รวมอยู่ในการติดตั้งค่าเริ่มต้น `full`)

ฟังก์ชันในตัวทั้งหมดนี้ทำงานแบบรอหรือแบบวนถาม ไม่มีตัวใดรับคอลแบ็ก คุณเขียนลูปที่ตรวจดูงาน
แล้วเรียก `นอน(ms)` ระหว่างการตรวจแต่ละครั้ง ความล้มเหลวในการผูกพอร์ตหรือเชื่อมต่อจะแสดงเป็นตัวเลขสถานะ
ไม่ใช่ข้อผิดพลาด จึงต้องตรวจสถานะเสมอ

## ล็อบบี้ใน LAN: `net_*`

`net_*` เป็นช่องทางส่งข้อมูลขนาดเล็กที่ไว้ใจได้สำหรับสถานะเกม โปรเซสหนึ่งเป็นได้อย่างใดอย่างหนึ่ง คือ
**โฮสต์**ที่รับไคลเอนต์ได้สูงสุด 64 ตัว หรือ**ไคลเอนต์**ที่เชื่อมต่อกับโฮสต์หนึ่งตัว แต่ละข้อความคือข้อความ
UTF-8 หนึ่งบรรทัด ซ็อกเก็ตทำงานบนเธรดเบื้องหลัง ลูปเกมจึงไม่ถูกบล็อก `net_send` ใส่บรรทัดเข้าคิว
และ `net_recv` ดึงออกมาทีละบรรทัด

| ฟังก์ชันในตัว | 中文 | 日本語 | 한국어 | ไทย | หน้าที่ |
|---|---|---|---|---|---|
| `net_host(port)` | — | — | — | `เน็ตโฮสต์` | รอรับบนพอร์ต TCP (ค่าเริ่มต้น 7777) และเป็นโฮสต์ |
| `net_join(ip, port)` | — | — | — | `เน็ตจอย` | เชื่อมต่อกับโฮสต์และเป็นไคลเอนต์ |
| `net_send(text)` | — | — | — | `เน็ตส่ง` | ส่งหนึ่งบรรทัด: โฮสต์ส่งถึงทุกไคลเอนต์ ไคลเอนต์ส่งถึงโฮสต์ |
| `net_send_to(id, text)` | — | — | — | — | เฉพาะโฮสต์: ส่งหนึ่งบรรทัดถึงไคลเอนต์ตัวเดียว |
| `net_recv()` | — | — | — | `เน็ตรับ` | ข้อความเก่าสุดในคิว หรือ `""` |
| `net_recv_from()` | — | — | — | — | แบบเดียวกัน ในรูป `"id\|text"` |
| `net_clients()` | — | — | — | — | โฮสต์: รหัสไคลเอนต์ เช่น `"1,2"` |
| `net_client_count()` | — | — | — | — | จำนวนเพียร์ที่เชื่อมต่ออยู่ |
| `net_events()` | — | — | — | — | ดึงบรรทัด `connect:<id>` / `disconnect:<id>` ออกทั้งหมด |
| `net_status()` | — | — | — | `เน็ตสถานะ` | `0` ว่างหรือล้มเหลว `1` กำลังรอ `2` เชื่อมต่อแล้ว |
| `net_close()` | — | — | `연결종료` | — | ปิดโฮสต์หรือไคลเอนต์ |
| `net_announce(port, info)` | — | — | — | `เน็ตประกาศ` | โฮสต์: กระจายคำอธิบายล็อบบี้ใน LAN |
| `net_announce_stop()` | — | — | — | `เน็ตหยุดประกาศ` | หยุดกระจาย |
| `net_discover(port)` | — | — | — | `เน็ตค้นหา` | ไคลเอนต์: โฮสต์ที่ได้ยินใน 5 วินาทีล่าสุด |
| `net_test(port)` | — | — | — | `เน็ตทดสอบ` | รายงานว่าผูกพอร์ตได้หรือไม่ และที่อยู่ใน LAN |
| `net_local_ip()` | — | — | — | — | ที่อยู่ LAN ของเครื่องนี้ หรือ `""` เมื่อออฟไลน์ |
| `net_upnp_map(port, description)` | — | — | — | — | ขอให้เราเตอร์ส่งต่อพอร์ต TCP (ทำงานเบื้องหลัง) |
| `net_upnp_poll()` | — | — | — | — | ผลของ `net_upnp_map` |
| `net_upnp_unmap()` | — | — | — | — | ยกเลิกการส่งต่อพอร์ต |

### การเป็นโฮสต์และการเข้าร่วม

`net_host(port)` และ `net_join(ip, port)` ไม่คืนค่าใด ให้ดูที่ `net_status()` ฝั่งโฮสต์ `1` หมายถึงรอไคลเอนต์
และ `2` หมายถึงมีไคลเอนต์เชื่อมต่ออย่างน้อยหนึ่งตัว ฝั่งไคลเอนต์ `1` หมายถึงกำลังเชื่อมต่อ และ `2` หมายถึงเชื่อมต่อแล้ว
ถ้าผูกพอร์ตไม่ได้หรือเชื่อมต่อล้มเหลว สถานะจะกลับเป็น `0` หนึ่งโปรเซสมีได้หนึ่งบทบาท
การเรียก `net_host` หรือ `net_join` อีกครั้งจะแทนที่บทบาทเดิม

```ling-gui
# host.ling
ผูก เริ่ม = ทำ {
    net_host(17777)
    ผูก รอบ = 0
    ขณะที่ รอบ < 100 {
        ผูก ข้อความ = net_recv()
        ถ้า ข้อความ != "" {
            พิมพ์("โฮสต์ได้รับ: " + ข้อความ)
            net_send("ตอบกลับ:" + ข้อความ)
            ผูก รอบ = 1000
        }
        นอน(50)
        ผูก รอบ = รอบ + 1
    }
    นอน(300)
    net_close()
}
```

```ling-gui
# client.ling
ผูก เริ่ม = ทำ {
    net_join("127.0.0.1", 17777)
    ผูก รอบ = 0
    ขณะที่ net_status() != 2 && รอบ < 100 {
        นอน(50)
        ผูก รอบ = รอบ + 1
    }
    net_send("สวัสดี")
    ผูก ได้รับ = ""
    ขณะที่ ได้รับ == "" && รอบ < 200 {
        ผูก ได้รับ = net_recv()
        นอน(50)
        ผูก รอบ = รอบ + 1
    }
    พิมพ์("ไคลเอนต์ได้รับ: " + ได้รับ)
    net_close()
}
```

รันโฮสต์ในเทอร์มินัลหนึ่ง และไคลเอนต์ในอีกเทอร์มินัลหนึ่ง ไคลเอนต์จะพิมพ์
`ไคลเอนต์ได้รับ: ตอบกลับ:สวัสดี`

### ข้อความและเหตุการณ์

- ข้อความต้องไม่มีอักขระขึ้นบรรทัดใหม่ เพราะอักขระขึ้นบรรทัดใหม่ที่แทรกอยู่จะทำให้ได้รับเป็นสองข้อความ
- คิวขาเข้าแต่ละคิวเก็บได้ 4096 บรรทัด เมื่อเต็มแล้วบรรทัดที่เก่าที่สุดจะถูกทิ้ง
- `net_recv()` และ `net_recv_from()` อ่านจากคิวเดียวกัน จึงควรเลือกใช้แบบเดียวในแต่ละโปรแกรม
  `net_recv_from()` คืน `"2|hello"` ให้แยกที่ `|` **ตัวแรก** เพราะตัวข้อความเองอาจมี `|`
- `net_events()` เก็บเหตุการณ์ล่าสุด 256 รายการ โดยเชื่อมด้วยการขึ้นบรรทัดใหม่

### การค้นหาโฮสต์ใน LAN

`net_announce(port, info)` กระจาย `info` ผ่าน UDP (พอร์ตเริ่มต้น 7778) ประมาณวินาทีละครั้ง
การเรียกซ้ำจะอัปเดตข้อความ `net_discover(port)` คืนบรรทัด `"ip|info"` ของโฮสต์ที่ได้ยินใน 5 วินาทีล่าสุด
การเรียกครั้งแรกจะเริ่มตัวรอรับ จึงคืน `""` จนกว่าจะมีการประกาศเข้ามา

```ling-gui
ผูก เริ่ม = ทำ {
    ผูก โฮสต์ = ""
    ผูก รอบ = 0
    ขณะที่ โฮสต์ == "" && รอบ < 40 {
        ผูก โฮสต์ = net_discover(7778)
        นอน(250)
        ผูก รอบ = รอบ + 1
    }
    พิมพ์(โฮสต์)
}
```

### การส่งต่อพอร์ตของเราเตอร์

`net_upnp_map(port, description)` ขอให้เราเตอร์ (UPnP IGD) ส่งต่อพอร์ต TCP มายังเครื่องนี้
`net_upnp_poll()` คืน `""` ระหว่างทำงาน จากนั้นคืน `"ok|<public ip>"`, `"cgnat|<ip>"`
(เราเตอร์เองอยู่หลัง NAT ของผู้ให้บริการ การส่งต่อพอร์ตจึงไปไม่ถึงคุณ) หรือ `"fail|<reason>"`
`net_upnp_unmap()` ยกเลิกการส่งต่อพอร์ต

### ความปลอดภัย

โฮสต์รอรับบนทุกอินเทอร์เฟซ ข้อมูลเป็นข้อความธรรมดา และใครก็ตามที่เข้าถึงพอร์ตได้ก็เข้าร่วมได้
ใช้ `net_*` ใน LAN ที่ไว้ใจได้หรือภายในอุโมงค์ข้อมูล ถ้าข้ามอินเทอร์เน็ต ให้ใช้ `lingtp_*`, `ssh_*` หรือ HTTPS
`net_test` และ `net_local_ip` หาที่อยู่ LAN โดยเปิดซ็อกเก็ต UDP ไปทางที่อยู่สาธารณะ แต่ไม่ได้ส่งอะไรออกไป

## SSH: `ssh_*`

ฟังก์ชัน SSH เป็นไคลเอนต์ SSH-2 ของจริงและเซิร์ฟเวอร์ SSH ขนาดเล็ก ไคลเอนต์ใช้ได้กับเซิร์ฟเวอร์ OpenSSH ทุกตัว
ส่วนเซิร์ฟเวอร์ช่วยให้โปรแกรม Ling รับบรรทัดคำสั่งเชลล์และคำขอ `exec` จากไคลเอนต์ OpenSSH ได้
ไม่มีตัวใดมีชื่อแปลตามภาษา

| ฟังก์ชันในตัว | หน้าที่ |
|---|---|
| `ssh_connect(host, port, user, password)` | เชื่อมต่อและล็อกอิน: `1` สำเร็จ `0` ข้อมูลล็อกอินผิด `-1` เชื่อมต่อผิดพลาด `-2` กุญแจโฮสต์เปลี่ยน |
| `ssh_exec(command)` | รันคำสั่งหนึ่งคำสั่งและคืนเอาต์พุตมาตรฐาน |
| `ssh_exit_code()` | สถานะการจบของ `ssh_exec` ล่าสุด (`-1` ถ้ายังไม่มี) |
| `ssh_client_status()` | `0` ไม่ได้เชื่อมต่อ `2` เชื่อมต่อแล้ว |
| `ssh_close()` | ตัดการเชื่อมต่อไคลเอนต์ |
| `ssh_config(port, user, password, host_key_path)` | เตรียมการตั้งค่าเซิร์ฟเวอร์ |
| `ssh_serve()` | เริ่มเซิร์ฟเวอร์เบื้องหลัง `true` ถ้ากำลังรอรับ |
| `ssh_serve_recv()` | ข้อมูลเข้าเก่าสุดจากไคลเอนต์ใดก็ได้ในรูป `"id\|text"` หรือ `""` |
| `ssh_serve_send(id, text)` | ส่งหนึ่งบรรทัดถึงไคลเอนต์ |
| `ssh_serve_exit(id, code)` | จบคำขอ `exec` ด้วยสถานะการจบและปิดช่องสัญญาณ |
| `ssh_serve_clients()` | รหัสไคลเอนต์ที่เชื่อมต่อ คั่นด้วยจุลภาค |
| `ssh_serve_client_count()` | จำนวนไคลเอนต์ที่เชื่อมต่อ |
| `ssh_serve_events()` | ดึงบรรทัด `connect:`, `disconnect:` และ `authfail:` ออกทั้งหมด |
| `ssh_serve_status()` | `0` ว่าง `1` กำลังรอรับ `2` มีไคลเอนต์เชื่อมต่อ |
| `ssh_stop()` | หยุดรอรับและตัดไคลเอนต์ทั้งหมด |

### ไคลเอนต์

```ling-gui
ผูก เริ่ม = ทำ {
    ผูก ผล = ssh_connect("192.168.1.20", 22, "deploy", env_get("DEPLOY_PASSWORD", ""))
    ถ้า ผล == 1 {
        พิมพ์(ssh_exec("uname -a"))
        พิมพ์(ssh_exit_code())
        ssh_close()
    } มิฉะนั้น {
        พิมพ์("ssh ล้มเหลว: " + ผล)
    }
}
```

ไคลเอนต์ตรวจกุญแจโฮสต์ทุกครั้งกับไฟล์ `known_hosts` ในรูปแบบของ OpenSSH การเชื่อมต่อครั้งแรกกับโฮสต์หนึ่ง
จะเชื่อถือกุญแจของโฮสต์นั้นเหมือน OpenSSH และกุญแจที่เปลี่ยนไปจะถูกปฏิเสธ (`-2`)
การยืนยันตัวตนใช้รหัสผ่านเท่านั้น อย่าใส่รหัสผ่านไว้ในซอร์สโค้ด ให้อ่านด้วย `env_get`

### เซิร์ฟเวอร์

`ssh_config` รับพอร์ต (ค่าเริ่มต้น 22) ชื่อผู้ใช้หนึ่งชื่อที่ยอมรับ รหัสผ่านที่ห้ามว่าง และไฟล์กุญแจโฮสต์ Ed25519
(`""` หมายถึง `.ling-ssh/host_ed25519` ซึ่งสร้างขึ้นเมื่อเริ่มครั้งแรก) เซิร์ฟเวอร์รองรับการล็อกอินด้วยรหัสผ่านเท่านั้น
และเปรียบเทียบรหัสผ่านด้วยเวลาคงที่ เซิร์ฟเวอร์ไม่ได้รันคำสั่งให้คุณ มันใส่สิ่งที่ไคลเอนต์พิมพ์เข้าคิว
แล้วโค้ดของคุณตัดสินว่าจะตอบอะไร มันจึงเป็นปลายทางของโปรโตคอล ไม่ใช่เชลล์

```ling-gui
ผูก เริ่ม = ทำ {
    ssh_config(2222, "admin", env_get("SSH_PASSWORD", ""), "")
    ถ้า ssh_serve() {
        ขณะที่ จริง {
            ผูก ข้อความ = ssh_serve_recv()
            ถ้า ข้อความ != "" {
                ผูก ส่วน = split(ข้อความ, "|")
                ssh_serve_send(to_number(ส่วน[0]), "คุณพิมพ์ว่า: " + ส่วน[1])
                ssh_serve_exit(to_number(ส่วน[0]), 0)
            }
            นอน(50)
        }
    }
}
```

> ข้อจำกัดที่ทราบ: ในการทดสอบผ่าน loopback ระหว่างไคลเอนต์ Ling กับเซิร์ฟเวอร์ Ling นั้น `ssh_exec`
> คืน `""` พร้อมสถานะการจบ `-1` แทนคำตอบของเซิร์ฟเวอร์ ควรใช้ OpenSSH เป็นอีกฝั่ง
> และทดสอบคู่ที่คุณใช้เองก่อนพึ่งพา

## ช่องทางหลังควอนตัม: `lingtp://`

`lingtp://` เป็นโปรโตคอลคำขอ/คำตอบขนาดเล็กที่ทำหน้าที่แบบ HTTPS แต่ใช้การเข้ารหัสหลังควอนตัม
และไม่มีผู้ออกใบรับรอง ทุกการเชื่อมต่อเริ่มด้วยแฮนด์เชก เซิร์ฟเวอร์พิสูจน์ตัวตนด้วยลายเซ็น **ML-DSA-87**
และทั้งสองฝั่งตกลงกุญแจกันด้วย KEM แบบผสม **X25519 + ML-KEM-768** จากนั้นทุกเฟรมจะถูกผนึกด้วย
XChaCha20-Poly1305 และห่อซ้ำอีกชั้นด้วยชุดเข้ารหัสต่อเนื่อง DICE-42 กุญแจใหม่ทุกการเชื่อมต่อ
จึงมีความลับไปข้างหน้า (forward secrecy)

ความเชื่อถือทำงานเหมือน SSH ครั้งแรกที่ไคลเอนต์เห็นโฮสต์ มันจะเก็บกุญแจสาธารณะของโฮสต์ไว้ใน
`.lingtp/known_hosts` (เทียบกับโฟลเดอร์ปัจจุบัน) ถ้าภายหลังโฮสต์นั้นแสดงกุญแจอื่น การเชื่อมต่อจะถูกปฏิเสธ
ถ้าเครือข่ายอาจไม่ปลอดภัย ให้ตรวจกุญแจผ่านช่องทางอื่นในครั้งแรก

คำขอคือสตริงหนึ่งตัว (พาธ รวมถึงสตริงคิวรี) และคำตอบคือสตริงหนึ่งตัว (เนื้อหา) การ POST ส่ง
`path + "\n" + body` ตัวจัดการจึงแยกสองแบบออกจากกันได้ด้วยการดูว่ามีการขึ้นบรรทัดใหม่หรือไม่

| ฟังก์ชันในตัว | หน้าที่ |
|---|---|
| `lingtp_get(host, port, path)` | ดึงพาธ (พอร์ตเริ่มต้น 7780) คืนเนื้อหา หรือ `""` เมื่อล้มเหลว |
| `lingtp_post(host, port, path, body)` | ส่งเนื้อหา คืนเนื้อหาของคำตอบ |
| `lingtp_get_status()` | ผลของคำขอล่าสุด: `1` สำเร็จ `0` เชื่อมต่อผิดพลาด `-1` ลายเซ็นเซิร์ฟเวอร์ไม่ถูกต้อง `-2` กุญแจโฮสต์เปลี่ยน |
| `lingtp_config(port, host_key_path)` | เตรียมการตั้งค่าเซิร์ฟเวอร์ |
| `lingtp_route(prefix, handler)` | ตอบพาธที่ขึ้นต้นด้วย `prefix` (คำนำหน้าที่ยาวที่สุดชนะ) |
| `lingtp_serve()` | ให้บริการจนกว่าจะเรียก `lingtp_stop` บล็อกเธรดที่เรียก |
| `lingtp_stop()` | หยุดเซิร์ฟเวอร์ |
| `lingtp_status()` | `0` หยุด `1` กำลังรอรับ `2` มีไคลเอนต์เชื่อมต่อ |
| `lingtp_client_count()` | จำนวนไคลเอนต์ที่เชื่อมต่อ |
| `lingtp_events()` | ดึงบรรทัด `connect:<id>` / `disconnect:<id>` ออกทั้งหมด |

ไม่มีตัวใดมีชื่อแปลตามภาษา

### การให้บริการ

ลงทะเบียนเส้นทางก่อนเรียก `lingtp_serve()` ทันที เพราะมันล้างตารางเส้นทางเมื่อเริ่มทำงาน
มันคืน `false` ถ้ายังไม่ได้ตั้งค่า หรือสร้างกุญแจหรือซ็อกเก็ตไม่ได้ ตัวจัดการรับพาธและคืนเนื้อหา

```ling-gui
ฟังก์ชัน ทักทาย(พาธ) {
    คืน "สวัสดีหลังควอนตัมจาก " + พาธ
}

ผูก เริ่ม = ทำ {
    lingtp_config(17780, "hostkey.hex")
    lingtp_route("/", ทักทาย)
    พิมพ์("กำลังให้บริการ")
    lingtp_serve()
}
```

### การดึงข้อมูล

```ling-gui
ผูก เริ่ม = ทำ {
    ผูก เนื้อหา = lingtp_get("127.0.0.1", 17780, "/hi?x=1")
    ถ้า lingtp_get_status() == 1 {
        พิมพ์(เนื้อหา)
    } มิฉะนั้น {
        พิมพ์("lingtp ล้มเหลว: " + lingtp_get_status())
    }
}
```

เมื่อใช้กับเซิร์ฟเวอร์ข้างต้น จะพิมพ์ `สวัสดีหลังควอนตัมจาก /hi?x=1`

### หมายเหตุด้านความปลอดภัย

- กุญแจโฮสต์ถูกเก็บเป็นเมล็ดเลขฐานสิบหกในไฟล์ธรรมดา (`.lingtp/host_mldsa87` เป็นค่าเริ่มต้น
  หรือพาธที่คุณให้กับ `lingtp_config`) ปกป้องไฟล์นี้เหมือนกุญแจส่วนตัวของ SSH และสำรองไว้
  ถ้าทำหาย ตัวตนของเซิร์ฟเวอร์จะเปลี่ยน และไคลเอนต์ทุกตัวจะปฏิเสธการเชื่อมต่อ
- ข้อผิดพลาดในตัวจัดการจะถูกส่งกลับไปยังไคลเอนต์เป็น `handler error: ...` ซึ่งอาจเผยรายละเอียดภายใน
  ตรวจสอบข้อมูลเข้าและหลีกเลี่ยงข้อผิดพลาดในตัวจัดการ
- เซิร์ฟเวอร์รอรับบนทุกอินเทอร์เฟซและตอบคำขอทีละรายการ
- `lingtp_post` ถือว่าการขึ้นบรรทัดใหม่ครั้งแรกคือจุดเริ่มของเนื้อหา จึงต้องเข้ารหัสเปอร์เซ็นต์การขึ้นบรรทัดใหม่ในพาธ
- เครต Rust `ling-net` มีโมดูล `lingtp` ของตัวเองซึ่งใช้รูปแบบข้อมูลบนสายต่างออกไป `lingtp_get` ของ Ling
  จึงคุยกับเซิร์ฟเวอร์ `ling-net` ไม่ได้ ให้ใช้การสร้างแบบเดียวกันทั้งสองฝั่ง

## เพียร์ทูเพียร์: `p2p_*`

`p2p_*` รัน LWP-1 ซึ่งเป็นช่องทางส่งข้อมูลของโครงการ Ling Wallet เพียร์ยืนยันตัวตนกันด้วยตัวตน ML-DSA-87
ระหว่างแฮนด์เชกแบบผสม X25519 + ML-KEM-1024 และเฟรมจะถูกเติมให้มีขนาดคงที่แล้วผนึก โหนดเก็บฐานข้อมูลเพียร์
ใช้รายการเมล็ดที่ลงนามแล้วและพร็อกซี SOCKS5 ได้ (เช่น Tor ที่ `127.0.0.1:9050`) และส่งต่อธุรกรรมด้วย Dandelion++
ข้อมูลที่ส่งเป็นสตริงเลขฐานสิบหกที่ติดป้ายด้วยตัวเลข `kind` ซึ่งโปรแกรมของคุณกำหนดเอง

| ฟังก์ชันในตัว | หน้าที่ |
|---|---|
| `p2p_start(config, events)` | เริ่มโหนด คืน `Ok(handle)` หรือ `Err(message)` ส่ง `""` ให้ `events` |
| `p2p_poll(net, max, timeout_ms)` | ดึงเหตุการณ์ได้สูงสุด `max` รายการ (ค่าเริ่มต้น 64) รอได้นานสุด `timeout_ms` |
| `p2p_send(net, peer, kind, payload_hex)` | ส่งถึงเพียร์หนึ่งตัว `true` ถ้าเข้าคิวแล้ว |
| `p2p_broadcast(net, kind, payload_hex, except_peer)` | ส่งถึงทุกเพียร์ยกเว้นหนึ่งตัว (`-1` ถ้าไม่ยกเว้น) |
| `p2p_relay(net, id_hex, payload_hex, kind, from_peer)` | ส่งต่อธุรกรรมที่ตรวจแล้วแบบ Dandelion++ |
| `p2p_mark_fluffed(net, id_hex)` | บันทึกว่าธุรกรรมถูกกระจายไปแล้ว |
| `p2p_peers(net)` | `[id, addr, inbound, fingerprint, is_seed, connected_secs]` ของแต่ละเพียร์ |
| `p2p_misbehaving(net, peer, score, reason)` | เพิ่มคะแนนแบนของเพียร์ |
| `p2p_local_addr(net)` | ที่อยู่ที่รอรับ `"ip:port"` หรือ `""` |
| `p2p_fingerprint(identity_seed_hex)` | ลายนิ้วมือที่เพียร์จะเห็นสำหรับเมล็ดหนึ่ง เช่น `9ebc-56af-97f2-61af` |
| `p2p_netgroup(net, peer)` | กลุ่มเครือข่ายของเพียร์ เช่น `v4:1.2` |
| `p2p_seeds_sign(network, issued_at, entries, authority_seed_hex)` | ลงนามรายการเมล็ดในฐานะผู้มีอำนาจออกเมล็ด |
| `p2p_seeds_verify(list_hex, authority_pk_hex)` | `Ok([network, issued_at, entries])` หรือ `Err(...)` |
| `p2p_shutdown(net)` | หยุดโหนด `true` ในครั้งแรก |

ไม่มีตัวใดมีชื่อแปลตามภาษา `str_to_hex(text)` และ `hex_to_str(hex)` แปลงข้อมูลที่ส่งระหว่างข้อความกับเลขฐานสิบหก

### การตั้งค่า

`config` เป็นรายการของคู่ `[key, value]` คีย์ที่ไม่รู้จัก คีย์ซ้ำ และชนิดข้อมูลผิดจะถูกปฏิเสธด้วย `Err(message)`

| คีย์ | ความหมาย |
|---|---|
| `magic_hex` | **จำเป็น** เลขฐานสิบหก 8 ตัว เพียร์ที่ค่า magic ต่างกันจะไม่เชื่อมต่อกัน |
| `network` | **จำเป็น** รหัสเครือข่าย 0–255 |
| `data_dir` | **จำเป็น** โฟลเดอร์สำหรับฐานข้อมูลเพียร์และตัวตน สร้างให้ถ้ายังไม่มี |
| `listen` | `"ip:port"` เพื่อรับเพียร์ หรือ `""` สำหรับขาออกอย่างเดียว พอร์ต `0` เลือกพอร์ตว่างให้ |
| `peers` | รายการเพียร์ `"host:port"` ที่จะพยายามเชื่อมต่อเสมอ |
| `identity_seed_hex` | เลขฐานสิบหก 64 ตัวสำหรับตัวตนระยะยาว ละไว้เพื่อใช้ตัวตนสุ่ม |
| `ephemeral_outbound` | ใช้ตัวตนใหม่ทุกการเชื่อมต่อขาออก (ค่าเริ่มต้น `true`) |
| `max_outbound`, `max_inbound` | จำนวนการเชื่อมต่อสูงสุด (ค่าเริ่มต้น 8 และ 32) |
| `proxy` | พร็อกซี SOCKS5 `"ip:port"` สำหรับการรับส่งขาออกทั้งหมด |
| `seeds_hex`, `authority_pk_hex` | รายการเมล็ดที่ลงนามแล้วและกุญแจที่ต้องใช้ตรวจสอบ |
| `fast_timers` | ตัวจับเวลาแบบสั้น สำหรับการทดสอบ |

### เหตุการณ์

`p2p_poll` คืนรายการของเหตุการณ์ ซึ่งแต่ละเหตุการณ์ก็เป็นรายการ:

| สมาชิกตัวแรก | รูปแบบ |
|---|---|
| `"connected"` | `["connected", peer_id, addr, inbound, fingerprint, is_seed]` |
| `"disconnected"` | `["disconnected", peer_id]` |
| `"message"` | `["message", peer_id, kind, payload_hex]` |
| `"stem"` | `["stem", peer_id, payload_hex]`: ธุรกรรม Dandelion++ ที่ต้องตรวจสอบ |

ต้องวนถามต่อเนื่อง เพราะเหตุการณ์รออยู่ในคิวขนาดจำกัด และคิวที่เต็มจะทำให้ทุกเพียร์ช้าลง
ค่า kind ของข้อความอยู่ระหว่าง 16–255 (ค่าที่ต่ำกว่าถูกสงวนไว้) และข้อมูลที่ส่งมีขนาดสูงสุดประมาณ 4 MiB

### ตัวอย่าง

สองโหนดบนเครื่องเดียว: A รอรับ ส่วน B เชื่อมต่อกับ A และส่งคำว่า `สวัสดี`

```ling-gui
ฟังก์ชัน แกะ(r) { คืน จับคู่ r { ok(v) => v, bad(e) => "ผิดพลาด:" + e } }

ผูก เริ่ม = ทำ {
    ผูก ก = แกะ(p2p_start([["magic_hex", "4c494e47"], ["network", 1], ["listen", "127.0.0.1:0"], ["data_dir", "node_a"]], ""))
    ผูก ข = แกะ(p2p_start([["magic_hex", "4c494e47"], ["network", 1], ["listen", ""], ["data_dir", "node_b"], ["peers", [p2p_local_addr(ก)]]], ""))
    ผูก เพียร์ = []
    ผูก รอบ = 0
    ขณะที่ ความยาว(เพียร์) == 0 && รอบ < 100 {
        ผูก เพียร์ = p2p_peers(ข)
        นอน(100)
        ผูก รอบ = รอบ + 1
    }
    p2p_send(ข, เพียร์[0][0], 16, str_to_hex("สวัสดี"))
    ผูก ที่ได้ = ""
    ผูก รอบ = 0
    ขณะที่ ที่ได้ == "" && รอบ < 20 {
        ผูก เหตุการณ์ = p2p_poll(ก, 10, 500)
        ผูก i = 0
        ขณะที่ i < ความยาว(เหตุการณ์) {
            ถ้า เหตุการณ์[i][0] == "message" { ผูก ที่ได้ = hex_to_str(เหตุการณ์[i][3]) }
            ผูก i = i + 1
        }
        ผูก รอบ = รอบ + 1
    }
    พิมพ์("A ได้รับ: " + ที่ได้)
    p2p_shutdown(ก)
    p2p_shutdown(ข)
}
```

### หมายเหตุด้านความปลอดภัย

- ใน isolate ที่ถูกจำกัดสิทธิ์ ฟังก์ชัน `p2p_*` ทุกตัวต้องมีความสามารถ `"p2p"` เธรดหลักมีความสามารถทุกอย่าง
- แฮนเดิลเครือข่ายเป็นสตริงเลขฐานสิบหก 128 บิตที่เดาไม่ได้ และใช้ได้เฉพาะใน isolate ที่เริ่มมัน
  แฮนเดิลที่ไม่รู้จักทำให้เกิดข้อผิดพลาด หลัง `p2p_shutdown` การเรียกจะคืน `false` หรือ `[]`
- `data_dir` เก็บตัวตนของโหนด ปกป้องมันเหมือนกุญแจส่วนตัว
