# การเข้ารหัส

Ling มีระบบการเข้ารหัสในตัว ได้แก่ แฮช การเข้ารหัสแบบยืนยันตัวตน การแฮชรหัสผ่าน
ลายเซ็นดิจิทัลทั้งแบบดั้งเดิมและแบบหลังควอนตัม การแลกเปลี่ยนกุญแจแบบผสมหลังควอนตัม
รหัสยืนยันสองขั้นตอน และชุดฟังก์ชันพื้นฐานของ Ling Wallet (`lw_*`) พร้อมวลีกู้คืนแบบ BIP-39
ฟังก์ชันในตัวเหล่านี้เป็นชั้นบางๆ ที่ทำงานกับสตริง ครอบอยู่บนโค้ด Rust ที่ผ่านการตรวจสอบแล้ว
(RustCrypto, dalek, BLAKE3, `ml-kem`, `ml-dsa`, Argon2) ในเครต `ling-crypto`

โปรไฟล์การติดตั้งที่ต้องใช้:

| ฟังก์ชันในตัว | โปรไฟล์ |
|---|---|
| แฮช, `crypto_seal`/`crypto_open`, ลายเซ็น, `knot_*`, `password_*` | `web` หรือ `privacy` (ทั้งสองมีส่วนประกอบด้านการเข้ารหัส) |
| `totp_secret`, `totp_now` | `web` |
| `lw_*` | `privacy` |

การติดตั้งค่าเริ่มต้น (`full`) มีครบทุกตัว ถ้าไม่มีโปรไฟล์ใด การเรียกฟังก์ชันในตัวของโปรไฟล์นั้น
จะล้มเหลวพร้อมข้อความที่บอกชื่อโปรไฟล์ที่ต้องติดตั้งใหม่

## ข้อตกลง

- **รับเข้าเป็นเลขฐานสิบหก ส่งออกเป็นเลขฐานสิบหก** กุญแจ nonce ข้อความเข้ารหัส ไดเจสต์ และลายเซ็น
  เป็นสตริงเลขฐานสิบหกตัวพิมพ์เล็ก กุญแจขนาด 32 ไบต์คือ 64 ตัวอักษร
- **แฮนเดิล** `ed25519_keygen`, `mldsa_keygen`, `mldsa87_keygen` และ `knot_keygen` คืนตัวเลขเล็กๆ
  ที่ชี้ไปยังตารางกุญแจภายในอินเทอร์พรีเตอร์ ส่วนตระกูล `lw_*` คืนแฮนเดิลเลขฐานสิบหก 32 ตัวอักษรแทน
  ไบต์ของกุญแจลับไม่เคยมาถึงโค้ดของคุณ
- **ผลลัพธ์** ฟังก์ชันในตัวที่อาจล้มเหลวเมื่อได้รับข้อมูลไม่ถูกต้องจะคืนผลลัพธ์ เมื่อพิมพ์ออกมาจะเห็นเป็น
  `Ok(...)` หรือ `Err(message)` แกะค่าออกด้วย `จับคู่ r { ok(v) => ..., bad(e) => ... }` (ชื่อรูปแบบ `ok` และ `bad` ต้องเขียนเป็นภาษาอังกฤษ)
- **ชื่อที่สะกดผิดจะเงียบ** ฟังก์ชันที่ไม่มีอยู่จะได้ค่า `()` ถ้าการเรียกใด "ไม่ทำอะไรเลย" ให้ตรวจการสะกด

## คำแนะนำด้านความปลอดภัย

1. **ใช้ฟังก์ชันในตัวระดับสูงสุดที่ทำงานนั้นได้** ถ้าจะเข้ารหัสด้วยกุญแจที่มีอยู่แล้ว ให้ใช้ `crypto_seal`
   ถ้าจะเก็บรหัสผ่าน ให้ใช้ `password_hash` อย่าสร้างระบบเองจากแฮชและ XOR
2. **กุญแจต้องเป็นค่าสุ่มจริง 32 ไบต์** `crypto_seal`, `crypto_open` และฟังก์ชัน `*_from_seed`
   อ่านเลขฐานสิบหกแบบผ่อนปรน กุญแจที่สั้นไปจะถูกเติมศูนย์ ที่ยาวไปจะถูกตัด และคู่ตัวอักษรที่ไม่ใช่ฐานสิบหก
   จะถูกทิ้ง การพิมพ์ผิดจึงให้กุญแจที่อ่อนแอแทนที่จะเกิดข้อผิดพลาด สร้างกุญแจด้วย `random_hex(32)`
   และแปลงวลีรหัสผ่านเป็นกุญแจด้วย `lw_password_key` (Argon2id) ห้ามใช้แฮชเพียงครั้งเดียว
3. **`password_hash` ใช้สำหรับการล็อกอิน ส่วน `lw_password_key` ใช้สำหรับสร้างกุญแจ**
4. **ห้ามใช้ nonce ซ้ำ** `crypto_seal` เลือก nonce สุ่มใหม่ทุกครั้ง ส่วน `lw_aead_seal` รับ nonce จากคุณ
   ให้ใช้ `random_hex(24)` สำหรับแต่ละข้อความ
5. **อย่าใช้ตัวสุ่มของเกมกับความลับ** `rand` มีไว้สำหรับการเล่นเกม ให้ใช้ `random_hex` หรือ `lw_random`
   ซึ่งอ่านจากตัวสร้างค่าสุ่มที่ปลอดภัยของระบบปฏิบัติการ
6. **สตริงไม่ถูกลบทิ้ง** ความลับแบบเลขฐานสิบหกในตัวแปรของ Ling จะอยู่นานเท่ากับสตริงนั้น
   เก็บความลับไว้ในแฮนเดิลเมื่อ API มีให้ และทิ้งกุญแจ `lw_*` ด้วย `lw_key_drop`
7. **เปรียบเทียบด้วยฟังก์ชันตรวจสอบ** `==` กับสตริงไม่ใช้เวลาคงที่ ให้ใช้ `ed25519_verify`,
   `mldsa87_verify`, `password_verify` และ `totp_verify`
8. **`crypto_hash` ไม่ใช่ SHA3-256 ธรรมดา** มันเติมป้ายกำกับเฉพาะของ Ling ผลจึงไม่ตรงกับเครื่องมืออื่น
   ใช้ `sha256_hex` หรือ `hash_hex` เมื่อต้องทำงานร่วมกับระบบอื่น
9. **ถือว่าการออกแบบเฉพาะของ Ling ยังไม่ผ่านการตรวจสอบ** ชั้นเรขาคณิต (`knot_points`, `holo_points`,
   `crypto_hash`) ชุดเข้ารหัสต่อเนื่อง DICE-42 ใน `lingtp://` และลายเซ็นแบบวง LRS-87
   เป็นโครงสร้างที่ออกแบบใหม่บนฟังก์ชันพื้นฐานมาตรฐาน LRS-87 ถูกระบุว่าเป็นของทดลอง
   สำหรับระบบที่มีมูลค่าสูง ให้ใช้ฟังก์ชันพื้นฐานมาตรฐานและจัดให้มีการตรวจสอบของคุณเอง
10. **ระบบหลังควอนตัมที่นี่เป็นแบบผสม** ฟังก์ชัน KEM รวม X25519 เข้ากับ ML-KEM
    ความลับจึงยังปลอดภัยแม้ส่วนใดส่วนหนึ่งถูกเจาะ ข้อความเข้ารหัส KEM ที่ถูกแก้ไขจะให้ความลับที่ต่างออกไป
    แทนที่จะเกิดข้อผิดพลาด จึงต้องใช้ความลับนั้นยืนยันบางอย่างเสมอ

## แฮชและไบต์สุ่ม

| ฟังก์ชันในตัว | 中文 | 日本語 | 한국어 | ไทย | หน้าที่ |
|---|---|---|---|---|---|
| `sha256_hex(text)` | `SHA256哈希` | — | — | — | SHA-256 เป็นเลขฐานสิบหก 64 ตัว |
| `hash_hex(text)` | — | — | — | `แฮชสตริง` | BLAKE3 เป็นเลขฐานสิบหก 64 ตัว |
| `file_hash(path)` | — | — | — | `แฮชไฟล์` | BLAKE3 ของไบต์ดิบในไฟล์ |
| `crypto_hash(text)` | `几何哈希` | `幾何ハッシュ` | `기하해시` | `แฮชเข้ารหัส` | SHA3-256 ที่มีป้ายกำกับของ Ling |
| `shake_hex(text, len)` | `SHAKE哈希` | — | — | — | SHAKE-256 ส่งออก `len` ไบต์ |
| `hash_str(text)` | — | — | — | `แฮช` | แฮชเร็วที่ไม่ใช่เชิงการเข้ารหัส ค่า 0 ถึง 1 |
| `hash_int(text, n)` | — | — | — | `แฮชจำนวน` | แฮชเร็วที่ไม่ใช่เชิงการเข้ารหัส ค่า 0 ถึง `n - 1` |
| `random_hex(n)` | — | — | `무작위16진수` | — | ไบต์สุ่มที่ปลอดภัย `n` ไบต์เป็นเลขฐานสิบหก |

### `sha256_hex`, `hash_hex`, `file_hash`

`sha256_hex` ให้ผลตรงกับเครื่องมือ SHA-256 อื่นทุกตัว รวมถึง `crypto.subtle.digest` ของเบราว์เซอร์
`hash_hex` คือ BLAKE3 ซึ่งเร็วและทนต่อการชนกัน `file_hash` แฮชไบต์ดิบของไฟล์ด้วย BLAKE3
(ใช้กับไฟล์ไบนารีได้) และคืน `""` ถ้าอ่านไฟล์ไม่ได้ ไม่มีตัวใดเป็นแฮชรหัสผ่าน

```ling
ผูก เริ่ม = ทำ {
    พิมพ์(sha256_hex("abc"))
    พิมพ์(hash_hex("abc"))
    write_file("note.txt", "สวัสดีไฟล์")
    พิมพ์(file_hash("note.txt") == hash_hex("สวัสดีไฟล์"))
    remove_file("note.txt")
}
```

```output
ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
6437b3ac38465133ffb63b75273a8db548c558465d79db03fd359c6cd5bd9d85
true
```

### `crypto_hash`, `shake_hex`

`crypto_hash(text)` คำนวณ `SHA3-256("ling-geo-holo-hash-v1" + text)` และเป็นไดเจสต์ที่ `knot_points`
นำไปวาด `shake_hex(text, len)` ดึงข้อมูลออกจาก SHAKE-256 จำนวน `len` ไบต์ (ค่าเริ่มต้น 32)

```ling
ผูก เริ่ม = ทำ {
    พิมพ์(แฮชเข้ารหัส("abc"))
    พิมพ์(shake_hex("abc", 16))
}
```

```output
0f5ae6a06fa73d3e18615b33ee9a9efafdb1a25a7bbf5f3ca9c4d7f1ac4ddfb9
483366601360a8771c6863080cc4114d
```

### `hash_str`, `hash_int`

แฮชแบบ FNV-1a สำหรับค่าเมล็ด สี และการแบ่งกลุ่ม ให้ผลแน่นอนแต่**ไม่ปลอดภัย**
ห้ามใช้กับข้อมูลที่ผู้โจมตีควบคุมได้ ค่า `n` ของ `hash_int` มีค่าเริ่มต้นเป็น 100

### `random_hex(n)`

คืนไบต์สุ่ม `n` ไบต์ (ค่าเริ่มต้น 32 จำกัดอยู่ที่ 1–256) จากตัวสร้างค่าสุ่มที่ปลอดภัยของระบบปฏิบัติการ
เป็นเลขฐานสิบหก `2 * n` ตัว ใช้สำหรับกุญแจ nonce และรหัสเซสชัน

```ling
ผูก เริ่ม = ทำ {
    ผูก กุญแจ = random_hex(32)
    พิมพ์(ความยาว(กุญแจ))
}
```

```output
64
```

## การผนึกข้อความ

| ฟังก์ชันในตัว | 中文 | 日本語 | 한국어 | ไทย | หน้าที่ |
|---|---|---|---|---|---|
| `crypto_seal(key_hex, text)` | `封印` | `封印する` | `봉인` | `ผนึก` | เข้ารหัสและยืนยันด้วย XChaCha20-Poly1305 |
| `crypto_open(key_hex, sealed_hex)` | `解封` | `封印解除` | `봉인해제` | `เปิดผนึก` | ตรวจสอบและถอดรหัส |

`crypto_seal` คืน `nonce (24 ไบต์) + ข้อความเข้ารหัส + แท็ก (16 ไบต์)` เป็นเลขฐานสิบหก
การผนึกข้อความเดิมสองครั้งให้ผลต่างกัน เพราะแต่ละครั้งสุ่ม nonce ใหม่ `crypto_open` คืนข้อความเดิม
หรือ `Err("decryption/auth failed")` ถ้ากุญแจผิดหรือมีบิตใดเปลี่ยนไป ข้อความถูกถอดเป็น UTF-8
ข้อมูลไบนารีจึงต้องเข้ารหัสก่อน (เช่นด้วย `base64_encode`)

```ling
ผูก เริ่ม = ทำ {
    ผูก กุญแจ = "000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f"
    ผูก ผนึกแล้ว = ผนึก(กุญแจ, "เจอกันตอนเที่ยง")
    พิมพ์(เปิดผนึก(กุญแจ, ผนึกแล้ว))
    พิมพ์(เปิดผนึก("ff" + กุญแจ, ผนึกแล้ว))
}
```

```output
เจอกันตอนเที่ยง
Err(decryption/auth failed)
```

## รหัสผ่าน

| ฟังก์ชันในตัว | 中文 | 日本語 | 한국어 | ไทย | หน้าที่ |
|---|---|---|---|---|---|
| `password_hash(password)` | — | — | `비밀번호해시` | — | แฮช Argon2id เป็นสตริง PHC |
| `password_verify(password, stored)` | — | — | `비밀번호확인` | — | ตรวจรหัสผ่านกับแฮชที่เก็บไว้ |

`password_hash` ใช้ Argon2id ด้วยหน่วยความจำ 64 MiB, 3 รอบ, 4 เลน และ salt สุ่มใหม่
แล้วคืนสตริงแบบ `$argon2id$v=19$m=65536,t=3,p=4$...` ให้เก็บทั้งสตริง แต่ละครั้งใช้เวลาหลายสิบมิลลิวินาที
โดยตั้งใจ `password_verify` อ่านพารามิเตอร์จากสตริงที่เก็บไว้ แล้วคืน `true` หรือ `false`
(สตริงที่ผิดรูปแบบให้ `false`)

```ling
ผูก เริ่ม = ทำ {
    ผูก ที่เก็บ = password_hash("ม้าถูกต้อง")
    พิมพ์(substr(ที่เก็บ, 0, 30))
    พิมพ์(password_verify("ม้าถูกต้อง", ที่เก็บ))
    พิมพ์(password_verify("ผิด", ที่เก็บ))
}
```

```output
$argon2id$v=19$m=65536,t=3,p=4
true
false
```

## ลายเซ็น

ทั้งสามตระกูลมีรูปแบบเดียวกัน คือ สร้างคู่กุญแจ (แบบสุ่มหรือจากเมล็ด 32 ไบต์) อ่านกุญแจสาธารณะ
เซ็นสตริง แล้วตรวจสอบด้วยกุญแจสาธารณะ

| ตระกูล | คำนำหน้า | กุญแจสาธารณะ | ลายเซ็น | หมายเหตุ |
|---|---|---|---|---|
| Ed25519 | `ed25519_` | 32 ไบต์ | 64 ไบต์ | แบบดั้งเดิม เร็ว ให้ผลแน่นอน |
| ML-DSA-65 (FIPS 204) | `mldsa_` | 1952 ไบต์ | 3309 ไบต์ | หลังควอนตัม NIST ระดับ 3 |
| ML-DSA-87 (FIPS 204) | `mldsa87_` | 2592 ไบต์ | 4627 ไบต์ | หลังควอนตัม NIST ระดับ 5 ใช้ใน `lingtp://` |

| ฟังก์ชันในตัว | 中文 | 日本語 | 한국어 | ไทย | หน้าที่ |
|---|---|---|---|---|---|
| `ed25519_keygen()` | `生成签名密钥` | `署名鍵生成` | `생성서명키` | `สร้างกุญแจลายเซ็น` | แฮนเดิลคู่กุญแจแบบสุ่ม |
| `ed25519_keygen_from_seed(seed_hex)` | `从种子生成签名密钥` | `シードから署名鍵生成` | `씨앗에서생성서명키` | `สร้างกุญแจลายเซ็นจากเมล็ด` | คู่กุญแจจากเมล็ด 32 ไบต์ |
| `ed25519_public(handle)` | `签名公钥` | `署名公開鍵` | `서명공개키` | `กุญแจสาธารณะลายเซ็น` | กุญแจสาธารณะเป็นเลขฐานสิบหก |
| `ed25519_sign(handle, message)` | `签名` | `署名する` | `서명하다` | `เซ็นชื่อ` | ลายเซ็นเป็นเลขฐานสิบหก |
| `ed25519_verify(public_hex, message, sig_hex)` | `验证签名` | `署名検証` | `서명확인` | `ยืนยันลายเซ็น` | `true` ถ้าถูกต้อง |
| `mldsa_keygen()` | `生成量子签名密钥` | `量子署名鍵生成` | `양자서명키생성` | `สร้างกุญแจลายเซ็นควอนตัม` | คู่กุญแจ ML-DSA-65 แบบสุ่ม |

### การใช้ลายเซ็น

เมล็ดช่วยให้คุณเก็บเพียงเลขฐานสิบหก 64 ตัว แล้วสร้างคู่กุญแจเดิมขึ้นใหม่หลังรีสตาร์ต
จึงต้องปกป้องเมล็ดเหมือนกุญแจส่วนตัว แฮนเดิลที่ไม่รู้จักทำให้ `*_public` และ `*_sign` คืน `""`
ฟังก์ชันตรวจสอบคืน `false` เมื่อลายเซ็นผิดหรือข้อมูลผิดรูปแบบ ลายเซ็น Ed25519 ให้ผลแน่นอน
กุญแจและข้อความเดียวกันจะให้ลายเซ็นเดียวกันเสมอ

สำหรับไฟล์ที่ต้องใช้ไปนาน เช่น ไฟล์ใบอนุญาตหรือรายการไฟล์ของรุ่นที่เผยแพร่ ให้เซ็นด้วย Ed25519
**และ** ML-DSA-87 แล้วยอมรับเฉพาะเมื่อตรวจผ่านทั้งคู่

```ling
ผูก เริ่ม = ทำ {
    ผูก เมล็ด = "0101010101010101010101010101010101010101010101010101010101010101"
    ผูก กุญแจเอ็ด = ed25519_keygen_from_seed(เมล็ด)
    ผูก กุญแจควอนตัม = mldsa87_keygen_from_seed(เมล็ด)
    ผูก เอกสาร = "ใบอนุญาต: acme หมดอายุ 2031-01-01"
    ผูก ลายเซ็นก = ed25519_sign(กุญแจเอ็ด, เอกสาร)
    ผูก ลายเซ็นข = mldsa87_sign(กุญแจควอนตัม, เอกสาร)
    พิมพ์(ความยาว(ed25519_public(กุญแจเอ็ด)))
    พิมพ์(ed25519_verify(ed25519_public(กุญแจเอ็ด), เอกสาร, ลายเซ็นก) && mldsa87_verify(mldsa87_public(กุญแจควอนตัม), เอกสาร, ลายเซ็นข))
    พิมพ์(mldsa87_verify(mldsa87_public(กุญแจควอนตัม), เอกสาร + "!", ลายเซ็นข))
}
```

```output
true
false
```

## รหัสใช้ครั้งเดียว (TOTP)

| ฟังก์ชันในตัว | 中文 | 日本語 | 한국어 | ไทย | หน้าที่ |
|---|---|---|---|---|---|
| `totp_secret()` | — | — | — | `โทเทนลับ` | ความลับ Base32 แบบสุ่มใหม่ (160 บิต) |

TOTP ที่นี่เป็นไปตาม RFC 6238 ใช้ SHA-1 หกหลัก และช่วงละ 30 วินาที ตรงกับ Google Authenticator และ Authy
`totp_verify` ยอมรับคลาดเคลื่อนได้หนึ่งช่วงทั้งก่อนและหลัง และไม่ติดตามการใช้ซ้ำ

```ling
    พิมพ์(ความยาว(ความลับ))
    พิมพ์(โทเทนตรวจ(ความลับ, โทเทนตอนนี้(ความลับ)))
```


## ฟังก์ชันพื้นฐานของ Ling Wallet: `lw_*`

ตระกูล `lw_*` คือชุดฟังก์ชันพื้นฐานของโครงการ Ling Wallet ต่างจากฟังก์ชันในตัวข้างต้นสามข้อ:

- **รับข้อมูลแบบเข้มงวด** เลขฐานสิบหกต้องถูกรูปแบบและยาวตรงตามที่ระบุ ข้อมูลไม่ถูกต้องจะคืน
  `Err(reason)` แทนที่จะถูกซ่อมให้
- **แฮนเดิลความลับ** ฟังก์ชันที่สร้างความลับคืน `Ok(handle)` ซึ่งเป็นแฮนเดิลเลขฐานสิบหก 32 ตัว
  `lw_key_drop` ทำลายกุญแจและล้างหน่วยความจำของมัน
- **ฟังก์ชันตรวจสอบไม่ล้มเหลวเสียงดัง** `lw_id_verify`, `lw_ring_verify` และ `lw_pk_valid` คืน `false`
  เมื่อได้รับข้อมูลผิดรูปแบบ

ไม่มีตัวใดมีชื่อแปลตามภาษา

| ฟังก์ชันในตัว | หน้าที่ |
|---|---|
| `lw_h256(domain, parts)` | SHAKE-256 แยกโดเมน ส่งออก 32 ไบต์ `parts` เป็นรายการของสตริงเลขฐานสิบหก |
| `lw_xof(domain, parts, len)` | แบบเดียวกัน ส่งออก `len` ไบต์ |
| `lw_random(n)` | ไบต์สุ่มที่ปลอดภัย `n` ไบต์ (สูงสุด 1 MiB) เป็นเลขฐานสิบหก |

เธรดหลักมีความสามารถทุกอย่าง

### ตัวตน

ตัวตนจะเซ็นภายใต้ป้ายบริบท และผู้ตรวจสอบต้องใช้ป้ายเดียวกัน

```ling

    ผูก ตัวตน = แกะ(lw_id_keypair("0101010101010101010101010101010101010101010101010101010101010101"))
    ผูก กุญแจสาธารณะ = lw_id_public(ตัวตน)
    ผูก ลายเซ็น = lw_id_sign(ตัวตน, "ctx", "68656c6c6f")
    พิมพ์(lw_id_verify(กุญแจสาธารณะ, "ctx", "68656c6c6f", ลายเซ็น))
    พิมพ์(lw_id_verify(กุญแจสาธารณะ, "อื่น", "68656c6c6f", ลายเซ็น))
    พิมพ์(lw_id_fingerprint(กุญแจสาธารณะ))
    พิมพ์(lw_key_drop(ตัวตน))
```


### วลีกู้คืน (BIP-39)

`lw_mnemonic_from` แปลง 32 ไบต์เป็นคำภาษาอังกฤษ 24 คำ `lw_mnemonic_to` รับคำที่คั่นด้วยช่องว่าง
(ตัวพิมพ์ใดก็ได้) และตรวจจำนวนคำ ตัวคำ และผลรวมตรวจสอบ

```ling
ฟังก์ชัน แกะ(r) { คืน จับคู่ r { ok(v) => v, bad(e) => "ผิดพลาด:" + e } }

ผูก เริ่ม = ทำ {
    ผูก เอนโทรปี = "1111111111111111111111111111111111111111111111111111111111111111"
    ผูก คำ = lw_mnemonic_from(เอนโทรปี)
    พิมพ์(ความยาว(คำ))
    พิมพ์(คำ[0] + " " + คำ[1] + " " + คำ[23])
    พิมพ์(แกะ(lw_mnemonic_to(join(คำ, " "))) == เอนโทรปี)
    พิมพ์(แกะ(lw_mnemonic_to("abandon abandon")))
}
```


### ลายเซ็นแบบวงและการพิสูจน์งาน

ลายเซ็นแบบวง LRS-87 (`lw_ring_sign`) ถูกระบุในซอร์สโค้ดว่าเป็นของทดลอง ใช้สำหรับงานวิจัยและต้นแบบ
ไม่ใช่สำหรับทรัพย์สินที่คุณเสียไม่ได้ `lw_pow_hash` จองพื้นที่ทำงาน 16 MiB และช้าโดยตั้งใจ
`lw_meets_difficulty` รับค่าความยากเป็นตัวเลข หรือเป็นสตริงทศนิยมสำหรับค่าที่เกิน 2^53
