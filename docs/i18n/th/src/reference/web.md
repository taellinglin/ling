# เว็บเซิร์ฟเวอร์และ HTTP

Ling มีเว็บเซิร์ฟเวอร์ขนาดเล็กที่เร็วมาให้ คุณลงทะเบียนเส้นทาง โฟลเดอร์สแตติก และโฮสต์เสมือน
แล้วเรียก `http_serve` ซึ่งจะหยุดรออยู่ตรงนั้นและตอบคำขอ ฟังก์ชันในตัวกลุ่ม `http_*`
สั่งงาน [`ling-http`](https://crates.io/crates/ling-http) (axum และ tokio) จากโค้ด Ling
ในกลุ่มเดียวกันยังมีไคลเอนต์ HTTP (`http_get` และพวกพ้อง) และตัวช่วยสำหรับสตริงคิวรี คุกกี้ และการหนีอักขระ

**ling-lang.org ทำงานบนสิ่งนี้** เซิร์ฟเวอร์ของมันคือไฟล์ Ling ไฟล์เดียวชื่อ `site.ling`
ซึ่งให้บริการหน้าแรก เอกสารนี้ใต้ `/docs/` ไฟล์ PDF ของหนังสือ Ling และ SVG ตัวอย่าง
และใช้ `http_vhost` ส่งซับโดเมน `docs.ling-lang.org` ที่เลิกใช้แล้วไปที่ `/docs/`

> **โปรไฟล์การติดตั้ง** ฟังก์ชันในตัวฝั่งเซิร์ฟเวอร์และไคลเอนต์อยู่ในโปรไฟล์ `web`
> (และ `full` ซึ่งเป็นค่าเริ่มต้น) `ling` ที่บิลด์ด้วย `--no-default-features --features core`
> จะหยุดพร้อมข้อความ `unknown function 'http_static'` ให้ติดตั้งใหม่ด้วย `cargo install ling-lang`
> หรือเพิ่ม `--features web`

## ลำดับการตอบคำขอ

1. **โฮสต์เสมือน** (`http_vhost`) มาก่อน ถ้าส่วนหัว `Host` ระบุโฮสต์ที่ลงทะเบียนไว้
   คำขอจะถูกตอบจากโฟลเดอร์ของโฮสต์นั้น หรือถูกเปลี่ยนเส้นทางถ้าเป้าหมายเป็น URL
2. ถัดมาคือ **คำนำหน้าสแตติก** (`http_static`) `/css/style.css` ใต้คำนำหน้า `/css`
   จะถูกอ่านจากดิสก์ตรงตามไบต์
3. สุดท้ายคือ **เส้นทาง** (`http_route`) เลือกจากเมธอดและพาธที่ **ตรงกันทุกตัวอักษร**
   ตัวจัดการคือฟังก์ชัน Ling ที่รับ `Request` แล้วคืนข้อความหรือเรคคอร์ดคำตอบ
4. นอกเหนือจากนี้ได้ `404` พร้อมเนื้อหา `not found`

ขั้นที่ 1 และ 2 ทำงานบนรันไทม์แบบอะซิงโครนัสและไม่แตะอินเทอร์พรีเตอร์เลย ไฟล์ใหญ่
(วิดีโอ PDF zip) จึงส่งพร้อมกันได้และรองรับคำขอแบบช่วงของ HTTP ตัวจัดการของ Ling
ทำงานทีละรายการบนอินเทอร์พรีเตอร์ เว้นแต่คุณส่ง `workers` ให้ `http_serve`

โปรแกรมที่เรียก `http_serve` จะรันบนอินเทอร์พรีเตอร์เสมอ แม้ใช้ `ling run` ธรรมดา
เพราะตัวจัดการเป็นฟังก์ชันที่ส่งเข้าไปเป็นอาร์กิวเมนต์

## ฟังก์ชันในตัวฝั่งเซิร์ฟเวอร์

### `http_route(method, path, handler)`

ลงทะเบียน `handler` ให้ `method` (ไม่สนตัวพิมพ์ใหญ่เล็ก ค่าเริ่มต้น `"GET"`) และ `path`
(ค่าเริ่มต้น `"/"`) พาธต้อง **ตรงกันทุกตัวอักษร** และไม่รวมสตริงคิวรี จึงไม่มีพารามิเตอร์ในพาธ
ให้ใส่ id ไว้ในคิวรี (`/note?id=2`) แล้วอ่านด้วย `query_param(req.query, "id", "")`
ลงทะเบียนเส้นทางทั้งหมดก่อนเรียก `http_serve`

ตัวจัดการที่เกิดข้อผิดพลาดจะตอบ `500` โดยมี `handler error: ...` ในเนื้อหา ซึ่งอาจเผยข้อมูลภายใน
ให้ตรวจสอบข้อมูลเข้าเพื่อไม่ให้ข้อผิดพลาดหลุดออกไป

### `http_static(prefix, dir)`

ให้บริการโฟลเดอร์ `dir` (ค่าเริ่มต้น `"static"`) ที่ `prefix` (ค่าเริ่มต้น `"/static"`)
`http_static("/css", "css")` จับคู่ `/css/a.css` กับ `css/a.css` คำขอที่ชี้ไปที่โฟลเดอร์จะได้
`index.html` ในโฟลเดอร์นั้น ใช้มันกับไฟล์ไบนารีทั้งหมด เพราะตัวจัดการเส้นทางคืนได้แค่ข้อความ

### `http_vhost(host, target)`

กำหนดพฤติกรรมเฉพาะให้ชื่อโฮสต์ทั้งชื่อ `target` เป็นได้ทั้งโฟลเดอร์หรือ URL

- **โฟลเดอร์** ชื่อโฮสต์นั้นจะได้รับบริการจากรากของโฟลเดอร์ ตรงตามไบต์เหมือน `http_static`
  ไฟล์ที่ไม่มีอยู่จะตอบ `404` และใช้ `404.html` ของโฟลเดอร์ถ้ามี (mdBook และตัวสร้างเว็บสแตติก
  ส่วนใหญ่สร้างไฟล์นี้ให้) ใช้เพื่อวางเว็บสแตติกไว้บนซับโดเมนของมันเอง
- **URL แบบ `http://` หรือ `https://`** ทุกคำขอที่มาถึงชื่อโฮสต์นั้นจะได้คำตอบ
  `301 Moved Permanently` ไปยังเป้าหมายต่อด้วยพาธและคิวรีของคำขอ
  ใช้เพื่อเลิกใช้ซับโดเมนโดยไม่ทำให้ลิงก์เก่าเสีย

รายละเอียด

- `host` จะเทียบกับส่วนหัว `Host` แบบไม่สนตัวพิมพ์ใหญ่เล็ก และไม่สนพอร์ต
- โฮสต์เสมือนถูกตรวจก่อนคำนำหน้า `http_static` และเส้นทางทุกตัว คำขอของโฮสต์เสมือนจึงไม่มีวันไปถึงตัวจัดการของคุณ
- ลงทะเบียนโฮสต์เสมือนหลายตัวได้ `Host` หนึ่งค่าจะตรงกับได้อย่างมากหนึ่งตัว

```ling-gui
ผูก เริ่ม = ทำ {
  http_vhost("docs.example.org", "../docs/book")              // เว็บสแตติกที่รากของซับโดเมน
  http_vhost("old.example.org", "https://example.org/docs")   // old.example.org/a.html -> https://example.org/docs/a.html
  เว็บสแตติก("/docs", "../docs/book")                         // เว็บเดียวกันใต้ /docs/ บนโฮสต์หลัก
  เว็บเสิร์ฟ("0.0.0.0", 8080)
}
```

นี่คือวิธีที่ ling-lang.org เลิกใช้ซับโดเมนเอกสารเก่าใน `site.ling`

```ling-module
ฟังก์ชัน ลงทะเบียนโฮสต์เอกสาร(พอร์ต) {
  http_vhost("docs.ling-lang.org", "https://ling-lang.org/docs")
  http_vhost("docs.localhost", "http://localhost:" + str(พอร์ต) + "/docs")
  คืน จริง
}
```

ถ้าอยากลองโฮสต์เสมือนบนเครื่องตัวเองโดยไม่ตั้ง DNS ให้ส่งส่วนหัวเอง

```sh
curl -i -H "Host: docs.localhost" http://127.0.0.1:8080/
```

เบราว์เซอร์ส่วนใหญ่ก็แปลง `*.localhost` เป็นเครื่องของคุณเอง `http://docs.localhost:8080/` จึงใช้ได้เช่นกัน

### `http_serve(host, port, workers)`

เริ่มเซิร์ฟเวอร์และตอบคำขอไปเรื่อยๆ จนกว่าโปรแกรมจะถูกหยุด ไม่มีการคืนค่า

- `host` ใช้ `"127.0.0.1"` (ค่าเริ่มต้น) สำหรับเครื่องนี้เท่านั้น หรือ `"0.0.0.0"` เพื่อรับการเชื่อมต่อจากเครือข่าย
- `port` ค่าเริ่มต้น `8080`
- `workers` ค่าเริ่มต้น `1` ดูหัวข้อ "เวิร์กเกอร์" ด้านล่าง

แบนเนอร์จะพิมพ์ออกมาเมื่อผูกซ็อกเก็ตสำเร็จ ถ้าพอร์ตไม่ว่าง ข้อผิดพลาดจะไปที่เอาต์พุตข้อผิดพลาดมาตรฐาน
และโปรแกรมจะรอต่อไป ถ้าไม่มีอะไรตอบให้ดูบันทึก

### `http_serve_tls(host, port, cert, key, workers)`

ให้บริการ HTTPS โดยตรงโดยไม่ต้องมีรีเวิร์สพร็อกซี `cert` และ `key` เป็น **พาธ** ของไฟล์ PEM
เช่น `fullchain.pem` และ `privkey.pem` ของ Let's Encrypt ให้ไฟล์คีย์อ่านได้เฉพาะผู้ใช้ของเซิร์ฟเวอร์
นอกนั้นทำงานเหมือน `http_serve`

### `http_serve_dev_tls(host, port, workers)`

ให้บริการ HTTPS ด้วยใบรับรองที่เซ็นเองซึ่งสร้างตอนเริ่มทำงาน เบราว์เซอร์และ `curl` จะปฏิเสธ
(บนเครื่องตัวเองใช้ `curl -k`) ใช้สำหรับการพัฒนาในเครื่องเท่านั้น ห้ามเปิดสู่อินเทอร์เน็ต

## คำขอ

ตัวจัดการรับอาร์กิวเมนต์หนึ่งตัว คือเรคคอร์ด `Request` ที่มีฟิลด์ข้อความเหล่านี้

| ฟิลด์ | เนื้อหา |
|---|---|
| `method` | เมธอดตัวพิมพ์ใหญ่ เช่น `GET` |
| `path` | พาธที่ไม่รวมสตริงคิวรี |
| `query` | สตริงคิวรีดิบ ไม่รวม `?` อ่านด้วย `query_param` |
| `body` | เนื้อหาแบบ UTF-8 สูงสุด 32 MiB ยกเว้นการอัปโหลดแบบมัลติพาร์ต (ดูด้านล่าง) |
| `cookie` | ส่วนหัว `Cookie` ดิบ หรือ `""` อ่านด้วย `cookie_get` |
| `authorization` | ส่วนหัว `Authorization` ดิบ หรือ `""` |
| `client_ip` | ค่าแรกของ `X-Forwarded-For` ถ้าไม่มีใช้ `X-Real-IP` ถ้าไม่มีอีกเป็น `""` |

`client_ip` มาจากส่วนหัวที่ไคลเอนต์ไหนก็ตั้งได้ ให้เชื่อถือเฉพาะเมื่ออยู่หลังรีเวิร์สพร็อกซีของคุณเอง
สำหรับการเชื่อมต่อตรงค่านี้จะว่าง

การอัปโหลดแบบ `multipart/form-data` จะสตรีมไฟล์ลงดิสก์ใต้ `storage/tmp/` จากนั้นตัวจัดการ
จะได้เนื้อหาแบบฟอร์มที่มีฟิลด์ข้อความพร้อม `artifact_path` และ `artifact_size`
อ่านด้วย `query_param(req.body, ...)`

## คำตอบ

คืน **ข้อความ** เพื่อตอบ `200` แบบ `text/html; charset=utf-8` ค่าอื่นที่ไม่ใช่เรคคอร์ดจะถูกแปลง
เป็นข้อความและส่งเป็น `text/plain`

กรณีอื่นให้คืนเรคคอร์ดที่มีฟิลด์ใดก็ได้จาก `status` `content_type` `body` `set_cookie` และ `location`
ฟิลด์ที่ขาดไปจะใช้ค่าเริ่มต้นคือสถานะ `200` เนื้อหาว่าง และ `text/html` เรคคอร์ดสร้างตามตำแหน่ง
และสิ่งที่มีผลคือชื่อฟิลด์ ชื่อของเรคคอร์ดเองไม่สำคัญ ชื่อฟิลด์ต้องเป็นภาษาอังกฤษตามเดิม

```ling-gui
โครงสร้าง คำตอบ { status, content_type, body, set_cookie, location }

ฟังก์ชัน สถานะAPI(คำขอ) {
  คืน คำตอบ(200, "application/json", "{\"ok\":true}", "", "")
}

ฟังก์ชัน หน้าเก่า(คำขอ) {
  คืน คำตอบ(301, "text/plain", "", "", "/new")
}

ฟังก์ชัน เข้าสู่ระบบ(คำขอ) {
  ผูก คุกกี้ = "sid=" + random_hex(16) + "; HttpOnly; Secure; SameSite=Lax; Path=/"
  คืน คำตอบ(303, "text/plain", "", คุกกี้, "/me")
}

ผูก เริ่ม = ทำ {
  เว็บเส้นทาง("GET", "/api/status", สถานะAPI)
  เว็บเส้นทาง("GET", "/old", หน้าเก่า)
  เว็บเส้นทาง("POST", "/login", เข้าสู่ระบบ)
  เว็บเสิร์ฟ("127.0.0.1", 8080)
}
```

คำตอบจากเส้นทางของ Ling จะมี `X-Frame-Options: DENY` และ
`Content-Security-Policy: frame-ancestors 'none'` ยกเว้นพาธที่อยู่ใต้ `/embed`
นอกจากนี้ไม่มีการเพิ่มอะไรอีก ให้ตั้ง `Secure` `HttpOnly` และ `SameSite` ของคุกกี้เอง
และเพิ่มส่วนหัวความปลอดภัยอื่นๆ (HSTS นโยบายความปลอดภัยของเนื้อหาแบบเต็ม) ที่รีเวิร์สพร็อกซี

## เวิร์กเกอร์

โดยค่าเริ่มต้น อินเทอร์พรีเตอร์ตัวเดียวตอบทุกคำขอทีละรายการ ตัวจัดการที่ช้าจะทำให้ผู้เข้าชมคนอื่นทุกคนต้องรอ

เมื่อใช้ `http_serve(host, port, N)` โดย `N` มากกว่า 1 อินเทอร์พรีเตอร์ `N` ตัวจะดึงคำขอจากคิวเดียวกัน
ling-lang.org อ่านตัวเลขนี้จากบรรทัดคำสั่ง (`--workers 4`) กฎมีดังนี้

- ตัวจัดการต้องเป็น **ฟังก์ชันระดับบนสุดที่มีชื่อ** ถ้าใช้คลอเชอร์แบบอินไลน์เป็นตัวจัดการ จะเกิดข้อผิดพลาดตอนเริ่มทำงาน
- บล็อก `เริ่ม` ทำงาน **ครั้งเดียว** บนอินเทอร์พรีเตอร์หลัก เวิร์กเกอร์เห็นแค่การประกาศในโปรแกรม
  จึงควรเก็บการตั้งค่าไว้ในฟังก์ชัน ไม่ใช่ในการผูกระดับบนสุดที่ `เริ่ม` เป็นผู้เปลี่ยน
- เวิร์กเกอร์แต่ละตัวเปิดการเชื่อมต่อของตัวเองไปยังฐานข้อมูลของ `db_open`
  ดู[ฐานข้อมูล (SQLite)](../reference/database.md)
- งานอะซิงโครนัสใช้ร่วมกัน งานที่เริ่มบนเวิร์กเกอร์หนึ่งตรวจสถานะจากอีกเวิร์กเกอร์ได้

## ตัวช่วยสำหรับคำขอ

ฟังก์ชันเหล่านี้ใช้ได้ทุกที่ ไม่จำกัดแค่ในตัวจัดการ จึงลองได้โดยไม่ต้องมีหน้าจอ

```ling
ผูก เริ่ม = ทำ {
  ผูก คิวรี = "q=%E0%B8%AA%E0%B8%A7%E0%B8%B1%E0%B8%AA%E0%B8%94%E0%B8%B5&page=2&tag=x+y"
  พิมพ์(พารามิเตอร์(คิวรี, "q", ""))
  พิมพ์(พารามิเตอร์(คิวรี, "page", "1"))
  พิมพ์(พารามิเตอร์(คิวรี, "tag", ""))
  พิมพ์(พารามิเตอร์(คิวรี, "sort", "ล่าสุด"))
  พิมพ์(รับคุกกี้("sid=abc123; theme=dark", "theme", "light"))
  พิมพ์(กันเอชทีเอ็มแอล("<b>เอดา & 'บ็อบ'</b>"))
  พิมพ์("{\"ชื่อ\":\"" + หนีเจสัน("เขาพูดว่า \"สวัสดี\"\n") + "\"}")
  พิมพ์(url_decode("a%20b+c%41"))
  พิมพ์(อาร์กิวเมนต์("port", "8080"))
}
```

```output
สวัสดี
2
x y
ล่าสุด
dark
&lt;b&gt;เอดา &amp; &#39;บ็อบ&#39;&lt;/b&gt;
{"ชื่อ":"เขาพูดว่า \"สวัสดี\"\n"}
a b cA
8080
```

- `query_param(qs, name, default)` (`พารามิเตอร์`) คืนค่าแรกของ `name` โดยถอดรหัส `%XX` และ `+`
  ใช้ได้กับ `req.query` และเนื้อหาฟอร์ม (`req.body`)
- `cookie_get(header, name, default)` (`รับคุกกี้`) คืนคุกกี้หนึ่งตัวจาก `req.cookie` โดยไม่ถอดรหัส
- `html_escape(text)` (`กันเอชทีเอ็มแอล`) หนีอักขระของทุกค่าที่ไม่น่าเชื่อถือ ณ จุดที่คุณประกอบ HTML
  เพียงพอสำหรับเนื้อหาในอิลิเมนต์และค่าแอตทริบิวต์ที่มีเครื่องหมายคำพูด แต่ไม่พอภายใน `<script>`
  หรือแอตทริบิวต์ที่ไม่มีเครื่องหมายคำพูด
- `json_escape(text)` (`หนีเจสัน`) หนี `"` `\` และอักขระควบคุม โดยไม่เติมเครื่องหมายคำพูดหัวท้าย
  Ling สร้าง JSON ด้วยการต่อสตริง จึงต้องส่งข้อความผ่านฟังก์ชันนี้เสมอ
- `url_decode(text)` ถอดรหัส `%XX` และ `+`
- `cli_arg(name, default)` (`อาร์กิวเมนต์`) คืน `--name value` จากบรรทัดคำสั่งเป็น **ข้อความ**
  แปลงด้วย `to_number` เพราะ `cli_arg("port", "8080") + 0` จะได้ `"80800"`
- `env_get(name, default)` (`รับตัวแปรแวดล้อม`) ตัวแปรสภาพแวดล้อม ควรโหลดความลับด้วยวิธีนี้ ไม่ใช่เขียนไว้ในซอร์ส

## ไคลเอนต์ HTTP

### `http_get(url)` และ `http_get_status()`

`http_get` (`เว็บรับ`) ดึง URL แบบ `http://` หรือ `https://` และรอเนื้อหา มันคืนเนื้อหาแม้สถานะจะเป็นข้อผิดพลาด
`http_get_status()` ให้สถานะของ `http_get` ครั้งล่าสุด `0` หมายถึงไม่มีคำตอบเลย (DNS การเชื่อมต่อ หรือ TLS ล้มเหลว)
และตอนนั้นเนื้อหาจะเป็น `""` ให้ตรวจสถานะก่อนเชื่อเนื้อหา

`http_get` หยุดรอจนเสร็จ ใช้ในเครื่องมือหรือตอนเริ่มทำงานได้ แต่ในตัวจัดการมันจะทำให้ผู้เข้าชมทุกคนค้าง
ที่นั่นจึงควรใช้เวอร์ชันอะซิงโครนัส

### `http_get_all(urls)`

ดึงรายการ URL พร้อมกันและรอจนครบทุกตัว คืนเนื้อหาตามลำดับเดิม โดยเป็น `""` สำหรับความล้มเหลวหรือสถานะข้อผิดพลาดของ HTTP

### `http_get_async(url)` `http_post_async(url, body, type)` และ `http_job_poll(id)`

เริ่มคำขอเบื้องหลังและคืน id งานทันที `type` คือ `Content-Type` ของเนื้อหา POST
(ค่าเริ่มต้น `"application/json"`) จากนั้นเรียก `http_job_poll(id)` (`เว็บงานสำรวจ`) ทีหลัง
มันคืน `""` ระหว่างที่งานยังทำ แล้วคืนเนื้อหาคำตอบเมื่อเสร็จ GET ที่ล้มเหลวจะได้ข้อความขึ้นต้นด้วย `ERROR:`
ส่วน POST ที่ล้มเหลวจะได้ `{"error":"..."}`

```ling-gui
ผูก เริ่ม = ทำ {
  ผูก งาน = http_get_async("https://ling-lang.org/api/books.json")
  ผูก เนื้อหา = ""
  ผูก จำนวนครั้ง = 0
  ขณะที่ เนื้อหา == "" && จำนวนครั้ง < 100 {
    ผูก เนื้อหา = เว็บงานสำรวจ(งาน)
    นอน(50)
    ผูก จำนวนครั้ง = จำนวนครั้ง + 1
  }
  พิมพ์(เนื้อหา)
}
```

## ตัวอย่างเต็ม: เว็บไซต์เล็กๆ

```ling-gui
โครงสร้าง คำตอบ { status, content_type, body, set_cookie, location }

ฟังก์ชัน หน้าแรก(คำขอ) {
  คืน อ่านไฟล์("index.html")
}

ฟังก์ชัน ทักทายAPI(คำขอ) {
  ผูก ชื่อ = พารามิเตอร์(คำขอ.query, "name", "โลก")
  คืน คำตอบ(200, "application/json", "{\"hello\":\"" + หนีเจสัน(ชื่อ) + "\"}", "", "")
}

ผูก เริ่ม = ทำ {
  เว็บสแตติก("/css", "css")
  เว็บสแตติก("/images", "images")
  เว็บเส้นทาง("GET", "/", หน้าแรก)
  เว็บเส้นทาง("GET", "/api/hello", ทักทายAPI)
  เว็บเสิร์ฟ(อาร์กิวเมนต์("host", "127.0.0.1"), to_number(อาร์กิวเมนต์("port", "8080")), 4)
}
```

รันด้วย `ling run site.ling --port 8080` แล้วเปิด `http://127.0.0.1:8080/`
หรือ `http://127.0.0.1:8080/api/hello?name=Ada`
