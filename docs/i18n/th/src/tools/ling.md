# คำสั่ง ling

`ling` ใช้รัน บิลด์ วาด และแปลงโปรแกรม Ling หน้านี้รวบรวมคำสั่งย่อยและตัวเลือกทั้งหมด
ถ้าต้องการบทนำแบบง่ายกว่า ให้เริ่มที่[การรันโปรแกรม](../getting-started/running.md)

```text
ling run [--interp|--wasm|--O0|--O1|--O2|--O3] <file.ling>
ling <file.ling>                       (shorthand for: ling run <file.ling>)
ling build <file.ling|dir> [--out dir] [--platform list] [--icon file] [--pack] [--aot]
ling ast [path] [--technical|--artwork|--ling|--all] [--out dir]
ling visualize <file.ling>
ling convert <asset> [-o out.ling] [--no-compression]
```

| คำสั่งย่อย | หน้าที่ |
|---|---|
| `run` | รันโปรแกรม (ใช้ JIT เป็นค่าเริ่มต้น) |
| `build` | คอมไพล์ไฟล์หรือโปรเจกต์ให้เป็นสิ่งที่แจกจ่ายได้ สำหรับหนึ่งแพลตฟอร์มหรือมากกว่า |
| `ast` | วาดต้นไม้ไวยากรณ์ของไฟล์หรือโปรเจกต์เป็นไฟล์ SVG |
| `visualize` | เขียน SVG หนึ่งภาพของต้นไม้ไวยากรณ์ออกทางเอาต์พุตมาตรฐาน |
| `convert` | แปลงแอสเซต (โมเดล เสียง MIDI SVG) เป็นไฟล์ `.ling` ที่นำเข้าได้ |

ถ้ารัน `ling` โดยไม่มีอาร์กิวเมนต์ หรือใส่สิ่งที่มันไม่รู้จัก มันจะพิมพ์ข้อความวิธีใช้แล้วจบด้วยสถานะ 0
บรรทัดแรกบอกเวอร์ชัน ไม่มีตัวเลือก `--version` หรือ `--help` และไม่มีคำสั่งย่อย `check`, `fmt`, `translate` หรือ `test`

ไฟล์ซอร์สใช้นามสกุล `.ling`, `.灵`, `.霊`, `.령` หรือ `.ลิง` ก็ได้

### `ling run`

แจงไวยากรณ์ไฟล์ หาจุดเริ่มต้น แล้วรัน

| ตัวเลือก | ผล |
|---|---|
| *(ไม่มี)* | Cranelift JIT ซึ่งเป็นค่าเริ่มต้น ถ้า JIT คอมไพล์ไม่ได้ จะให้อินเทอร์พรีเตอร์รันทั้งโปรแกรมแทน |
| `--interp` | อินเทอร์พรีเตอร์แบบไล่ต้นไม้ เป็นมาตรฐานอ้างอิงด้านความหมาย และให้ข้อความแจ้งข้อผิดพลาดดีที่สุด |
| `--wasm` (หรือ `--web`) | บิลด์โปรแกรมเป็น WebAssembly เปิดให้บริการในเครื่อง แล้วเปิดเบราว์เซอร์ ต้องมี `lingc` อยู่ข้าง `ling` |
| `--O0` `--O1` `--O2` `--O3` | ระดับการปรับแต่งของ JIT (ค่าเริ่มต้น `--O3`) ลดลงได้ถ้าโปรแกรมใหญ่มากคอมไพล์ช้า |

ตัวเลือกวางไว้ก่อนหรือหลังชื่อไฟล์ก็ได้ อาร์กิวเมนต์แรกที่มีนามสกุลของ Ling คือโปรแกรม
อาร์กิวเมนต์ที่ตามหลังจะเหลือไว้ให้โปรแกรมอ่านด้วย `get_args()` และ `cli_arg(name, default)`

สิ่งที่ควรรู้:

- โปรแกรมที่เรียก `http_serve` หรือ `lingtp_serve` (หรือชื่อแปลอย่าง `เว็บเสิร์ฟ`) จะรันบนอินเทอร์พรีเตอร์โดยอัตโนมัติ
  เพราะ JIT ยังไม่รองรับอาร์กิวเมนต์ที่เป็นโคลเชอร์ แบบย่อ `ling file.ling` ไม่ได้ตรวจเรื่องนี้ จึงควรใช้ `ling run` กับเซิร์ฟเวอร์
- บน JIT ฟังก์ชันที่ไม่รู้จักจะคืน `()` อย่างเงียบ ๆ ส่วนอินเทอร์พรีเตอร์จะแจ้ง `unknown function`
  ดู[ข้อจำกัดที่ทราบ](../language/limits.md)
- ไฟล์ที่ไม่มีจุดเริ่มต้นจะถือเป็นไลบรารี และล้มเหลวด้วย `error[runtime]: no entry point`
- สำหรับไฟล์ซอร์สภาษาอื่น `ling` จะพิมพ์ `[detected language: ...]` ทางเอาต์พุตข้อผิดพลาดมาตรฐานก่อนรัน
- ถ้าไม่พบไฟล์ จะพิมพ์ `[ling] error: file does not exist: <path>` ข้อผิดพลาดด้านไวยากรณ์คือ `error[parse]: ...`
  ข้อผิดพลาดขณะรันคือ `error[runtime]: ...` พร้อมลำดับการเรียก ทุกกรณีจบด้วยสถานะ 1

### `ling build`

คอมไพล์โปรแกรมหรือโปรเจกต์ให้เป็นสิ่งที่แจกจ่ายได้

| ตัวเลือก | ความหมาย |
|---|---|
| `<target>` | ไฟล์ `.ling` หรือไดเรกทอรี (ค่าเริ่มต้น `.`) ไดเรกทอรีจะอ่านผ่านแมนิเฟสต์ (`灵符.toml`, `ลิงฟู.toml` แล้วจึง `Ling.toml`) ถ้าไม่มี `ling` จะหา `main.ling`, `start.ling`, `启.灵`, `เริ่ม.ลิง` โฟลเดอร์ `src` หรือไฟล์ `.ling` ใดก็ได้ |
| `--out <dir>` | โฟลเดอร์ผลลัพธ์ ค่าเริ่มต้น `dist` แต่ละแพลตฟอร์มอยู่ในโฟลเดอร์ย่อย เช่น `dist/web` หรือ `dist/windows` |
| `--platform <list>` | เป้าหมายคั่นด้วยจุลภาค ดูตารางด้านล่าง `all` หมายถึง `win,lin,mac,web` |
| `--icon <file>` | ไอคอนแอป (`.svg`, `.png`, `.jpg`, `.bmp`, `.ico`) ใช้แทน `icon` ในแมนิเฟสต์ |
| `--pack` | ฝังทรัพยากรใน `[includes]` และตัวโปรแกรมไว้ในไฟล์โปรแกรม ให้เป็นไฟล์เดียวที่ใช้ได้ทันที |
| `--aot` | คอมไพล์ล่วงหน้าเป็นโค้ดเครื่องแทนการฝังอินเทอร์พรีเตอร์ |

| แพลตฟอร์ม | ชื่ออื่น | ผลลัพธ์ |
|---|---|---|
| `web` | | ชุดไฟล์ WebGL/WebAssembly บิลด์โดย `lingc` |
| `win` | `windows` | ไฟล์โปรแกรม Windows |
| `lin` | `linux` | ไฟล์โปรแกรม Linux |
| `mac` | `macos`, `darwin` | ไฟล์โปรแกรม macOS (Intel) |
| `macarm` | `mac-arm`, `mac-arm64`, `macos-arm64`, `apple-silicon` | ไฟล์โปรแกรม macOS (Apple Silicon) |
| `pios` | `pi`, `raspios`, `linux-arm64`, `linarm`, `arm64` | Raspberry Pi OS / Linux ARM 64 บิต |
| `kernel` | `bare` | อิมเมจเคอร์เนล LingOS แบบ bare-metal (โปรไฟล์ `os`) |
| `rpi` | `raspberrypi` | อิมเมจ LingOS สำหรับ Raspberry Pi (โปรไฟล์ `os`) |
| `lingos` | `app`, `apps` | แอป userland ของ LingOS (โปรไฟล์ `os`) |
| `lingos-rpi` | `apps-rpi`, `app-rpi` | แอป userland ของ LingOS สำหรับ Raspberry Pi (โปรไฟล์ `os`) |

ถ้าไม่ใส่ `--platform` การบิลด์จะใช้ `targets` ในแมนิเฟสต์ หรือถ้าไม่มีก็ใช้แพลตฟอร์มเครื่องนี้กับ `web`
เมื่อรายการมาจากแมนิเฟสต์ เป้าหมายเดสก์ท็อปที่เครื่องนี้บิลด์ไม่ได้ (และไม่ได้ติดตั้ง `cross`) จะถูกข้ามพร้อมข้อความแจ้ง
แต่ถ้าระบุ `--platform` เอง จะล้มเหลวแทน

เป้าหมายเนทีฟจะสร้างและคอมไพล์โปรเจกต์ Rust ขนาดเล็ก จึง**ต้องติดตั้งชุดเครื่องมือ Rust**
และการบิลด์ครั้งแรกอาจใช้เวลาหลายนาที

#### คีย์ในแมนิเฟสต์

`ling build` อ่านแมนิเฟสต์ทีละบรรทัด ไม่ได้ใช้ตัวแจง TOML เต็มรูปแบบ ให้เขียนแต่ละค่าในบรรทัดเดียวแบบ
`key = value` และเขียนอาร์เรย์ให้อยู่ในบรรทัดเดียว

| คีย์ | ความหมาย |
|---|---|
| `name` | ชื่อโปรเจกต์ ใช้เป็นชื่อไฟล์โปรแกรม |
| `version` | สตริงเวอร์ชัน ค่าเริ่มต้น `0.1.0` |
| `entry` | โปรแกรมจุดเริ่มต้น เทียบจากตำแหน่งแมนิเฟสต์ ค่าเริ่มต้น `main.ling` |
| `kind` | `bin` (ค่าเริ่มต้น), `web`, `game`, `ui`, `ai`, `crypto`, `lib`, `polyglot`, `kernel` |
| `icon` | ไฟล์ไอคอน |
| `targets` | แพลตฟอร์มเริ่มต้น เช่น `targets = ["win", "lin", "web"]` |
| `pack` | `pack = true` มีผลเหมือน `--pack` |
| `includes` | แพตเทิร์นของทรัพยากร หรือส่วน `[includes]` ที่มีแพตเทิร์นในเครื่องหมายคำพูดบรรทัดละหนึ่งรายการ `*` จับคู่ภายในโฟลเดอร์ `**` จับคู่ข้ามโฟลเดอร์ |
| `ling-features` | ฟีเจอร์ Cargo ของ `ling` ที่จะเปิดในไฟล์โปรแกรม เช่น `["web"]` สำหรับโปรแกรมที่ใช้ `db_*` |

```toml
# Ling.toml
[project]
name = "my-game"
version = "1.0.0"
entry = "main.ling"
icon = "images/logo.svg"
targets = ["win", "lin", "web"]
pack = true

[includes]
"/music/*.wav"
"/font/*.otf"
"/levels/**/*.json"
```

ไฟล์ที่รวมไว้จะถูกคัดลอกไปไว้ข้างไฟล์โปรแกรมตามโครงสร้างเดิม หรือถูกฝังไว้เมื่อใช้ `--pack`
ฟังก์ชันในตัวด้านไฟล์อย่าง `read_file` ทำงานได้เหมือนกันทั้งสองแบบ

### `ling ast`

วาดต้นไม้ไวยากรณ์ของไฟล์หรือทั้งโปรเจกต์เป็น SVG ไดเรกทอรีจะถูกไล่ดูทุกชั้น (ข้ามโฟลเดอร์ที่ซ่อนไว้ `target`, `dist`,
`node_modules`, `AST` และ `灵碑`) และถือเป็นโปรแกรมเดียว

| ตัวเลือก | ความหมาย |
|---|---|
| `[path]` | ไฟล์หรือไดเรกทอรี ค่าเริ่มต้น `.` |
| `--technical`, `--artwork`, `--ling` | เลือกรูปแบบการวาดหนึ่งแบบหรือมากกว่า ถ้าไม่เลือกเลยจะได้ทั้งสามแบบ |
| `--all` | ทั้งสามรูปแบบ |
| `--out <dir>` | โฟลเดอร์ผลลัพธ์ ค่าเริ่มต้น `AST` |

```text
$ ling ast hello.ling
ling ast: 'hello' — 1 file(s), 0 fn(s)
  ✓ AST\hello.technical.svg
  ✓ AST\hello.artwork.svg
  ✓ AST\hello.ling.svg
```

### `ling visualize`

เขียนภาพ SVG หนึ่งภาพของต้นไม้ไวยากรณ์ออกทางเอาต์พุตมาตรฐาน ให้เปลี่ยนทิศทางไปเก็บเป็นไฟล์:

```sh
ling visualize hello.ling > hello.svg
```

คำสั่งนี้แค่แจงไวยากรณ์ไฟล์ จึงใช้ตรวจอย่างรวดเร็วได้ด้วยว่าโปรแกรมแจงไวยากรณ์ผ่านหรือไม่

### `ling convert`

แปลงแอสเซตเป็นไฟล์ `.ling` ที่นำเข้าด้วย `ใช้` ได้ ดู[การแปลงแอสเซต](convert.md)

```sh
ling convert model.glb -o model.ling
```
