# 모듈과 프로젝트

프로그램이 한 파일에 담기지 않을 만큼 커지면 함수를 라이브러리 파일로 옮기고 `사용`(`use`)으로
불러오십시오. 이 페이지는 `사용`, `모듈`(`mod`) 블록, 이름이 충돌할 때 일어나는 일, 그리고
`lingfu`로 프로젝트를 구성하는 방법을 설명합니다.

Ling의 모듈 시스템은 작습니다. `사용`은 파일을 하나의 공유 네임스페이스로 불러오며, 비공개로 만들
수 있는 것은 없습니다. 아래에 소개하는 몇 가지 이름 짓기 습관을 지키면 편하게 쓸 수 있습니다.

| 형태 | 하는 일 |
|---|---|
| `사용 "lib/파일.ling"` | 파일을 불러옵니다. 그 함수, 타입, 최상위 바인딩을 이름만으로 쓸 수 있게 됩니다 |
| `사용 "lib/파일.ling" 로서 m` | 파일을 불러옵니다. 그 함수는 `m::이름()`으로 호출합니다 |
| `모듈 이름 { 함수 f() { ... } }` | 한 파일 안에서 함수를 묶습니다. `이름::f()`로 호출합니다 |

## 사용: 다른 파일 불러오기

`사용 "경로"`는 다른 `.ling` 파일을 불러옵니다. 경로는 텍스트이며, `ling`을 실행한 폴더가 아니라
**그 `사용`이 들어 있는 파일을 기준으로** 해석됩니다. `.ling` 확장자는 생략할 수 있습니다.

불러온 파일의 모든 것을 쓸 수 있게 됩니다. 함수, `구조`와 `선택` 타입, 최상위 `바인드` 값입니다.
불러온 파일도 다른 파일을 `사용`할 수 있으며, 그 경로는 그 파일 자신의 위치를 기준으로 합니다.

**`lib/textkit.ling`**

```ling-module
// textkit: 작은 텍스트 도우미
함수 tk_왼쪽채움(텍스트, 너비) {
  바인드 여백 = 너비 - 길이(텍스트)
  만약 여백 > 0 { str_repeat(" ", 여백) + 텍스트 } 아니면 { 텍스트 }
}
함수 tk_줄(너비) { str_repeat("-", 너비) }
```

**`lib/report.ling`**은 자기와 같은 폴더에서 `textkit.ling`을 불러옵니다.

```ling-module
사용 "textkit.ling"
구조 품목 { 이름, 수량, }
함수 rp_행(항목) { 항목.이름 + tk_왼쪽채움(str(항목.수량), 6) }
```

**`main.ling`**

```ling-module
사용 "lib/report.ling"
바인드 시작 = 실행 {
  출력(rp_행(품목("차", 3)))
  출력(rp_행(품목("잼", 12)))
  출력(tk_줄(9))
}
```

```sh
$ ling run main.ling
차     3
잼    12
---------
```

`main.ling`은 `textkit.ling`을 직접 불러오지 않았지만 `tk_줄`이 보입니다. 불러온 파일은 모두 하나의
네임스페이스를 공유하기 때문입니다.

### 사용 ... 로서

`로서`(`as`)를 붙이면 불러온 파일의 함수는 별칭을 통해 호출합니다. 이때는 이름만으로는 쓸 수
**없습니다**.

```ling-module
사용 "lib/textkit.ling" 로서 tk
바인드 시작 = 실행 {
  출력(tk::tk_줄(5))
}
```

```sh
$ ling run alias.ling
-----
```

## 이름 충돌

불러온 이름은 모두 하나의 네임스페이스를 공유하며, 두 정의가 충돌해도 오류나 경고가 없습니다.

- 불러온 두 파일이 같은 이름의 함수를 정의하면 **마지막에** 불러온 것이 쓰입니다. 먼저 불러온 파일
  안에서 호출해도 마찬가지입니다.
- 메인 파일의 정의는 불러온 어떤 정의보다도 우선합니다.

`lib/first.ling`에 `함수 누구() { "첫째" }`가, `lib/second.ling`에 `함수 누구() { "둘째" }`가
있다고 합시다.

```ling-module
사용 "lib/first.ling"
사용 "lib/second.ling"
바인드 시작 = 실행 {
  출력(누구())
}
```

```sh
$ ling run clash.ling
둘째
```

메인 파일에 `함수 누구() { "메인 파일" }`을 더하면 대신 `메인 파일`이 출력됩니다.

같은 규칙이 진입점에도 적용됩니다. 라이브러리가 `start`를 바인딩하고 메인 파일의 `start`보다 나중에
불러와지면, 라이브러리의 `start`가 실행됩니다. 그러므로

- **라이브러리마다 짧은 접두사를 정하고**(`tk_`, `rp_`) 모든 함수에 붙이십시오.
- **라이브러리에는 진입점 바인딩을 절대 두지 마십시오.** 진입점은 메인 프로그램에만 있습니다.
- **데이터는 매개변수로 넘기십시오.** 라이브러리 함수는 최상위 바인딩은 보지만, 호출한 쪽의 지역
  바인딩은 절대 보지 못합니다.

## 모듈: 파일 안의 네임스페이스

`모듈 이름 { ... }`은 함수를 한 이름 아래로 묶고 `::`로 접근하게 합니다. 여러 묶음이 같은 함수
이름을 필요로 할 때 유용합니다.

```ling
모듈 벡터 {
  함수 더하기(a, b) { [a[0] + b[0], a[1] + b[1]] }
  함수 내적(a, b) { a[0] * b[0] + a[1] * b[1] }
  함수 길이제곱(a) { 벡터::내적(a, a) }
}
모듈 금액 {
  함수 더하기(a, b) { 반올림((a + b) * 100) / 100 }
}
바인드 시작 = 실행 {
  출력(벡터::더하기([1, 2], [3, 4]))
  출력(벡터::길이제곱([3, 4]))
  출력(금액::더하기(0.1, 0.2))
}
```
```output
[4, 6]
25
0.3
```

`모듈`의 규칙:

- **같은 모듈의 함수는 한정된 이름으로 호출하십시오**(`벡터::내적`). `길이제곱`이 그 예입니다.
  `내적(a, a)`만 쓰면 인터프리터에서는 실패하고 JIT에서는 `()`가 됩니다.
- `모듈` 안의 함수는 파일의 최상위 함수를 접두사 없이 호출할 수 있습니다.
- **`모듈` 안에서 값을 바인딩하지 마십시오.** `벡터::원점`은 JIT에서는 `()`, 인터프리터에서는
  텍스트 `벡터::원점`이 되며, 모듈 자신의 함수도 그 값을 보지 못합니다. 상수는 함수로 내보내십시오:
  `함수 원점() { [0, 0] }`으로 만들고 `벡터::원점()`으로 호출합니다.

## lingfu로 만드는 프로젝트

`lingfu new <이름>`은 프로젝트 폴더를 만듭니다.

```sh
$ lingfu new shop
~ Ling Manifest — Spirit Token Descends ~
Creating project: shop

✓ Spirit Realm created!
  cd shop
  lingfu build
  lingfu run
```

```text
shop/
  Ling.toml          매니페스트
  README.md
  ling.ignore
  lexicons/en.ling   언어 데이터(건드리지 마십시오)
  src/start.ling     진입점
  tests/test.ling    시작용 테스트
```

라이브러리는 `src/` 아래, 예를 들어 `src/lib/textkit.ling`에 두고, `src/start.ling`에서
`사용 "lib/textkit.ling"`으로 불러오십시오.

| 명령 | 하는 일 |
|---|---|
| `lingfu run` | `src/start.ling`을 실행합니다 |
| `lingfu test` | `tests/`의 모든 `.ling` 파일을 실행합니다 |
| `lingfu build` | 배포용 프로그램을 만듭니다(아래 `entry` 줄이 필요합니다) |

### 프로젝트의 진입점

- **프로그램**은 `src/start.ling`이며, 진입점 바인딩을 가집니다.
- `tests/`의 **테스트**도 프로그램입니다. 아무 이름이나 `실행` 블록에 바인딩하고(시작용 테스트는
  `bind test = do { ... }`를 씁니다), 테스트할 코드를 자기 위치 기준의 경로로 불러옵니다. 예를 들어
  `사용 "../src/lib/textkit.ling"`입니다. `tests/`의 모든 파일에는 진입점이 있어야 하며, 진입점이
  없는 도우미 파일은 `no entry point`로 실패합니다.
- **라이브러리**에는 진입점 바인딩이 전혀 없습니다.

### 매니페스트

`Ling.toml`은 자동으로 만들어집니다. `lingfu run`과 `lingfu test`는 그대로 동작하지만, 매니페스트에
진입 파일이 적혀 있지 않으면 `lingfu build`는 `main.ling`을 찾습니다. `[spirit]` 섹션에 `entry`
줄을 더하십시오.

```toml
[spirit]
name = "shop"
kind = "bin"
version = "2030.0.0"
entry = "src/start.ling"
```

모든 명령은 [lingfu](../tools/lingfu.md)를, 현재 도구의 특이한 동작은
[알려진 제한 사항](limits.md#도구)을 참고하십시오.
