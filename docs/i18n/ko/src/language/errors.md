# 오류와 결과

Ling에는 예외가 없습니다. 실패할 수 있는 함수는 **결과**를 돌려줍니다. 잘되면 `좋아(값)`, 안 되면
`나쁨(이유)`입니다. 호출한 쪽은 `매치`로 결과를 엽니다. 이 페이지는 결과, `시도` 내장 함수, 런타임
오류와 트레이스백, 그리고 대부분의 내장 함수가 따르는 "부드러운 실패" 규칙을 설명합니다.

| 도구 | 용도 |
|---|---|
| `좋아(값)` / `나쁨(이유)` | 직접 만든 함수에서 성공이나 실패를 돌려줄 때 |
| `매치 r { 좋아(v) => ..., 나쁨(e) => ... }` | 두 경우를 모두 처리할 때 |
| `시도(f, 인수...)` | 런타임 오류를 `나쁨` 결과로 바꿀 때(인터프리터 전용) |
| `ling run --interp` | 런타임 오류를 트레이스백과 함께 볼 때 |

## 결과: 좋아와 나쁨

`좋아(값)`은 성공한 값을, `나쁨(이유)`는 실패를 감쌉니다. 이유는 보통 텍스트지만 어떤 값이든
됩니다. 결과는 `Ok(...)` 또는 `Err(...)`로 출력됩니다. (결과를 만들 때는 `err`도 `나쁨`의 다른
이름으로 쓸 수 있지만, 패턴에는 `나쁨`을 써야 합니다.)

```ling
함수 안전한나눗셈(a, b) {
  만약 b == 0 { 나쁨("0으로 나눔") } 아니면 { 좋아(a / b) }
}
바인드 시작 = 실행 {
  출력(안전한나눗셈(6, 3))
  출력(안전한나눗셈(1, 0))
}
```
```output
Ok(2)
Err(0으로 나눔)
```

## 매치로 결과 처리하기

`좋아(v)`와 `나쁨(e)`는 패턴이기도 합니다. 괄호 안의 이름은 그 갈래 안에서 감싸인 값에
바인딩됩니다.

```ling
함수 안전한나눗셈(a, b) {
  만약 b == 0 { 나쁨("0으로 나눔") } 아니면 { 좋아(a / b) }
}
함수 보여주기(r) {
  매치 r {
    좋아(v) => "값 " + str(v),
    나쁨(이유) => "실패: " + 이유
  }
}
바인드 시작 = 실행 {
  출력(보여주기(안전한나눗셈(8, 2)))
  출력(보여주기(안전한나눗셈(8, 0)))
}
```
```output
값 4
실패: 0으로 나눔
```

결과 안을 들여다보는 방법은 `매치`뿐이므로, 작은 도우미 함수를 만들어 두면 좋습니다.

```ling
함수 값또는(r, 기본값) {
  매치 r {
    좋아(v) => v,
    _ => 기본값
  }
}
함수 안전한제곱근(x) {
  만약 x < 0 { 나쁨("음수") } 아니면 { 좋아(제곱근(x)) }
}
바인드 시작 = 실행 {
  출력(값또는(안전한제곱근(16), 0))
  출력(값또는(안전한제곱근(-16), 0))
}
```
```output
4
0
```

> 결과에 메서드를 호출하면 감싸인 값이 돌아옵니다(`좋아(5).anything`은 `5`). 대개 원하는 동작이
> 아닙니다. `매치`를 쓰십시오.

## 입력 검증

규칙을 하나씩 확인하고, 실패마다 각각의 이유를 돌려줍니다.

```ling
함수 나이해석(텍스트) {
  바인드 t = trim(텍스트)
  만약 길이(t) == 0 {
    나쁨("입력이 비어 있음")
  } 아니면 만약 to_number(t) == 0 && t != "0" {
    나쁨("숫자가 아님: " + t)
  } 아니면 만약 to_number(t) > 130 {
    나쁨("너무 큼: " + t)
  } 아니면 {
    좋아(to_number(t))
  }
}
함수 보여주기(r) {
  매치 r {
    좋아(v) => "나이 " + str(v),
    나쁨(이유) => "거부 (" + 이유 + ")"
  }
}
바인드 시작 = 실행 {
  위해 s 안에 ["42", " 7 ", "", "마흔", "200"] {
    출력(보여주기(나이해석(s)))
  }
}
```
```output
나이 42
나이 7
거부 (입력이 비어 있음)
거부 (숫자가 아님: 마흔)
거부 (너무 큼: 200)
```

한 단계가 다른 단계에 의존할 때는 `매치`를 중첩하고 각 `나쁨`에 맥락을 덧붙이십시오. 그러면 최종
메시지가 어디서 잘못되었는지 알려 줍니다.

```ling
함수 숫자해석(텍스트) {
  바인드 n = to_number(텍스트)
  만약 n == 0 && 텍스트 != "0" { 나쁨("숫자가 아님: " + 텍스트) } 아니면 { 좋아(n) }
}
함수 넓이(너비텍스트, 높이텍스트) {
  매치 숫자해석(너비텍스트) {
    나쁨(e) => 나쁨("너비: " + e),
    좋아(w) => 매치 숫자해석(높이텍스트) {
      나쁨(e) => 나쁨("높이: " + e),
      좋아(h) => 좋아(w * h)
    }
  }
}
바인드 시작 = 실행 {
  출력(넓이("4", "2.5"))
  출력(넓이("4", "x"))
}
```
```output
Ok(10)
Err(높이: 숫자가 아님: x)
```

## 런타임 오류와 트레이스백

어떤 문제는 **런타임 오류**로 프로그램을 멈춥니다. 알 수 없는 함수 호출, 없는 파일 읽기, 리스트
끝을 넘는 인덱스, 필드 수가 맞지 않는 생성자 등입니다. 인터프리터는 오류, 파일 이름, 그리고 가장
깊은 호출을 마지막에 둔 트레이스백을 출력합니다.

```ling-module
함수 읽기(경로) { read_file(경로) }
함수 진행() { 읽기("no_such_file.txt") }
바인드 시작 = 실행 {
  출력(진행())
}
```

```sh
$ ling run --interp broken.ling
[detected language: Korean (한국어)]
error[runtime]: read_file 'no_such_file.txt': The system cannot find the file specified. (os error 2)
 --> broken.ling
  traceback (deepest call last):
    0: start
    1: 진행
    2: 읽기
```

프로그램은 0이 아닌 종료 코드로 멈춥니다. (콜론 뒤의 OS 메시지는 시스템에 따라 다릅니다.)

> **JIT는 멈추지 않습니다.** 기본 엔진에서는 이런 문제 대부분이 조용히 `()`가 되고 프로그램은 계속
> 실행됩니다. 위 프로그램은 `ling run`에서 `()`를 출력합니다. 프로그램이 이상하게 동작하면
> `ling run --interp`로 한 번 실행해서 진짜 오류를 확인하십시오.

Ling에는 `assert`, `panic`, `exit` 내장 함수가 없습니다. 실패를 알리려면 `나쁨` 결과를 돌려주고
분명한 메시지를 출력하십시오.

## 시도: 런타임 오류 잡기

`시도(f, 인수...)`(`try`)는 주어진 인수로 `f`를 호출합니다. 호출이 성공하면 `좋아(결과)`를, 런타임
오류가 나면 `나쁨(메시지)`를 돌려줍니다. 넘기는 것은 함수 자체(괄호 없는 이름)이고, 그 뒤에 인수를
씁니다. 클로저도 됩니다: `시도(| | 6 * 7)`.

**`시도`는 인터프리터에서만 동작합니다.** JIT는 함수를 내장 함수에 넘길 수 없어서, JIT에서 `시도`는
항상 `나쁨("try: first argument must be a function")`을 돌려줍니다.

```ling
함수 하나더(x) { x + 1 }
함수 고장(x) { 없는함수(x) }
바인드 시작 = 실행 {
  출력(시도(하나더, 4))
  출력(시도(고장, 4))
}
```
```output
Err(try: first argument must be a function)
Err(try: first argument must be a function)
```

같은 프로그램을 인터프리터에서 실행하면 다음과 같습니다.

```sh
$ ling run --interp try_demo.ling
[detected language: Korean (한국어)]
Ok(5)
Err(unknown function '없는함수')
```

`http_serve`를 호출하는 프로그램은 항상 인터프리터에서 실행되므로, 웹 요청 핸들러 안에서는 `시도`가
동작합니다. 그 밖의 곳에서는 `시도`를 개발 보조 도구로 여기고, 직접 만든 함수가 `좋아`와 `나쁨`을
돌려주도록 작성하십시오.

## 내장 함수의 부드러운 실패

대부분의 내장 함수는 결과를 돌려주지 않습니다. 실패하면 해가 없는 중립적인 값을 돌려주고 계속
진행합니다.

| 내장 함수 | 실패했을 때 |
|---|---|
| `to_number("x")` | `0` |
| `요소가져오기(xs, 99)` | `""`(빈 텍스트) |
| `str_find("abc", "z")` | `-1` |
| `file_exists(경로)` | `false` |
| `read_file("missing.txt")` | JIT에서는 `()`, 인터프리터에서는 런타임 오류 |

```ling
바인드 시작 = 실행 {
  출력(to_number("바나나"))
  출력("[" + 요소가져오기([1, 2, 3], 99) + "]")
  출력(str_find("안녕", "z"))
  출력(file_exists("no-such-file.txt"))
}
```
```output
0
[]
-1
false
```

실패가 진짜 값처럼 보일 수 있습니다. `to_number("0")`과 `to_number("영")`은 둘 다 `0`입니다. 그러니
먼저 확인하십시오. `read_file` 전에 `file_exists`를 호출하고, 인덱스는 `길이(xs)`와 비교하고,
`to_number`를 믿기 전에 텍스트를 검증하십시오. 작은 감싸기 함수로 부드러운 실패를 진짜 결과로
바꿀 수 있습니다.

```ling
함수 텍스트읽기(경로) {
  만약 file_exists(경로) { 좋아(read_file(경로)) } 아니면 { 나쁨("파일 없음: " + 경로) }
}
바인드 시작 = 실행 {
  출력(텍스트읽기("missing.cfg"))
}
```
```output
Err(파일 없음: missing.cfg)
```
