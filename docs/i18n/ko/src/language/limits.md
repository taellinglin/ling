# 알려진 제한 사항

Ling은 젊고 빠르게 변하는 언어입니다. 이 페이지는 사람들이 가장 많이 놀라는 동작을 모아, 몇 시간이
아니라 몇 분 만에 알아챌 수 있게 합니다. 여기 적힌 내용은 모두 현재 `ling` 바이너리(2030.1.53)의 두
엔진, 기본 JIT(`ling run`)와 인터프리터(`ling run --interp`)에서 확인했습니다.

> **팁:** 프로그램이 이상하게 동작하면 `ling run --interp`로 한 번 실행해 보십시오. 인터프리터는
> JIT가 조용히 `()`로 바꿔 버리는 알 수 없는 함수와 런타임 오류를 알려 줍니다.

## JIT와 인터프리터 한눈에 보기

| 상황 | JIT(기본) | 인터프리터 |
|---|---|---|
| 알 수 없는 함수 이름 | 조용히 `()`를 돌려줌 | `unknown function` 오류 |
| 런타임 오류(없는 파일, 잘못된 인덱스 등) | `()`나 빈 값을 돌려주고 계속 진행 | 오류와 트레이스백을 출력하고 멈춤 |
| `1 / 0` | `()` | `inf` |
| 이름만 쓴 `pi` | `()`(`pi()`로 쓰십시오) | 그 값 |
| 조건 안의 `""`나 `[]` | 참 | 거짓 |
| 리스트 끝을 넘는 인덱스 | 빈 값 | `index N out of bounds` 오류 |
| 텍스트의 한 글자 `s[i]` | 빈 값 | 그 글자(둘 다에서 쓰려면 `substr(s, i, 1)`) |
| `위해 c 안에 "텍스트"` | 빈 값 | 한 글자씩 |
| 텍스트 크기 비교 `"a" < "b"` | `false` | 오류 |
| `실행 { }` 안의 `바인드` | 나중에도 보임 | 버려짐 |
| 변수에 담은 클로저 `f(3)` | `()` | `unknown function 'f'` 오류 |
| 함수나 클로저를 내장 함수에 넘기기(`시도`, `list_map` 등) | `()`가 됨 | 동작함 |
| `기다려 식` | `()` | 그 값 |
| 범위 값 `0..5` 출력 | `[0, 5]` | `[0, 1, 2, 3, 4]` |
| 필드 수가 맞지 않는 생성자 | `()` | 오류 |
| 빠진 함수 인수를 사용 | `()` | `undefined` 오류 |
| 진입점 안에 바로 쓴 `반환` | 조용히 프로그램 종료 | `unexpected top-level return` 오류 |

이런 구석을 피한 프로그램은 두 엔진에서 똑같이 동작합니다.

## 대입이 없습니다

`x = x + 1`은 구문 오류입니다. 대신 다시 바인딩하십시오: `바인드 x = x + 1`.
[바인딩과 재바인딩](syntax.md#바인딩과-재바인딩)을 참고하십시오.

## 루프와 범위

| 구문 | 안의 `바인드`가 바깥 변수를 바꾸는가? |
|---|---|
| `동안` 본문 | 예 |
| `만약` 본문 | 예 |
| `위해` 본문 | **아니요**: 매번 범위의 새 복사본을 받습니다 |
| `실행 { }` 블록 | JIT에서는 예, 인터프리터에서는 아니요. 어느 쪽에도 의존하지 마십시오 |

합계를 누적하거나 리스트를 만들려면 카운터가 있는 `동안` 루프를 쓰십시오.

`break`나 `continue`는 없습니다. `멈춤`과 `계속`은 아무 일도 하지 않는 예약어입니다. JIT에서는
루프가 그냥 계속되고, 인터프리터에서는 `undefined` 오류가 됩니다. 루프를 함수에 넣고 `반환`하거나,
플래그를 쓰는 `동안`을 쓰십시오.

## 범위 경계는 단순해야 합니다

`0..n`과 `0..(n + 1)`은 동작합니다. `0..n + 1`은 구문 오류이고, `0..길이(xs)`는 조용히 잘못
동작합니다(JIT에서는 빈 루프, 인터프리터에서는 오류). 단순한 이름이나 숫자가 아니면 괄호로
감싸십시오: `0..(길이(xs))`.

## &&와 ||는 항상 양쪽을 평가합니다

두 엔진 모두 단락 평가를 하지 않습니다. `x != 0 && 10 / x > 1`에서는 `x`가 `0`이어도 나눗셈이
실행됩니다. 오른쪽을 실행하면 안 될 때는 `만약`을 중첩하십시오.

## 숫자와 텍스트

- 숫자 리터럴은 10진수 숫자이며 소수 부분은 최대 하나입니다. `1e3`, `0xff`, `1_000`, `.5`, `3.`은
  없습니다. 더 곤란하게도 `1e3`과 `0xff`는 구문 오류가 아닙니다. `1`이나 `0` 뒤에 알 수 없는 이름이
  이어진 것으로 읽힙니다.
- 텍스트는 큰따옴표만 쓰며 보간이 없습니다. 텍스트는 `+`와 `str()`로 만드십시오.
- `print`와 `println`(한국어로는 둘 다 `출력`)은 모두 줄을 바꾸고, 인수를 **구분자 없이**
  이어 붙입니다. `출력("합계", 1 + 2)`는 `합계3`을 출력합니다.
- `!x`는 `x == 거짓`이라는 뜻이라서 `!0`과 `!""`는 모두 `false`입니다. `!`는 불리언에만 쓰십시오.

## 구조가 있는 값 비교

리스트, 레코드, 열거 값, 결과끼리의 `==`는 내용이 같아도 항상 `false`입니다. 요소나 필드를 직접
비교하십시오. [타입과 값](types.md#값-비교)을 참고하십시오.

## 타입 시스템이 하는 일과 하지 않는 일

Ling은 동적 타입 언어입니다. `x: number`나 `-> T` 같은 타입 표기는 파싱된 뒤 무시됩니다. 맵(사전),
집합, 튜플, JSON 파서는 없습니다. 레코드나 나란한 리스트를 쓰거나, `db_*` 내장 함수로 SQLite에
데이터를 저장하십시오.

## 아무 일도 하지 않는 키워드

다음 단어들은 예약되어 있지만 아무 효과가 없습니다.

`멈춤`(`stop`), `계속`(`again`), `변경`(`change`), `게시`(`post`), `전달`(`give`), `적합`(`fit`),
`가능`(`can`), `확실`(`sure`), `아마도`(`maybe`), `순수`(`pure`), `생성`(`spawn`), `없음`(`none`)

소유권 단어 `소유`, `빌려`, `공유`, `이동`, `복사`는 파싱된 뒤 무시되며, 빌림이나 이동 검사는
없습니다. `비동기 함수`는 동기적으로 실행됩니다. `타입`(`type`) 선언은 버려지고 뒤따르는 내용을
삼킵니다. [키워드](keywords.md)를 참고하십시오.

## 클로저와 함수 값

그 자리에서 호출하는 클로저 식 `(|x| x + 1)(5)`는 어디서나 동작합니다. 그 밖에는 다음과 같습니다.

- 변수에 담은 클로저는 인터프리터에서 이름으로 호출할 수 없고, JIT에서도 믿을 수 없습니다.
- JIT는 함수나 클로저를 내장 함수에 넘기지 못합니다. `list_map`, `list_filter` 같은 내장 함수는
  `()`를 돌려주고, `시도()`는 항상 `나쁨("try: first argument must be a function")`을 돌려줍니다.
  인터프리터에서는 동작합니다.
- `http_serve`를 호출하는 프로그램은 자동으로 인터프리터에서 실행되므로, 요청 핸들러 안에서는
  클로저와 `시도`가 동작합니다.

이름 있는 최상위 `함수`와 평범한 루프를 쓰십시오.

## 모듈

- `사용 "파일"`은 하나의 공유 네임스페이스로 불러옵니다. 두 파일이 같은 이름의 함수를 정의하면
  마지막에 불러온 것이 조용히 쓰입니다. 먼저 불러온 파일 안에서 호출해도 마찬가지입니다. 이 규칙은
  진입점에도 적용되므로, 라이브러리에서는 절대 `start` 같은 진입점 이름을 바인딩하지 마십시오.
- `모듈` 안에서는 같은 모듈의 함수를 한정된 이름(`도형::넓이`)으로 호출하십시오. 이름만 쓰면
  실패합니다.
- `모듈` 안에서 바인딩한 값은 쓸 수 없습니다. 상수는 함수로 내보내십시오.

라이브러리 함수에는 라이브러리 이름을 접두사로 붙이십시오. 예를 들면 `geom_area`입니다.
[모듈과 프로젝트](modules.md)를 참고하십시오.

## 도구

- `lingfu new`는 `src/start.ling`을 만들지만, 매니페스트에 따로 적지 않으면 `lingfu build`는
  `main.ling`을 찾습니다. `Ling.toml`의 `[spirit]` 섹션에 `entry = "src/start.ling"`을 더하십시오.
- `lingfu check`, `lingfu fmt`, `lingfu translate`는 존재하지 않는 `ling` 하위 명령을 호출합니다.
  `ling`의 사용법만 출력하고 아무 일도 하지 않지만, `check`와 `fmt`는 여전히 성공을 보고합니다.
  프로그램 확인에는 `ling run --interp`를, 번역에는 `lingfu normalize <언어>`를 쓰십시오(현재 폴더의
  모든 `.ling` 파일을 다시 쓰므로 복사본에서 쓰십시오).
- `lingfu normalize`는 몇몇 키워드를 틀리게 씁니다. 중국어, 한국어, 태국어에서는 `form`을 렉서가
  받아들이지 않는 단어로 쓰고([키워드](keywords.md#철자)의 철자를 쓰십시오), `choose`는 영어로
  남겨 두며, 일본어와 태국어에서는 `ok`/`bad`를 `매치` 패턴으로 쓸 수 없는 내장 함수 이름으로
  씁니다. 일부 소유권 단어(`copy`, `lend`, `share`)도 일본어와 태국어에서 잘못 나옵니다. 결과를
  실행해 보고 이런 단어는 직접 고치십시오.
- `lingfu build`는 생성한 Rust 코드를 Cargo로 컴파일하므로 Rust 툴체인이 필요합니다.

## 테스트

`lingfu test`는 JIT에서 테스트를 실행하는데, JIT는 런타임 오류에서 멈추지 않으므로 실패한
테스트에도 `All tests passed!`를 출력할 수 있습니다. 테스트가 분명한 `PASS` 또는 `FAIL` 줄을
출력하게 하고 그 줄을 확인하거나, `ling run --interp`로 실행하십시오. `tests/` 안에 둔 도우미
파일은 테스트로 취급되어 `no entry point`로 실패하므로, 도우미 파일은 다른 곳에 두십시오.

## 구문 함정

- `-`나 `[`로 시작하는 줄은 앞 줄에 이어집니다.
- `구조 P { x: number, y: number }`는 구문 오류입니다. 타입 표기가 있는 필드 목록은 쉼표로
  끝내십시오: `구조 P { x: number, y: number, }`.
- 매개변수 없는 클로저에는 공백이 필요해서 `| | 식`으로 씁니다. `||`는 "또는"이기 때문입니다.
- `함수 main() { ... }`은 진입점이 아닙니다. `바인드 main = 실행 { ... }`을 쓰십시오.
- `assert`, `panic`, `exit`, `append_file`, `delta_time`은 내장 함수가 아닙니다. 프레임 시간을 재려면
  연속한 두 `time_now()` 값을 빼십시오.
