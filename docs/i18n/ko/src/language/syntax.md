# 문법

이 페이지는 Ling 프로그램을 쓰는 방법을 설명합니다. 프로그램 구성, 리터럴, 연산자, 바인딩, 함수,
제어 흐름입니다. 모든 예제는 현재 `ling` 바이너리로 실제로 실행했습니다. Ling에는 두 가지 실행
엔진, 기본 JIT(`ling run`)와 인터프리터(`ling run --interp`)가 있습니다. 둘의 동작이 다른 곳은
이 페이지에서 알려 드리며, 모든 차이점은 [알려진 제한 사항](limits.md)에 모아 두었습니다.

이 페이지의 코드는 한국어 키워드로 작성했습니다. 각 키워드의 영어 및 다른 언어 철자는
[키워드](keywords.md)를 참고하십시오.

## 프로그램 구조

Ling 파일은 최상위 **항목**의 목록입니다.

| 항목 | 형태 | 참고 |
|---|---|---|
| 바인딩 | `바인드 이름 = 식` | [바인딩과 재바인딩](#바인딩과-재바인딩) |
| 함수 | `함수 이름(a, b) { ... }` | [함수](#함수) |
| 레코드 타입 | `구조 이름 { 필드, 필드 }` | [레코드와 열거형](#레코드와-열거형) |
| 열거형 | `선택 이름 { 변형, 변형(a) }` | [레코드와 열거형](#레코드와-열거형) |
| 모듈 | `모듈 이름 { 함수 ... }` | [모듈과 프로젝트](modules.md) |
| 가져오기 | `사용 "파일.ling"` | [모듈과 프로젝트](modules.md) |

`출력(...)` 같은 문장은 최상위에 쓸 수 없습니다. 함수 안이나 진입점 안에 써야 합니다.

### 진입점

프로그램은 값이 `실행` 블록인 최상위 바인딩에서 시작합니다.

```ling
바인드 시작 = 실행 {
  출력("안녕하세요, Ling!")
}
```
```output
안녕하세요, Ling!
```

런타임은 다음 이름의 바인딩을 이 순서대로 찾습니다. `start`, `main`, `启`, `เริ่ม`, `시작`, 그리고
몇몇 다른 언어의 같은 뜻의 단어입니다. 아무것도 없으면 값이 `실행` 블록인 첫 번째 최상위 바인딩을
실행합니다. 그런 바인딩이 없는 파일은 라이브러리이며, `ling run`은 `no entry point`를 출력하고
멈춥니다.

```ling
바인드 main = 실행 {
  출력("main도 됩니다")
}
```
```output
main도 됩니다
```

> `함수 main() { ... }`은 진입점이 **아닙니다**. `바인드 main = 실행 { ... }`이라고 쓰십시오.

## 주석과 문장

주석은 `#` 또는 `//`부터 줄 끝까지입니다. 블록 주석은 없습니다. 문장은 줄바꿈으로 구분합니다.
문장 끝에 `;`를 붙이면 한 줄에 두 문장을 쓸 수 있습니다.

```ling
# 샵 주석
// 슬래시 주석
바인드 시작 = 실행 {
  출력("가") // 줄 끝 주석
  출력("나"); 출력("다")
}
```
```output
가
나
다
```

## 식별자

이름은 글자나 `_`로 시작하고, 글자, 숫자, `_`가 이어집니다. 유니코드 글자라면 무엇이든 되므로
한국어, 중국어, 일본어, 태국어 이름을 쓸 수 있습니다. 이름은 대소문자를 구분합니다.

```ling
바인드 시작 = 실행 {
  바인드 名前 = "Ling"
  바인드 ชื่อ = 3
  출력(名前)
  출력(ชื่อ + 1)
}
```
```output
Ling
4
```

아직 아무 일도 하지 않는 키워드(`변경`(`change`), `멈춤`(`stop`), `아마도`(`maybe`) 등.
[키워드](keywords.md) 참고)는 파서에게 평범한 이름이므로 `바인드 멈춤 = 2`는 동작합니다. 하지만
`위해`(`for`)나 `만약`(`if`) 같은 활성 키워드를 이름으로 쓰지는 마십시오. 한국어로 이름을 지을
때는 `단`, `조건`, `반복`, `생성` 같은 단어도 키워드라는 점에 주의하십시오.

## 리터럴

| 리터럴 | 형태 | 설명 |
|---|---|---|
| 숫자 | `42`, `3.14` | 10진수 숫자이며 소수 부분은 최대 하나입니다. 모든 숫자는 64비트 부동소수점입니다. |
| 텍스트 | `"안녕"` | 큰따옴표만 씁니다. 여러 줄에 걸쳐도 됩니다. 이스케이프: `\n` `\t` `\r` `\"` `\\` `\0`. |
| 불리언 | `참`, `거짓` | |
| 유닛 | `()` | "아무것도 없음"을 나타내는 값입니다. |
| 리스트 | `[1, "둘", 3.5]` | 요소의 타입은 자유이며, 번호는 0부터 시작합니다. |
| 범위 | `0..5` | 끝을 포함하지 않습니다: 0, 1, 2, 3, 4. `위해`와 함께 씁니다. |
| 클로저 | `\|x\| x + 1` | [클로저](#클로저)를 참고하십시오. |

`1e3`, `0xff`, `1_000`, `.5`, `3.` 같은 표기는 없습니다. 문자 리터럴이 없고(`'a'`는 구문 오류),
맵 리터럴도 튜플도 없습니다. 텍스트에는 보간이 없습니다. `"{x}"`는 그 세 글자 그대로입니다.
텍스트는 `+`와 `str()`로 만드십시오. `\q` 같은 알 수 없는 이스케이프는 백슬래시까지 그대로
남습니다.

```ling
바인드 시작 = 실행 {
  출력("첫째 줄\n둘째 줄")
  출력("따옴표: \"q\" 백슬래시: \\")
  출력(1.5 + 1)
  출력([1, "둘", 3.5, 참])
  출력(())
}
```
```output
첫째 줄
둘째 줄
따옴표: "q" 백슬래시: \
2.5
[1, 둘, 3.5, true]
()
```

## 연산자와 우선순위

가장 강하게 결합하는 것부터 순서대로입니다.

| 순위 | 연산자 | 설명 |
|---|---|---|
| 1 | `.` `()` `[]` `::` `..` | 필드 또는 메서드, 호출, 인덱스, 모듈 경로, 범위 |
| 2 | `-x` `!x` | 전위 마이너스와 부정 |
| 3 | `*` `/` `%` | `%`는 소수에도 동작합니다: `7.5 % 2`는 `1.5` |
| 4 | `+` `-` | `+`는 텍스트를 잇습니다. 한쪽이 텍스트이면 다른 쪽의 숫자는 텍스트가 됩니다 |
| 5 | `==` `!=` `<` `>` `<=` `>=` | |
| 6 | `&&` | |
| 7 | `\|\|` | |

모든 이항 연산자는 왼쪽 결합입니다. `10 - 3 - 2`는 `5`입니다.

```ling
바인드 시작 = 실행 {
  출력(2 + 3 * 4)
  출력((2 + 3) * 4)
  출력(10 - 3 - 2)
  출력(-3 + 5)
  출력(2 * -4)
  출력(1 < 2 && 2 < 3)
  출력("n=" + 5)
  출력(7 / 2)
}
```
```output
14
20
5
2
-8
true
n=5
3.5
```

주의할 점:

- `&&`와 `||`는 두 엔진 모두에서 **항상 양쪽을 평가합니다**. `x != 0 && 10 / x > 1`은 나눗셈을
  막아 주지 않습니다. 대신 `만약`을 중첩하십시오.
- 비교는 왼쪽부터 이어집니다. `1 == 1 == 1`은 `(1 == 1) == 1`이라는 뜻이고 결과는 `false`입니다.
- 전위 마이너스는 겹쳐 쓸 수 없습니다. `- - x`는 구문 오류입니다. `0 - x`는 언제나 동작합니다.
- 리스트, 레코드, 열거 값끼리의 `==`는 항상 `false`입니다. [타입과 값](types.md#값-비교)을
  참고하십시오.

## 바인딩과 재바인딩

`바인드 이름 = 식`은 값에 이름을 붙입니다. 대입은 없습니다. `x = 5`는 구문 오류입니다. 값을
"바꾸려면" 같은 이름을 다시 바인딩합니다. 그 지점부터 새 바인딩이 이전 바인딩을 대신합니다.

```ling
바인드 시작 = 실행 {
  바인드 x = 1
  바인드 x = x + 10
  바인드 x = x * 2
  출력(x)
}
```
```output
22
```

블록이 끝난 뒤에도 재바인딩이 보이는지는 블록의 종류에 따라 다릅니다.

| 위치 | 블록이 끝난 뒤의 재바인딩 |
|---|---|
| `만약` / `아니면` 본문 | 남음 |
| `동안` 본문 | 남음. 그래서 `동안` 루프로 값을 누적할 수 있습니다 |
| `위해` 본문 | **사라짐**: 매번 새 복사본에서 시작합니다 |
| `매치` 갈래 | 사라짐 |
| 함수 본문 | 그 호출 안에서만 |
| `실행 { }` 블록 | 인터프리터에서는 사라지고 JIT에서는 남음. 어느 쪽에도 의존하지 마십시오 |

```ling
바인드 시작 = 실행 {
  바인드 합계 = 0
  위해 i 안에 1..5 { 바인드 합계 = 합계 + i }
  출력(합계)
  바인드 합 = 0
  바인드 i = 1
  동안 i < 5 {
    바인드 합 = 합 + i
    바인드 i = i + 1
  }
  출력(합)
}
```
```output
0
10
```

최상위 `바인드`는 전역 상수입니다. 함수는 이것을 읽을 수 있지만, 호출한 쪽의 지역 바인딩은 절대
보지 못합니다.

```ling
바인드 배율 = 3
함수 확대(n) { n * 배율 }
바인드 시작 = 실행 {
  바인드 배율 = 100
  출력(확대(2))
}
```
```output
6
```

## 블록

`실행 { ... }`은 안의 문장을 차례로 실행하고, 마지막 문장의 값이 블록의 값이 됩니다. 진입점도
`실행` 블록이며, 식을 쓸 수 있는 곳이면 어디서나 쓸 수 있습니다.

```ling
바인드 시작 = 실행 {
  바인드 총계 = 실행 {
    바인드 a = 20
    바인드 b = 22
    a + b
  }
  출력(총계)
}
```
```output
42
```

## 함수

`함수 이름(매개변수) { 본문 }`은 최상위(또는 `모듈` 안)에 함수를 선언합니다. 결과는 본문의 마지막
식입니다. `반환 값`으로 일찍 빠져나가며, 값 없는 `반환`은 `()`를 돌려줍니다. 함수는 재귀할 수
있고 선언 순서는 자유입니다. 함수 안에 함수를 중첩할 수는 없습니다.

```ling
함수 피보나치(n) {
  만약 n < 2 { 반환 n }
  피보나치(n - 1) + 피보나치(n - 2)
}
함수 인사(이름) { "안녕하세요, " + 이름 + "!" }
바인드 시작 = 실행 {
  출력(피보나치(15))
  출력(인사("Ling"))
}
```
```output
610
안녕하세요, Ling!
```

- `함수 f(a: number) -> text` 같은 타입 표기는 받아들여지고 무시됩니다.
- 인수를 너무 적게 넘기면 빠진 매개변수는 정의되지 않은 상태가 됩니다. 그것을 쓰면
  인터프리터에서는 오류이고 JIT에서는 `()`가 됩니다.
- 존재하지 않는 함수를 호출하면 인터프리터에서는 오류지만 JIT는 조용히 `()`를 돌려줍니다.
  프로그램이 "아무것도 하지 않을" 때는 `ling run --interp`로 실행해 보십시오.

## 클로저

클로저는 `|매개변수| 식`으로 씁니다. 예를 들어 `|x| x * 2`입니다. 매개변수가 없는 클로저는 공백이
필요해서 `| | 42`로 씁니다. `||`는 "또는" 연산자이기 때문입니다.

클로저 식을 그 자리에서 호출하는 것은 어디서나 동작합니다.

```ling
바인드 시작 = 실행 {
  출력((|x| x + 1)(5))
}
```
```output
6
```

클로저는 현재 언어에서 가장 믿기 어려운 부분입니다. 변수에 담은 클로저는 인터프리터에서 이름으로
호출할 수 없고, JIT는 클로저(나 함수 이름)를 `list_map`이나 `시도`(`try`) 같은 내장 함수에 넘기지
못합니다. 이름 있는 `함수`를 쓰십시오. [알려진 제한 사항](limits.md#클로저와-함수-값)을
참고하십시오.

## 제어 흐름

### if / else

`만약`(`if`)은 식입니다. 중괄호는 필수이고 조건에 괄호는 필요 없습니다. `아니면`(`else`)이 없고
조건이 거짓이면 `만약`은 `()`가 됩니다.

```ling
바인드 시작 = 실행 {
  바인드 n = 7
  바인드 표시 = 만약 n < 0 { "음수" } 아니면 만약 n == 0 { "영" } 아니면 { "양수" }
  출력(표시)
}
```
```output
양수
```

조건에는 진짜 불리언을 쓰십시오. `""`와 `[]`에 대한 판단이 엔진마다 다릅니다.
[타입과 값](types.md#참거짓-판정)을 참고하십시오.

### while

`동안 조건 { 본문 }`(`while`)은 조건이 성립하는 동안 반복합니다. 본문이 바깥 범위를 공유하므로
카운터와 합계에는 이 루프를 씁니다.

```ling
바인드 시작 = 실행 {
  바인드 n = 27
  바인드 단계 = 0
  동안 n != 1 {
    바인드 n = 만약 n % 2 == 0 { n / 2 } 아니면 { 3 * n + 1 }
    바인드 단계 = 단계 + 1
  }
  출력(단계)
}
```
```output
111
```

### for

`위해 이름 안에 시퀀스 { 본문 }`(`for ... in`)은 범위나 리스트의 항목마다 본문을 한 번씩
실행합니다. 범위 `lo..hi`는 `hi` 바로 앞에서 멈춥니다.

```ling
바인드 시작 = 실행 {
  위해 i 안에 1..4 { 출력(i * i) }
  위해 이름 안에 ["ada", "lin"] { 출력(str_upper(이름)) }
}
```
```output
1
4
9
ADA
LIN
```

`break`나 `continue`는 없습니다. 일찍 멈추려면 루프를 함수에 넣고 `반환`하거나, 플래그를 쓰는
`동안` 루프를 쓰십시오.

### match

`매치 값 { 패턴 => 식, ... }`(`match`)은 갈래를 위에서부터 차례로 시도하고, 처음 맞는 갈래를
평가합니다. 패턴은 다음과 같습니다.

| 패턴 | 맞는 것 |
|---|---|
| `_` | 무엇이든 |
| `0`, `"예"`, `참` | 그 리터럴 값 |
| `이름` | 무엇이든. 그 값을 `이름`에 바인딩합니다 |
| `좋아(p)`, `나쁨(p)` | 결과([오류와 결과](errors.md) 참고) |
| `변형(p, ...)`, `변형()` | 열거 값 |

```ling
함수 분류(n) {
  매치 n {
    0 => "영",
    1 => "일",
    그외 => "많음 (" + str(그외) + ")"
  }
}
바인드 시작 = 실행 {
  출력(분류(0))
  출력(분류(9))
}
```
```output
영
많음 (9)
```

맞는 갈래가 없으면 `매치`는 `()`가 됩니다. 가드는 없고, 리스트나 레코드에 대한 패턴도 없습니다.

## 레코드와 열거형

`구조`(`form`)는 레코드 타입을 선언합니다. 타입 이름을 필드 순서대로 호출하면 레코드가 만들어지고,
`.`으로 필드를 읽습니다.

```ling
구조 점 { x, y }
바인드 시작 = 실행 {
  바인드 p = 점(3, 4)
  출력(p)
  출력(p.x + p.y)
}
```
```output
점 { x: 3, y: 4 }
7
```

`선택`(`choose`)은 값을 가질 수 있는 변형들로 이루어진 열거형을 선언합니다. 변형을 호출해 값을
만들고 `매치`로 분해합니다. 값이 없는 변형도 괄호를 붙여 `점하나()`처럼 씁니다. 변형의 이름은
`.tag`로 얻을 수 있습니다.

```ling
선택 도형 { 원(r), 사각형(w, h), 점하나 }
함수 넓이(s) {
  매치 s {
    원(r) => 3 * r * r,
    사각형(w, h) => w * h,
    점하나() => 0
  }
}
바인드 시작 = 실행 {
  출력(넓이(원(2)))
  출력(넓이(사각형(3, 4)))
  출력(넓이(점하나()))
  출력(사각형(1, 2).tag)
}
```
```output
12
12
0
사각형
```

레코드는 바꿀 수 없으므로 필요하면 새로 만드십시오. `점 { x: 1, y: 2 }` 같은 리터럴 문법은
지원하지 않습니다. 생성자를 잘못된 필드 수로 호출하면 인터프리터에서는 오류이고 JIT에서는 `()`가
됩니다.

## 구문 함정

- **`-`나 `[`로 시작하는 줄은 앞 줄에 이어집니다.** `바인드 x = 5` 다음 줄이 `-1`이면 `x`는 `4`가
  되고, `[1, 2]`로 시작하는 줄은 인덱싱으로 읽힙니다.
- **범위 경계.** `0..n + 1`은 구문 오류이고 `0..길이(xs)`는 조용히 잘못 동작합니다. 단순한 이름이나
  숫자가 아니면 괄호로 감싸십시오: `0..(n + 1)`, `0..(길이(xs))`.
- **`구조`의 필드 표기.** `구조 P { x: number, y: number }`는 구문 오류입니다. `}` 바로 앞의 표기가
  닫는 중괄호를 삼키기 때문입니다. 목록 끝에 쉼표를 붙이십시오: `구조 P { x: number, y: number, }`.
- **대입은 없습니다.** `x = x + 1`은 구문 오류입니다. `바인드 x = x + 1`이라고 쓰십시오.
- **매개변수 없는 클로저.** `|| 식`이 아니라 `| | 식`으로 쓰십시오.
